# 科研论文辅助 Agent 项目需求文档

版本：V0.13

项目阶段：需求规划阶段

终端范围：PC Web 端

支持语言：中文、英文

后续规划：PC 端稳定后考虑开发小程序端

## 一、项目总体需求

### 1. 项目背景

本项目拟开发一套面向生物医学、药学相关科研场景的 AI Agent 系统，辅助研究人员开展科研数据分析、SCI 科研论文撰写及毕业论文撰写。

系统围绕科研数据分析、论文初稿生成及后续意见处理，重点解决以下三个核心问题：

1.  用户已有实验、调查或研究数据，但缺少快速的数据整理、统计分析、可视化及结果解释能力。

2.  用户完成数据分析后，需要组织研究结果、图表及方法资料，形成 SCI 科研论文初稿，并获得投稿期刊建议及审稿修改支持。

3.  用户已有研究资料与分析结果，需要按照特定学校的毕业论文要求生成初稿，并根据导师意见和评审建议持续完善。

因此，第一阶段系统围绕以下三个核心模块建设：

- **科研数据分析模块：**根据研究目标，对原始科研数据进行整理、统计分析与结果解释，生成带标签及说明的研究结果图表和数据分析报告。

- **SCI科研论文生成模块：**结合用户提供的研究资料、研究结果图表及相关文献，生成 SCI 科研论文初稿，提供投稿期刊建议，并根据审稿意见辅助修改论文、准备审稿回复，支持论文投稿及后续修改过程。

- **毕业论文初稿生成模块：**结合用户提供的研究资料和研究结果图表，依据特定学校的毕业论文结构与格式要求生成初稿，并根据导师意见及评审建议辅助修改完善，提升论文的内容质量与规范性。

用户在创建项目时选择“SCI科研论文项目”或“毕业论文项目”。前者按约定结构生成 SCI 科研论文，并提供投稿期刊建议和审稿修改辅助；后者按学校毕业论文模板生成初稿，并辅助处理导师及评审意见。两类项目共用科研数据分析能力，各自管理对应的写作及修改任务。

### 2. 项目目标

系统帮助研究人员完成重复、耗时的基础工作，按三个核心模块及共用能力划分如下。

#### 2.1 科研数据分析模块

- 读取研究文件并识别内容；

- 整理研究数据；

- 完成数据统计与分析；

- 生成带标签及说明的科研图表；

- 解释图表及分析结果；

- 生成数据分析报告。

#### 2.2 SCI科研论文生成模块

- 理解研究问题、实验或研究方法、图表及分析结果；

- 按 Title、Abstract、Introduction、Results、Discussion、Materials and methods、References 七部分规划论文；

- 组织 Results 中的研究发现与图表，结合实际方法和已核实文献，生成 SCI 科研论文初稿。

- 根据研究主题、论文内容及投稿偏好提供期刊候选名单和建议理由；

- 根据审稿意见辅助修改论文、补充分析及准备逐条审稿回复。

#### 2.3 毕业论文初稿生成模块

- 解析用户上传的学校毕业论文模板及写作规范；

- 根据学校、院系及学位类型的要求生成毕业论文结构；

- 组织研究资料、分析结果、图表及相关文献，生成毕业论文初稿。

- 根据导师意见和评审建议逐条完善论文内容与学校格式，生成修改稿和修改说明。

#### 2.4 共用能力

- 为 SCI科研论文生成模块和毕业论文初稿生成模块提供文献检索；

- 为两个写作模块提供文献筛选、引用及来源核实辅助；

- 为三个模块提供 Word/PDF 文档输出与下载。

- 为两个写作模块保存稿件版本、意见轮次及逐条修改记录。

系统帮助用户从原始科研数据出发，完成分析、写作及意见驱动的多轮修改，提高科研材料的内容质量与规范性。用户负责审核研究事实、确认修改内容，并完成论文提交。

#### 2.5 中英文支持

第一阶段支持中文和英文界面及任务输入。数据分析报告、图表文字、SCI 科研论文、毕业论文、期刊建议和修改说明按照任务所选语言生成；审稿回复可单独选择中文或英文，以适配投稿要求。

同一份输出中的标题、正文、图表标签、图注和说明应保持语言一致；学校模板明确要求的双语部分按模板分别生成。审稿或评审意见应保留原文，需要翻译时另附译文。

### 3. 用户角色

系统设置普通用户和管理员两类角色。

#### 3.1 普通用户

- 注册、登录系统；

- 创建项目，并选择SCI科研论文项目或毕业论文项目；

- 上传研究文件、学校毕业论文模板，以及审稿、导师或评审意见；

- 使用科研数据分析 Agent；

- 使用SCI科研论文生成 Agent；

- 使用毕业论文初稿生成 Agent；

- 查看任务执行进度；

- 查看历史任务、论文版本和修改轮次；

- 下载生成结果；

- 管理本人上传的文件；

- 管理本人生成的报告、论文、期刊建议、修改说明及审稿回复。

- 查看期刊建议，选择目标期刊及当前稿件版本；

- 发起审稿或评审修改，补充所需材料并确认修改结果。

#### 3.2 管理员

- 用户管理；

- 用户权限管理；

- 系统任务查看；

- 异常任务查看；

- API 调用情况查看；

- API Token/费用统计；

- 模型配置；

- PubMed/NCBI 文献检索接口配置；

- 系统提示词/Agent 配置；

- 系统运行日志查看；

- 文件及存储空间管理；

- 系统基础参数配置。

- 期刊信息来源、更新情况及推荐规则配置；

- 学校模板解析规则及修改任务相关配置。

### 4. 核心业务结构

系统以“项目”为主要工作单位。一个用户可以创建多个项目，每个项目对应一个明确的写作目标。

#### 4.1 创建项目与类型选择

用户在创建项目时填写项目名称和研究主题，并从以下类型中选择一项：

- **SCI科研论文项目：**基于用户自己的研究资料与分析结果，生成 SCI 科研论文初稿，提供投稿期刊建议，并辅助处理审稿意见及后续修改。

- **毕业论文项目：**基于用户自己的研究资料与分析结果，按特定学校的毕业论文结构与格式生成初稿，并根据导师意见及评审建议修改完善。

项目类型在创建时确定。SCI 科研论文项目使用内置的七部分结构，无需上传论文模板；确定投稿期刊后，按已核实的期刊要求检查并调整稿件。毕业论文项目使用学校毕业论文模板及规范，按学校要求确定结构和格式。

科研数据分析模块是两类项目共用的能力。用户可以在项目中单独执行数据分析任务；已有分析结果时，也可以直接用于对应的写作任务。

#### 4.2 项目内容管理

两类项目均可保存的内容

- 原始数据、图片、文档及补充资料；

- 数据分析任务和统计结果；

- 带标签及说明的图表、图表解释和数据分析报告；

- 文献资料及引用信息。

SCI科研论文项目的专属内容

- SCI 科研论文生成任务、期刊建议任务和审稿修改任务；

- 研究结果分组、图表与结果段落的对应关系及七部分论文结构；

- 各版本论文、投稿期刊建议、目标期刊要求、审稿意见、逐条回复及导出文件。

毕业论文项目的专属内容

- 学校、院系、学位类型，以及毕业论文模板、写作规范和解析结果；

- 毕业论文初稿生成任务、论文章节结构及评审修改任务；

- 各版本毕业论文、导师及评审意见、意见处理记录和导出文件。

每个项目分别管理自己的资料、任务和成果。论文修改应关联作为修改依据的稿件版本、意见轮次及新增材料，保留原稿与修改稿，避免覆盖已有成果。

#### 4.3 SCI科研论文项目操作流程

1.  **创建SCI科研论文项目**：选择“SCI科研论文项目”，填写项目名称和研究主题。

2.  **准备研究资料：**上传原始数据或已有图表、分析结果，并提供研究目的、研究设计、材料和实验方法等资料。

3.  **完成数据分析**：需要分析原始数据时，执行数据整理、统计和绘图，生成分析报告；已有分析结果可直接使用。

4.  **组织论文内容：**将图表和分析结果归入 Results 的相应小节，整理 Materials and methods，并检索、筛选相关文献，支撑 Introduction 和 Discussion 等部分。

5.  **生成与导出：**按七部分结构生成 SCI 科研论文初稿，保留图表、图注和引用，支持 Word/PDF 下载，供用户审核。

6.  **选择投稿期刊：**根据论文主题、内容及用户偏好生成期刊建议，用户确认目标期刊后检查其格式要求并调整稿件。

7.  **审稿修改与回复：**用户提供实际投稿稿件、审稿意见及补充资料，系统逐条辅助修改并生成回复，支持多轮处理和版本保存。

#### 4.4 毕业论文项目操作流程

1.  **创建毕业论文项目**：选择“毕业论文项目”，填写项目名称和研究主题。

2.  **准备资料与学校模板：**上传原始数据或已有分析结果、研究设计和方法资料，并提供学校、院系、学位类型、毕业论文模板及写作规范。

3.  **完成科研数据分析与模板解析：**按需生成统计结果、带标签及说明的图表和分析报告；解析学校要求的章节结构及格式。

4.  **组织毕业论文内容：**将研究方法、结果和图表安排到学校要求的章节，检索并引用相关文献。

5.  **生成与导出：**按学校要求生成毕业论文初稿，支持 Word/PDF 下载，供用户及导师审阅。

6.  **导师及评审修改：**用户提供反馈意见和对应稿件，系统逐条处理内容与格式问题，输出修改稿和修改说明，供用户确认并继续完善。

## 二、详细功能需求

### 5. 科研数据分析模块

#### 5.1 模块目标

用户上传生物医学、药学相关科研项目的原始数据或研究资料，由科研数据分析 Agent 结合研究目标识别数据内容，完成数据整理、统计分析、结果解释及图表生成，形成研究结果图表和数据分析报告。

#### 5.2 文件上传

计划支持以下文件格式：

- Excel；

- Word；

- PDF；

- 图片。

用户可以一次上传一个或多个文件。系统需要保存：

- 原始文件；

- 文件名称；

- 文件类型；

- 上传时间；

- 所属项目；

- 文件解析状态。

#### 5.3 文件自动解析

Agent 应首先分析用户上传的文件，并判断文件内容。

Excel 数据需要识别：

- Sheet；

- 行数；

- 列数；

- 字段名称；

- 字段类型；

- 数值变量；

- 分类变量；

- 时间变量；

- 缺失值；

- 异常数据；

- 重复数据；

- 数据之间可能存在的关联关系。

Word/PDF，需要识别其中的：

- 表格；

- 数据；

- 文字；

- 图片；

- 图表；

- 数据说明。

解析完成后生成内部统一的数据描述结构，为后续 Agent 分析使用。

#### 5.4 数据分析需求输入

用户上传资料后，可以使用中文或英文描述需要分析的问题及希望获得的结果。

输入内容

用户可说明以下内容，帮助系统理解需求：

- **分析对象**：需要使用的文件、数据字段或研究人群；

- **分析目标**：希望比较的差异、了解的关系或回答的研究问题；

- **输出要求**：希望生成的图表类型及需要重点解释的内容。

需求示例

- “分析不同年龄组之间的指标差异，生成柱状图并解释结果。”

- “分析各变量之间的相关性，生成带标签和说明的热力图。”

- “比较治疗组和对照组的指标差异，并整理分析结果。”

系统处理

1.  结合用户描述和已上传资料，识别分析对象、分析目标及输出要求。

2.  将需求整理为相应的数据分析任务，交由科研数据分析模块执行。

#### 5.5 数据分析执行

科研数据分析 Agent 根据用户需求调用数据分析工具执行真实计算。原则上：**大模型负责理解、规划和解释，计算工具负责实际计算。**系统不得仅让大模型通过阅读数据后直接猜测统计结果。

#### 5.6 图表生成

用户可以指定需要生成的图表。例如：

- 热力图；

- 散点图；

- 折线图；

- 柱状图；

- 箱线图；

- 小提琴图；

- ROC 曲线；

- 森林图；

- Kaplan-Meier 曲线等。

系统也可以根据分析类型自动推荐图表。

生成的每张图都必须是带标签和说明的图，使读者仅查看图及其附带图注，也能理解展示的变量、分组和数值含义。按图表类型在图内标注：

- 图标题；

- X/Y 轴名称及单位（适用时）；

- 分组名称、变量名称、图例或颜色刻度（适用时）；

- 数据标签及必要统计信息（适用时）。

每张图还应有与图关联的图号、图注或简短说明，解释图中指标、分组或缩写，以及读图所需的统计标记；这些内容应随图片一起在数据分析报告或论文中展示和导出，不能只放在与图片脱离的正文里。例如热力图需标明行列变量、颜色与数值的对应关系，以及采用的相关性指标（如适用）。图中的文字及附带说明使用用户为该任务选择的中文或英文。

#### 5.7 数据分析结果解释

系统需要对每一个重要分析结果生成对应文字解释。例如：

图1：相关性热力图

对应生成：

- 分析目的；

- 使用数据；

- 分析方法；

- 主要结果；

- 结果解释；

- 可用于论文中的描述文字。

最终实现：**图 + 数据 + AI 解释**之间的绑定。

#### 5.8 数据分析报告生成

完成分析后，系统自动将分析结果整理为数据分析报告。最终支持Word、PDF格式下载。报告可包含：

1.  数据概况；

2.  数据质量情况；

3.  数据处理方式；

4.  分析方法；

5.  统计结果；

6.  带标签及说明的图表；

7.  图表结果解释；

8.  主要发现；

9.  分析总结。

报告内的图片和分析结果应根据项目类型，传递给该项目对应的SCI科研论文生成模块或毕业论文初稿生成模块。图表传递至后续模块时，应保留对应的标签、图注与说明。

审稿或评审要求重新分析时，科研数据分析模块基于用户补充或确认的数据执行计算，保存方法、结果和图表的新版本，供相应写作模块更新论文。需要新增实验或采集数据的事项由用户完成后补充材料。

### 6. SCI科研论文生成模块

#### 6.1 模块目标

在 SCI 科研论文项目中，基于用户自己的研究资料、真实分析结果和可核实文献，生成以原创研究为主体的论文初稿，并提供投稿期刊建议、审稿意见处理及回复辅助。初稿采用 Title、Abstract、Introduction、Results、Discussion、Materials and methods、References 七部分结构，具体要求见 6.4。

本模块使用内置论文结构；用户可提供参考论文，帮助系统理解研究结果的组织方式、图表引用及写作表达。参考论文中的实验、数据和结论不得作为用户自己的研究结果。

#### 6.2 研究资料理解

系统接收科研数据分析模块的图表、分析结果和报告，也接收用户补充的图片、文档及研究方法资料。首先整理以下信息：

- 研究问题：研究主题、研究目的，以及用户希望回答的问题或检验的假设；

- 研究设计与方法：研究对象或样本、分组、材料、实验或调查步骤、研究条件及实际使用的统计方法；

- 研究结果：每张图和每项分析对应的问题、关键数值、单位、样本量及统计信息（资料中具备时）；

- 资料关联：建立研究问题、方法、分析结果与图表之间的对应关系，区分用户研究结果和外部文献证据；

- 完整性检查：识别缺失或矛盾的信息，提示用户补充或确认。不得仅凭图片推断实验细节、样本量或统计显著性。

#### 6.3 研究结果与图表组织

系统按研究发现及其逻辑关系组织 Results 小节，将支持同一研究问题的图表和分析结果归为一组。每个小节应说明研究目的或比较对象、实际观察结果，并在相关描述中引用对应图表。

- 确定结果顺序：依据研究问题及证据之间的关系安排小节，避免逐张图片孤立描述；

- 组织图表：保留图表与原始数据或分析结果的关联。同一结果组中的图表可在同一小节展示；已有组合图应保留 A、B、C 等子图标识及对应说明；

- 统一引用：使用一致的图号、表号及子图引用，并检查正文引用与图表是否对应；

- 完善图注：说明图中对象、分组、缩写、统计标记及资料中已有的样本量、误差线含义等；缺失信息标记为“待补充”；

- 区分结果与解释：Results 描述本研究的实际发现，进一步的意义解释、文献比较及局限性放入 Discussion。

例如，六张图可以按研究内容分为“研究对象的基础特征”（图 1、图 2）、“主要指标变化”（图 3、图 4）和“相关因素分析”（图 5、图 6）三个 Results 小节。分组名称和结论必须根据实际资料确定。

#### 6.4 SCI 科研论文结构生成

SCI 科研论文初稿按以下七部分及顺序输出。中文任务使用对应中文标题，英文任务使用英文标题。确定目标期刊后，可依据其已核实的作者指南调整章节名称、顺序和格式，并记录调整依据。

Title（标题）

准确概括研究对象、核心问题或主要发现，与正文证据一致，避免夸大结论。

Abstract（摘要）

概括研究背景或目的、主要方法、关键结果及结论。摘要中的数值和结论须与正文一致；可在正文完成后提炼生成。

Introduction（引言）

结合已核实文献说明研究背景、已有研究及尚待解决的问题，引出本研究的目的或假设。

Results（结果）

按 6.3 组织研究发现及小节，描述真实分析结果、关键数值与统计信息，插入相关图表及图注。引用文献中的发现不得写成本研究的结果。

Discussion（讨论）

围绕主要发现解释其意义，与相关研究进行比较，说明证据能够支持的解释、研究局限和后续研究方向。结尾可概括主要结论，避免超出已有证据。

Materials and methods（材料与方法）

根据用户提供的资料及实际分析记录，说明研究对象、材料、研究设计、实验或数据获取过程、数据处理和统计方法。必要信息缺失时提示补充，不得编造实验过程、研究条件或审批信息。

References（参考文献）

收录正文实际引用且已核实的文献，统一引用格式，保证正文引用与参考文献列表对应、去重，并保留可核查的来源信息。

七部分是初稿的默认结构。关键词、致谢等附加内容按用户要求或已确认的目标期刊要求处理；检索关键词用于查找文献，不自动成为独立正文部分。

#### 6.5 文献检索

文献检索是 SCI 科研论文和毕业论文写作及修改过程中的共用步骤。系统根据研究主题、研究资料、分析结果及审稿或评审意见确定检索方向。SCI 科研论文的检索重点包括 Introduction 的研究背景、Discussion 中与已有研究的比较，以及 Materials and methods 中实际采用并需要引用的方法。

自动检索流程

1.  **确定本次检索主题**：Agent 根据当前章节及需要回答的研究问题，提炼具体的文献检索方向。检索方向应围绕用户提供的整体研究主题。

2.  **生成关键词和检索式**：Agent 将检索方向整理为英文专业术语、同义词及适用的 MeSH 主题词，并组合为 PubMed 可执行的检索式；按任务要求补充年份、文献类型等条件。

3.  **自动调用检索接口**：系统后端执行 Agent 发起的文献检索工具调用，通过 PubMed 的官方 API 提交检索式，获取匹配的文献标识，并读取对应的文献记录和可用摘要。

4.  **整理候选文献**：系统按 PMID 去重，整理标题、作者、发表年份、摘要等信息，并保存检索式、检索时间和来源链接，形成候选文献列表。

5.  **交给筛选与引用流程**：候选文献进入 6.6 所述流程。系统核对文献内容与拟写论述的关系后，将确认可用的文献交给初稿生成模块，用于组织正文和插入引用。

写作过程中，如发现新的文献需求或现有依据不足，系统可调整检索词补充检索。仍未找到支持材料的内容，按 6.6 的“无法确认时的处理”执行。

职责分工与接入方式

- **Agent**：理解研究需求，确定检索主题，生成关键词和检索式，并在取得结果后参与筛选及写作。

- **系统后端**：执行 API 请求，获取、去重和保存候选文献信息，并把结果交给 Agent。

- **PubMed**：根据检索式返回匹配的文献记录；文献是否支持当前论述，由系统后续流程核对。

SCI科研论文生成模块和毕业论文初稿生成模块共用这项能力。系统通过 NCBI 官方 E-utilities API 接入 <u>PubMed</u>，使用 ESearch 检索文献标识、EFetch 获取记录和可用摘要，具体依据 <u>PubMed 官方数据接入说明</u> 实现。

文献信息

- **识别与来源信息**：PMID、PubMed 页面链接；

- **书目信息**：标题、作者、发表年份、期刊等；

- **按实际记录获取的信息**：DOI、摘要、关键词、MeSH 主题词及全文链接等。

接口未返回的字段应标记为缺失，不得由模型补造。后端应按 NCBI 的接口要求控制请求频率，并处理请求失败和重试。

适用范围与全文边界

- PubMed 主要覆盖生物医学和生命科学，超出该范围的研究主题不能保证获得足够文献覆盖，参见 <u>PubMed 官方介绍</u>。

- PubMed 的文献记录和摘要不等同于论文全文。系统应分别记录摘要、全文是否实际获取。

- 如需读取全文，可通过 PMC 等来源提供的接口或用户上传的全文获取，并遵循相应使用条件；不能承诺所有候选文献均能获取全文。自动获取 PMC 内容时，参照 <u>PMC 官方数据与获取方式说明</u>。

#### 6.6 文献选择及引用

系统应根据文献实际内容判断其是否支持当前论述，不能仅因关键词匹配就插入引用。

处理流程

1.  **筛选候选文献**：结合研究问题、研究对象和章节主题，排除明显无关的文献。

2.  **读取可用内容**：读取已获取的摘要或全文，并记录本次判断所依据的内容范围。

3.  **核对论述依据**：检查文献中的研究方法、结果和结论是否支持拟引用的表述；只有摘要时，不得引用摘要未提供的具体数据或细节。

4.  **建立引用关联**：将正文论述与对应文献关联，保存 PMID、来源链接及支持该论述的内容依据，便于追溯和人工核查。

5.  **生成正文引用和参考文献**：按所选引用格式插入引用，生成参考文献列表，并检查正文引用与列表是否对应、是否重复。

无法确认时的处理

- 文献内容不足或无法确认是否支持论述时，标记为“待核实”，不作为已确认依据引用。

- 没有找到支持材料的论述，应提示用户补充资料或调整表述，不得虚构文献、DOI 或研究结论。

具体筛选算法和引用验证方式仍需进一步设计。

#### 6.7 SCI 科研论文初稿生成与输出

系统将研究资料、结果与图表分组、实际方法记录及已核实文献整合为论文初稿。各部分可以按内容依赖分步生成，最终初稿按 6.4 约定的七部分顺序排列；已确认的目标期刊格式要求按 6.8 处理。

生成过程

- 生成 Results 与 Materials and methods：依据真实结果及方法资料，建立每项结果与对应研究方法、图表的关系；

- 生成 Introduction 与 Discussion：结合已筛选的文献，说明研究背景、研究意义、与已有研究的关系及局限；

- 提炼 Title 与 Abstract：从已完成正文提炼标题和摘要，并整理 References；

- 检查全文一致性：核对结构完整性、数值、单位、术语、图号、图注及引用关系；保留“待补充”“待核实”标记，便于用户审核。

输出要求

支持 Word/PDF 下载，Word 为可编辑格式。导出文件应包含七部分正文、对应图表及图注、正文引用和参考文献；内容按用户选择的中文或英文生成，图表标签及说明同步使用对应语言。

生成结果需研究人员审核、修改和完善。资料不足时明确列出待补充内容，不得虚构研究结果、实验或文献。后续期刊建议和审稿修改分别按 6.8、6.9 执行。

#### 6.8 投稿期刊建议

系统结合论文主题、研究类型、摘要、主要结果及用户投稿偏好，提供候选期刊和匹配理由。用户可在初稿生成前后发起建议任务，论文内容或投稿偏好变化后可重新生成建议。

输入与匹配依据

- **稿件信息：**研究领域、主题、文章类型、标题、摘要及主要结果；

- **用户偏好：**目标学科、发表语言、开放获取偏好、费用预算及学校或单位的期刊要求（如有）；

- **匹配维度：**期刊收稿范围、可接收的文章类型及相关研究内容与当前稿件的符合程度。

信息核实与建议结果

从期刊官网、作者指南及可核实的期刊数据库获取资料。每个候选项展示期刊名称、官网、收稿范围、匹配理由、需要注意的投稿要求、信息来源和核实日期。无法获取的字段标记为“待核实”。

- 如展示 SCI/SCIE 收录情况、影响因子或分区，应核实相应数据来源、年份及评价体系；不得把 PubMed 可检索直接当作 SCI/SCIE 收录依据；

- 费用、开放获取政策及审稿时长等仅按已核实资料展示，注明适用条件和日期；不估算录用概率或承诺发表时间；

- 用户确认目标期刊后，系统保存其作者指南及要求，检查稿件的篇幅、章节、摘要、图表及引用格式，提出调整项并生成修改版本。

期刊信息接入来源、更新方式和候选排序规则需进一步确定。无法核实的信息应明确提示，不得依靠模型记忆补造。系统提供建议和材料辅助，实际投稿及录用结果由用户确认记录。

#### 6.9 审稿意见处理与论文修改

用户上传或粘贴编辑及审稿人的意见，并提供对应的投稿稿件、目标期刊要求和补充研究材料。意见及稿件支持文字输入或 Word/PDF 文件上传。每轮修改应指定稿件版本，后续多轮意见沿用同一项目管理。

意见解析与修改计划

- 保留编辑和各审稿人的原始意见，逐条编号，记录意见来源、修改轮次及涉及章节；

- 将意见区分为文字表达、结构与论证、文献补充、统计分析、图表、研究方法或补充实验等类别，生成逐条处理计划；

- 对含义不明、相互冲突或涉及研究结论调整的意见，提示用户确认；需要新增资料、分析或实验时列出待办内容。

执行修改与准备回复

- 依据稿件和已有证据修改文字、结构、图表说明及引用；需要补充文献时调用共用检索与核实流程；

- 需要重新统计或绘图时，将任务交给科研数据分析模块，取得实际结果后同步更新 Results、Discussion、Abstract 等相关内容；

- 需要补充实验、样本或研究记录时，标记为“待补充资料”，由用户提供后继续处理；不得虚构已完成实验或新增结果；

- 生成逐条审稿回复草稿，对应原始意见、处理说明、实际修改内容及位置。未采纳的意见应说明依据并交用户确认，未完成事项不得写成已完成。

输出与轮次管理

每轮输出论文修改稿、逐条审稿回复及修改对照说明，支持 Word/PDF 下载。对照说明应记录意见编号、修改前后内容或摘要、所在章节及最终导出稿中的可定位位置，并列出待用户确认和待补充事项。

保留原稿、用户上传的当前稿、系统修改稿及回复稿之间的版本关系。用户确认后用于再次提交；收到新一轮意见时，基于相应稿件继续处理。投稿、返修、录用或发表进展由用户根据实际情况更新，系统不将修改完成视为录用或发表。

### 7. 毕业论文初稿生成模块

#### 7.1 模块目标

在毕业论文项目中，根据用户提供的研究资料、分析结果、学校毕业论文模板及写作规范生成初稿，并根据导师意见和评审建议持续修改完善。模块以提升研究表达、论证完整性和学校格式符合度为目标；具体评价以学校、导师及评审要求为准。

#### 7.2 模板上传

用户提供学校名称、院系、专业及学位类型，并上传适用的毕业论文材料：

- 学校规定的毕业论文 Word 模板；

- 适用的院系或专业毕业论文补充要求；

- 适用的学位类型或培养层次的写作规范；

- 学校发布的毕业论文排版与引用格式说明；

- 用户已有的毕业论文稿件及其他学校要求（如有）。

毕业论文模板计划支持 Word 格式。系统应记录模板名称、适用学校及版本或发布时间；要求缺失或互相冲突时，提示用户确认后再用于生成。

#### 7.3 模板解析

系统分析模板中的：

- 页面结构；

- 论文标题格式；

- 摘要格式；

- 关键词格式；

- 字体；

- 字号；

- 行距；

- 页边距；

- 图题；

- 表题；

- 引用格式；

- 参考文献格式。

同时识别学校规定的章节及顺序。以下为可能出现的内容，具体以适用的学校模板为准：

1.  摘要

2.  Abstract

3.  引言

4.  材料与方法

5.  结果

6.  讨论

7.  结论

8.  参考文献

建立与学校模板对应的章节及格式规则，覆盖标题层级、摘要、目录、图表、引用和参考文献。学校另有封面、声明或致谢等要求时按规范处理；作者身份、签名等信息由用户提供。

#### 7.4 毕业论文内容生成

系统依据用户上传的研究资料、分析结果、学校毕业论文模板及已核实文献，组织各章节内容并生成毕业论文初稿。应检查研究问题、方法、结果和结论之间的对应关系，以及学校要求的内容是否齐全。

内容组织

以下为常见章节的内容分配。实际章节名称、顺序和格式以适用的学校毕业论文模板及规范为准。

| 论文章节     | 内容来源与生成要求                                                       |
|--------------|--------------------------------------------------------------------------|
| 引言         | 根据研究主题及相关文献，说明研究背景、问题和目的。                       |
| 材料与方法   | 根据用户提供的研究过程及实际执行的数据处理、统计分析方法，整理方法描述。 |
| 结果         | 根据统计结果、图表及分析报告，描述本研究的主要发现。                     |
| 讨论         | 结合结果解释及相关文献，讨论研究发现、与已有研究的异同及局限。           |
| 结论         | 概括本研究结果能够支持的结论。                                           |
| 摘要与关键词 | 根据已生成的正文提炼，并按模板要求生成对应语言的内容。                   |

生成要求

- 将图表放入对应章节，保留标签、图注和说明，并使图号与正文引用一致。

- 正文中的数值、单位和统计结论应与分析结果一致；用户自己的研究结果与引用文献的发现应明确区分。

- 对缺失的实验过程、研究条件等必要信息，标记为“待补充”，不得自动编造。

#### 7.5 文献引用

毕业论文初稿生成模块与 SCI科研论文生成模块共用第 6.5、6.6 节的文献检索与引用能力。系统需要能够根据当前论文内容：

- 生成搜索关键词；

- 检索候选论文；

- 判断文献相关性；

- 建立论述与文献关系；

- 插入正文引用；

- 自动生成参考文献列表。

#### 7.6 毕业论文输出

初稿及修改稿支持 Word/PDF 下载，Word 为主要编辑格式。输出应按学校模板检查并保留以下内容：

- 排版；

- 标题格式；

- 页面格式；

- 图片格式；

- 表格格式；

- 引用格式。

用户可下载后继续修改，并将本人修改后的稿件上传为下一轮修改的依据。完成导师或评审意见处理后，同时导出修改稿和逐条修改说明，保留对应的历史版本。

#### 7.7 导师及评审意见处理

用户上传或粘贴导师意见、评阅意见或答辩后的修改建议，并提供对应毕业论文稿件、学校规范及补充资料。系统按稿件版本和修改轮次建立逐条处理记录。

处理过程

- **拆分并编号意见：**保留原文及意见来源，识别涉及的章节和内容、论证、分析、图表或格式问题；

- **形成修改计划：**依据学校要求和已有研究资料提出处理方式；含义不清或导师与评审意见冲突时，交用户确认；

- **完成内容修改：**完善研究问题、方法描述、结果解释和讨论，补充已核实文献；需要重新分析或绘图时调用科研数据分析模块；

- **检查学校格式：**核对章节层级、摘要、目录、图表编号、引用及参考文献，并同步更新因正文修改而受影响的内容；

- **处理待补充事项：**需要实验、原始数据或学校信息时明确列出，由用户提供后再修改，不代造研究事实；

- **生成修改结果：**输出修改稿及逐条修改说明，记录意见编号、处理方式、对应位置、未完成原因及待确认事项。

支持多轮反馈与修改，每轮保留输入稿件、修改稿及说明。用户及导师审核后可继续完善；评价结果由学校或评审方确定，系统通过内容完整性、论证一致性及格式检查辅助提升质量。

### 8. 用户项目中心

系统需要提供统一项目中心。用户可以看到：

- 项目名称；

- 项目类型（SCI科研论文项目或毕业论文项目）；

- 创建时间；

- 最近更新时间；

- 文件数量；

- 数据分析任务；

- 与项目类型对应的初稿生成、期刊建议、审稿修改或毕业论文评审修改任务；

- 任务状态；

- 已生成文件。

- SCI 项目的目标期刊、期刊建议及实际投稿进展；

- 毕业论文项目的学校、学位类型及所用模板版本；

- 当前稿件版本、修改轮次、意见处理状态、待补充材料及回复或修改说明。

项目中心按项目类型展示资料、任务和成果，并支持进入历史项目继续分析、写作或修改。用户可选定稿件版本发起新一轮修改，查看每条意见的处理状态和对应修改位置。

### 9. 任务系统

科研数据分析、文献检索、初稿生成、期刊建议及意见处理均纳入统一任务机制。每项任务记录任务类型、输入资料、所用稿件版本及输出结果；修改任务同时关联意见轮次。

任务状态至少包括：

- 待执行；

- 文件解析中；

- AI 分析中；

- 数据计算中；

- 文献检索中；

- 文档生成中；

- 待补充资料；

- 待用户确认；

- 已完成；

- 执行失败。

发生失败时记录原因并支持重新执行。缺少必要资料时，任务进入“待补充资料”，列出所需材料；补充后继续处理。任务执行状态与论文投稿或评审进展分别记录，生成任务完成不代表论文已录用或评审通过。

## 三、第一阶段产品整体定义

第一阶段 PC 版本围绕SCI科研论文项目和毕业论文项目开展工作：

1.  **创建并确定项目类型**：用户选择SCI科研论文项目或毕业论文项目，明确本项目的写作目标。

2.  **准备资料：**上传原始研究数据或已有分析结果及研究设计、方法资料；毕业论文项目同时提供学校模板和写作规范。

3.  **按需执行数据分析**：解析数据，完成统计分析，生成带标签及说明的图表和数据分析报告。

4.  **按项目类型生成初稿：**SCI 科研论文项目按默认七部分结构组织原创研究内容；毕业论文项目按学校模板和规范组织内容。

5.  **审核与导出：**用户审核论文及图表，导出 Word/PDF 文件；后续可基于当前稿件和反馈意见继续修改。

6.  **期刊建议与审稿修改：**SCI 项目提供期刊候选，按目标期刊要求调整稿件，并根据审稿意见辅助修改和准备回复。

7.  **毕业论文评审修改：**毕业论文项目根据导师及评审建议处理内容和格式问题，保存各轮修改稿及说明。

本项目帮助生物医学、药学领域的用户从原始科研数据出发，完成科研分析、论文初稿生成及反馈驱动的多轮修改。SCI 项目支持投稿期刊选择和审稿回复，毕业论文项目支持学校格式要求与导师、评审意见处理。

系统通过读取资料、理解任务、调用分析与检索工具、组织研究内容和处理反馈，形成可追溯、可修改、可导出的科研写作成果。
