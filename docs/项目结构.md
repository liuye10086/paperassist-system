# 项目结构

更新日期：2026-10-08。本页描述当前代码职责与定位方式；整理过程见[结构实施计划](开发记录/项目维护/2026-10-07-项目结构整理-实施计划.md)。阶段01适用范围75/79项已验收，四项条件工作暂缓；阶段02统一任务、Word独立执行、模型调用与预算、解释迁移、绘图迁移、任务界面与等待恢复前六步均已验收，累计23/57项。最新范围见[第六步交付记录](开发记录/阶段02/任务界面与等待恢复交付记录.md)；前五步证据保留在同目录各自交付记录。

## 顶层目录

```text
paperassist-system/
├─ backend/                  Python 应用、迁移、运维入口及后端测试
├─ frontend/                 React 应用、静态资源及前端测试
├─ script/                   Windows 统一启停、账号初始化、真实队列测试入口
├─ infra/worker/             Linux Worker 镜像和运行说明
├─ compose.workers.yml       RabbitMQ、Worker 和 dispatcher 编排
├─ docs/                     需求、结构说明、开发阶段及交付记录
└─ reference-projects/       本地外部参考源码，Git 忽略
```

依赖目录、缓存、编译产物、日志和本地配置均由 `.gitignore` 排除。`backend/data/`、`backend/backups/` 和 `script/.runtime/` 是本机运行/验证数据，不属于源码，也不随代码分层搬迁。

## 后端

```text
backend/
├─ app/
│  ├─ main.py                FastAPI 组装和启动生命周期
│  ├─ manage_users.py        本机账号管理 CLI
│  ├─ manage_model_budgets.py 本机累计美元预算管理 CLI
│  ├─ api/                   HTTP 路由、请求依赖、上传限制
│  ├─ domain/                分析计算、成果组装、任务轮询及业务规则
│  ├─ adapters/              PostgreSQL 存储、Excel、OpenAI、Word 适配
│  ├─ auth/                  认证、会话、密码及撤销审计
│  ├─ core/                  配置、路径和公共错误契约
│  ├─ db/                    连接、权限、版本检查及表结构
│  ├─ workers/               Celery Worker、dispatcher 和容器运行入口
│  └─ maintenance/           离线导入、审计、迁移报告与恢复演练
├─ alembic/                  env 和冻结的数据库 revision（当前0011）
├─ explanation-policy.example.json  解释策略示例，必需价格/额度无默认值
├─ plot-policy.example.json  绘图策略示例，价格/额度/工具预留需显式填写
├─ scripts/                  离线维护的命令行脚本入口
├─ tests/                    api/auth/db/domain/adapters/maintenance/integration
│  ├─ conftest.py            测试库隔离等共享 fixture
│  ├─ helpers/               认证和任务等共享测试辅助
│  └─ queue/                 显式开启的真实 Linux 队列隔离测试
├─ data/                     原始 Excel、PNG、DOCX（本地）
└─ backups/                  数据库与资产备份（本地）
```

`api` 负责 HTTP 语义，调用 `domain` 和适配器；`domain` 不导入 HTTP 路由模块。`adapters` 处理外部格式/服务和持久化，部分适配器复用纯业务内容模型。`auth` 保留自己的路由、服务和中间件，以免把一个内聚模块重新打散。`maintenance` 是真实运维能力，不因应用启动时不导入就视为无用代码。

`main.py`、`manage_users.py` 与 `manage_model_budgets.py` 是外部入口，保留在包根目录；`__init__.py` 是Python包标记。`workers/` 当前执行Word、新解释和新绘图；新模型任务接统一门面及三级累计美元预算，解释保留严格结构化输出，绘图保留Code Interpreter及原PNG合同。绘图的容器创建、文件上传、Response创建分别持久化POST开始标记和回执；未知提交不重发，已知阶段继续，已核验PNG候选可从本地恢复发布。新任务GET仅读本地，旧绘图/解释job只兼容续取，不补造历史账本。

当前数据库`0011_task_waits`、25张业务表加版本表，迁移前23表全部旧列值、索引与8个资产保留。仓库策略模板没有真实默认预算/价格；本机已有获用户授权的模型策略和测试额度，本轮收尾未改配置、预算或预留。项目任务页、工作区精确历史成果、事件、三级预算及持久等待/原子幂等恢复已实现；资料补充和研究计划待办暂无业务消费者，LangGraph、工作流检查点、通用创建、取消和完整历史映射仍未实现，没有为未来流程预建空目录。验收后五服务已停止并保留broker卷。前六步作为本次阶段节点归档于 `feat/stage02-unified-tasks-models`，提交编号及远端同步状态以 Git 记录为准；具体用户验收证据见第六步交付记录。

## 前端

```text
frontend/src/
├─ main.tsx                  页面唯一入口
├─ app/                      App 组合、全局基础样式、应用样式
├─ features/
│  ├─ auth/                  登录、改密、界面语言
│  ├─ projects/              项目列表、分区导航、详情、摘要和选择状态
│  ├─ tasks/                 统一任务列表/详情、增量事件、待办恢复和精确成果
│  ├─ model-usage/           项目与任务三级预算、估算和调用分页面板
│  ├─ files/                 Excel 上传预览
│  ├─ analysis/              命名流程导航、字段配置和描述统计
│  ├─ figures/               箱线图异步提交、本地轮询、预算恢复和已有PNG展示
│  ├─ explanations/          解释异步提交、本地轮询、预算恢复和结果展示
│  └─ reports/               Word 异步提交、状态轮询、失败重试与下载

│  ├─ components/            鉴权下载等跨功能组件
│  └─ i18n/                  语言状态与公共/流程/错误词典
```

组件测试与功能放在一起；真正跨功能的用例进入 `test/integration`。请求客户端和语言状态各只有一个真实模块实例，避免出现移动后新旧路径各自保存会话状态的问题。CSS 保持基础样式先于应用样式加载；UI改版新增的工作台、项目内容、分析流程和成果样式放在对应功能目录。ProjectResources负责同一项目内文件与分析区域的挂载，AnalysisWorkflow负责命名流程的显示，原分析组件保留既有导航行为。ProjectTasks仅在任务分区挂载，列表/详情通过hash恢复；切项目、失权和注销清除数据，标签页隐藏暂停GET轮询但保留进行中的恢复POST。

## 脚本与稳定入口

```text
script/
├─ dev.cmd                   日常 start / status / stop
├─ test-queue.cmd            真实 Linux 队列隔离验证
├─ setup-database-roles.cmd  新环境运行账号初始化
├─ dev/                      PowerShell 控制器、Windows 进程树与 Worker 编排
├─ database/                 交互式数据库角色设置实现
├─ tests/                    脚本单元测试
└─ .runtime/                 状态、日志及本地验证材料（Git 忽略）
```

以下命令从项目根目录调用，入口保持不变：

```powershell
.\script\dev.cmd start
.\script\dev.cmd status
.\script\dev.cmd stop
```

`dev.cmd` 统一管理前后端及 RabbitMQ、Worker、dispatcher 三个容器；停止时保留 broker 数据卷，不关闭 Docker Desktop 或 PostgreSQL。独立队列测试使用 `script/test-queue.cmd`，默认后端测试不会启动 Docker 或连接 broker。配置与隔离边界见[脚本说明](../script/README.md)和[Worker运行说明](../infra/worker/README.md)。

数据库 CLI 的当前模块路径已调整；以下只读命令从 `backend` 目录执行：

```powershell
.\.venv\Scripts\python.exe -m app.db.database check
.\.venv\Scripts\python.exe -m app.maintenance.database_audit
```
