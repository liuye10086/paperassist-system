# 本地内测部署与回退手册

> 2026-10-27：第四批用户验收后，本批验收和恢复环境已停止、容器/卷/候选/备份保留。下列是可复用操作手册，不表示服务当前运行，也不授权自动重启或发布。见[收尾记录](../开发记录/阶段10/2026-10-27-第四批验收与阶段收尾记录.md)。

本工具只处理 `script/.runtime/stage10-batch04/releases/<namespace>` 的新隔离环境。它提供离线工程部署与合成验收入口，不代表生产发布、真实模型验证或用户验收。原环境、历史数据、备份和失败目标全部保留；没有清理动作。

## 前提与候选

在仓库根目录的 PowerShell 中执行，宿主只需要 Python 标准库、Docker CLI 与已有前端构建产物。应用运行时全部位于 Linux 容器中。构建只使用本地固定镜像，禁止拉取和联网安装。20 个合法本地字体由 `--fonts` 指定（默认 `C:/Windows/Fonts`），只读挂载。Docker Linux 建议 16 CPU / 8 GiB，本工具最低检查 4 CPU / 7 GiB；各服务资源上限在 `compose.release.yml` 中固定。

```powershell
python script/release/release.py preflight
python script/release/release.py build
```

`build` 输出 `candidate.json` 绝对路径。保存该路径到 `$candidate`；收据绑定完整镜像 ID、源文件精确 SHA manifest 和镜像内 manifest label。运行及恢复使用候选 context/compose.release.yml 快照，每次校验 manifest SHA，工作区 Compose 漂移不会改变旧候选。候选上下文仅包含显式白名单源码、迁移、入口和 `frontend/dist`，不读取 `.env`、原 data/backups、私钥或宿主依赖。基础镜像 installed requirements 必须精确匹配当前 `backend/requirements.txt`。前端改变后先通过既有本地工具构建 `frontend/dist`，再创建新候选。

## 创建、真实迁移及启动

namespace 必须全新、小写字母开头、最多 32 个小写字母数字或连字符；端口必须显式指定。以下只是示例，新环境名称和端口应按当次验收选择。

```powershell
$candidate = 'C:\Users\86182\Desktop\paperassist-system\script\.runtime\stage10-batch04\candidates\<id>\candidate.json'
python script/release/release.py create --namespace acceptance-a --candidate $candidate --port 18443
python script/release/release.py init --namespace acceptance-a --revision 0052_admin_configurations
python script/release/release.py switch --namespace acceptance-a --candidate $candidate
python script/release/release.py up --namespace acceptance-a
python script/release/release.py sample --namespace acceptance-a
python script/release/release.py maintenance --namespace acceptance-a --mode normal
python script/release/release.py watch --namespace acceptance-a
```

`create` 生成私有角色材料、本地 CA/server 证书和维护意图；不启动业务服务。CA 签名私钥只在生成时存在，未保存。`init` 创建新的 PostgreSQL 实例 `paperassist_system/public`，owner/runtime 不同，runtime 禁止 DDL/TEMP/角色继承。迁移凭证只挂载到显式 migration 工具。若 bootstrap 已成功而迁移容器创建失败，保留原目标和 TLS，使用 `resume-migration --namespace <name> --candidate <修正候选json> --revision 0052_admin_configurations`，再以同入口 `--revision head` 续跑；不要重复 init。每次只有迁移成功才写 revision，head 还必须通过 schema/权限检查才写 schema_ready。示例通过真实 0052→0053 链执行；普通全新初始化可省略 `--revision` 直接到 head。没有新增 0054，也没有变更原环境 bootstrap/backup 的限制。

`up` 必须通过 schema/runtime 权限检查。Web 唯一公开地址是 `https://localhost:18443`，绑定 `127.0.0.1`，API 同时连接 private internal 网络和单独的 front 非 internal 桥，使本机 Docker 实际发布 TLS 端口；只有 API 连接 front。数据库、broker、worker、dispatcher、renderer 和 operator 仍仅在 private 网络，均无主机端口。确切 front/private 名称、标签、internal 属性及实际附加网络 ID 均核验；旧候选 private-only API 仍可读检。API 健康检查实际请求 https://127.0.0.1:8443/api/v1/health，使用 /run/tls/ca.pem 验证 CA 与 SAN。生产会话使用 Secure cookie，可信 Origin 精确匹配上面的 localhost HTTPS origin。客户端使用新环境 `tls/ca.pem` 校验证书，例如 `curl.exe --cacert <绝对ca路径> https://localhost:18443/`。工具不会修改系统信任、不会跳过 TLS 验证；浏览器无法信任该 CA 时，应明确记录浏览器验证限制，不绕过它。

`watch` 在操作员终端每 15 秒尝试采样，每轮只做一次全资源绑定检查，worker/dispatcher/broker 通过确切容器 ID 并行探测（各8秒超时），随后复核 worker 容器/镜像/StartedAt 与 startup 回执，再复用已验证 collector（8秒超时）；Ctrl+C 停止。45 秒没有有效回执显示 unknown。worker 必须通过真实 Celery probe，而且 startup_id/时间必须对应当前运行容器；没有观测的外部限流保持 null。collector 每个环境/候选镜像使用一个受限持久容器，通过 exec 执行固定动作，不随采样次数增长；切换后旧 collector 停止保留。watch 与备份/切换使用同一环境操作锁，维护/失败时不会伪造绿色状态。worker 并发部署上限显式允许 2，实际取已批准配置与上限的较小值；修改配置后必须重启才能生效。

## 维护、一致备份及候选切换

```powershell
python script/release/release.py maintenance --namespace acceptance-a --mode maintenance
python script/release/release.py backup --namespace acceptance-a
python script/release/release.py switch --namespace acceptance-a --candidate <新candidate.json绝对路径>
python script/release/release.py up --namespace acceptance-a
python script/release/release.py sample --namespace acceptance-a
# 完成该候选验收之后，由操作员明确解除维护：
python script/release/release.py maintenance --namespace acceptance-a --mode normal
```

backup 依次写维护意图、优雅停止 API（允许已接收请求完成）、等待 queued/running 为 0、停止 dispatcher/worker、再次验证停机与任务计数，再执行 pg_dump 和完整 assets 复制（包括隐藏 storage intents）。API 不设置内部请求取消期限，Docker stop 120 秒；超过外层期限的强杀/137、命令超时或 OOM 均无法获得一致性收据。默认任务排空期限 180 秒，超时保留维护和失败证据，不取消或修改业务任务。

快照记录所有表/序列指纹、asset 清单与 SHA、dump SHA、候选及源码 manifest；操作后重复比对数据库和原 assets。只有实际完成全部检查才写 backup 收据。备份不会自动重启服务或解除维护。snapshot 源路径由命令输出返回；保留该路径与对应候选。切换仅前向迁移，失败保持维护，不执行 downgrade。

## 配对快照恢复至全新目标

```powershell
python script/release/release.py restore --namespace rollback-b --backup <backup目录绝对路径> --candidate <该备份配对candidate.json绝对路径> --port 18444
python script/release/release.py up --namespace rollback-b
python script/release/release.py sample --namespace rollback-b
```

restore 在创建前校验 dump、asset、源码 SHA 与完整候选 ID；目标namespace/目录/Docker项目或卷已存在即拒绝。恢复到新的空实例，重新授予受限 runtime 权限并验证实际表、序列和 asset 指纹。恢复成功仍保留维护；需针对下载、权限、草稿及任务进行验收，再显式 normal。旧源和失败目标均不覆盖、不删除。恢复到旧候选属于新目标恢复，不是数据库降级。

```powershell
python script/release/release.py status --namespace acceptance-a
python script/release/release.py stop --namespace acceptance-a
```

`stop` 只停止这个项目的服务，保留所有容器、卷、目录和证据。禁止 `down -v`、`prune` 或手工删除历史材料。所有命令错误只输出安全的固定说明；需要诊断时先确认隔离目标，再在私有终端查看对应服务日志，避免把凭证输出到公开收据。
