## 契约与文件责任

新增证据模块 `backend/app/domain/literature_evidence/`，核心 `LiteratureEvidenceService(assets)`；所有读取/写入遵守owner/project。接口前缀 `/api/v1/projects/{project_id}/literature/evidence`。所有POST沿用 `Idempotency-Key`，版本冲突409，无权限沿用现有返回约定。

| 接口 | 输入/输出约定 |
| --- | --- |
| GET `/config` | `project_id, full_text_mode:'user_upload', real_model_calls:false, supplement_round_limit:1, supplement_candidate_limit:20` |
| GET `/material-options?page` | `items:[{file_id,filename,file_type,versions:[{kind,version_id,version,label}]}],total,page,page_size:10`；kind为document_version/ocr_review_version；通过已有项目文件和版本选择，不要求用户填内部ID。 |
| POST/GET `/materials` | 写入 `{project_reference_id,file_id,source_kind,version_id,source_description,match_note}`；source_kind为上述文档/OCR版本，人工确认书目对应；返回`id,project_reference_id,source,source_description,match_note,created_at`。列表可按project_reference_id过滤，分页10。 |
| GET `/materials/{id}/source?page` | 复用已存文件内容与坐标：`source,items,total,page,page_size:20`，不信任客户端自报文本/页码。 |
| POST/GET `/claims` | 写入 `{content,context,output_language}`；返回`id,project_id,revision,content,context,output_language,created_at,updated_at`，列表分页10。 |
| POST `/claims/{id}/versions`；GET `/claims/{id}?revision` | 写入 `{expected_revision,content,context,output_language}`；旧版本保留。GET详情附`versions:[{revision,content,output_language,created_at}],is_current`；历史判定不能作为新论述已确认状态。 |
| POST/GET `/claims/{id}/evidence` | 写入 `{claim_revision,project_reference_id,source_kind:'abstract'或'material',search_id?,material_id?,item_id?,quote}`；abstract须明确本次search_id，material须实际材料item。服务端核对quote为实际来源精确子串，冻结来源/位置/读取范围。GET按revision和page查询，返回`id,claim_id,claim_revision,project_reference_id,quote,reading_scope,source,location,created_at`分页10。 |
| POST/GET `/claims/{id}/reviews` | 写入 `{claim_revision,project_reference_id,evidence_ids,status,relevance,reason,narrowed_statement,limitations}`；status为四种，relevance为related/unrelated/uncertain。只保存人工决定，记录actor和历史；supported/partial必须存在同一论述版本/文献的有效证据，unrelated不能supported，partial必须有收窄说明，缺证据只能needs_review。GET按revision和page，分页10。 |
| POST `/claims/{id}/supplement` | `{claim_revision,query,reason}`；服务端构造普通SearchRequest，继承论述主题/语言，limit=20。锁定稳定claim_id，全事务或稳定幂等键确保最多一个关联search；返回`task,round:1,limit:20`。论述详情附`supplement:{task_id,round,limit}|null`。已有NCBI消费者处理关闭等待/有限重试。 |

模型模块 `backend/app/domain/literature_assistance/`，接口前缀 `/api/v1/projects/{project_id}/literature/assistance`：

- POST `/tasks`：判别联合输入；`kind='search_plan'`含`research_topic,source_context,output_language`；`kind='evidence_review'`含`claim_id,claim_revision,project_reference_id,evidence_ids,output_language`。返回既有TaskView，202/幂等200。
- GET `/tasks?page` 和 `/tasks/{task_id}`：详情返回`task,kind,input_version,result,real_calls_enabled:false`，列表为相同详情的分页10。
- 统一任务类型 `literature_assistance`，工作流 `literature_assistance_v1`。正常业务进入持久授权等待；测试可注入合成模型provider，走既有模型网关、预算/调用记录和检查点，结果只为建议，不写人工reviews。
- search_plan建议固定字段`direction,terms,synonyms,mesh_candidates,query,explanation`，MeSH候选标注未核验。evidence_review建议固定字段`status,relevance,reason,narrowed_statement,limitations,evidence_ids`，只允许输入内证据ID，不能虚构来源。
- 证据服务提供 `assistance_snapshot(project_id, request_dict)` 返回冻结的项目/论述/书目/证据/语言材料；`assert_assistance_inputs_current(project_id, snapshot)` 在执行前核对当前论述与实际来源。旧任务/建议只读保留，不能应用到新版本。规划快照可由模型模块构造，不需要全文读取。
- 数据模块分别为 `db/literature_evidence_schema.py`、`db/literature_assistance_schema.py`；新增关系按已有复合owner/project外键约束。父任务统一整合metadata、当前head、冻结0031迁移及只读审计入口，避免并行覆盖公共文件。
