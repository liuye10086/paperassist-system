# 阶段02第四步：解释任务迁移

日期：2026-10-08。沿用 `feat/stage02-unified-tasks-models`，用户已确认第四步“验收成功，通过”。前四步均未提交；验收后五个项目服务已停止，正式范围与证据见[解释任务迁移交付记录](解释任务迁移交付记录.md)。下方设计及开发验证保留实施过程，不将本步通过视作整阶段完成。

## 开工时核查结论

现有解释 POST 直接向供应商提交，GET 会续取、验证并保存；启动扫描也处理旧解释任务。现有统计事实构造、六节引用校验和解释产物可复用。统一任务执行器仅支持 Word，模型门面已有预算记账但缺解释结构化输出和实际策略配置。不能只换一个调用函数就宣称完成迁移。

本步不增加依赖或 LangGraph。扩展已有 Celery、RabbitMQ、outbox、租约和 ModelGateway，保留 Windows API/Vite/PostgreSQL、Linux Worker 的运行方式。不设置真实模型价格、默认额度，不发起真实付费调用。

## 交付设计

1. 新解释 POST 只保存统一任务与 outbox；GET 仅读本地产物和状态。同请求键重放和串行重复提交复用任务；不同请求键并发争用同一来源时可返回冲突，避免创建两个收费任务。历史已保存解释和 Word 继续可读。项目概览显示统一解释任务。
2. Worker 一次只做一次 POST 或 GET。供应商未完成时，同事务增加任务版本、写 `deferred` 事件和延迟 outbox、释放租约。下次认领同一逻辑 attempt，轮询不耗尽崩溃重试次数。真正失联才走租约恢复。
3. 每个逻辑任务使用稳定调用键；已有响应编号只 GET。预留后崩溃由当前有效租约承接尚未提交的调用，开始提交时在同一事务验证租约。未知提交且无响应编号进入待确认，保留预留，不自动再 POST。
4. 网关增加受信任的解释输出格式枚举，对应原严格 JSON Schema。先持久化供应商用量，再解析 JSON、校验事实引用和保存解释；错误输出仍记实际已发生的用量。保留原 `provenance.input_sha256` 的材料摘要，另存统一调用关联，保持 Word 来源校验。
5. 解释与任务成功状态在同一事务提交；提交前再次校验租约、所有者、来源版本及文件完整性。新增可空 `tasks.result_explanation_id`，不改历史产物格式。
6. 服务端通过显式策略文件配置模型、提示词版本、输出上限、价格版本、输入预留和单任务上限。专用解释入口创建任务时冻结策略，并同事务建立任务预算；用户/项目累计预算仍由现有管理命令配置。无价格、无单任务配置不创建可收费新解释；缺用户/项目预算则任务等待，补足后显式恢复。
7. 为保持第一步通用任务持久化合同，内部 `TaskService.create` 仍可保存没有执行策略的解释任务；没有通用 HTTP 创建入口。执行器必须安全等待，不能自行填价或付费。恢复不得用未知配置覆盖已冻结策略。
8. 独立解释配置查询只显示可用状态和模型，不返回密钥、价格文件路径等。Linux Worker 独享模型密钥文件；dispatcher 不挂载模型密钥。测试栈不复制开发密钥，密钥变更需明确使 Worker 重建生效。
9. 前端支持排队、执行、预算等待、未知提交、失败和成功；后台等待不锁住整个工作台。预算恢复复用原任务，已有调用继续复用，尚无调用时只建立首次调用；终态输出失败后明确提示再次生成可能收费，用户显式操作才创建新逻辑任务。未知提交本步不提供盲目再次付费按钮。

## 历史兼容边界

- 已保存解释/报告原样读取，无需模型配置；不补造历史 task、价格或预算记录。
- 旧 `explanation_jobs` 中已有响应编号的请求保留 legacy-only 扫描，只续取同一响应。新任务不写旧表。
- 旧提交无响应编号超时标为未知；不迁成可自动提交的新任务。旧失败仅显式重试进入新机制。
- 历史解释费用未纳入统一账本，不把“未知”写成零。完整历史映射与人工核对不在本步冒充已完成。
- 绘图继续原执行机制；模型工具容器及绘图迁移为下一步，不在本步提前实现。

## 验证与实施顺序

采用先失败测试、实现、专项回归和独立审查。并行分工为网关/策略、执行器、API/前端/历史兼容；主代理负责迁移、运行配置、整合和交付。

- PostgreSQL 隔离 schema：迁移/回退/元数据一致性；新增字段、事件约束和原数据保持。
- API：POST 无供应商调用、GET 无执行副作用、并发幂等、所有权/来源、缓存优先、预算恢复、未知提交阻断。
- 执行/网关：多次续取仍同 attempt；重复消息和过期租约；预留后、提交中、回执保存后崩溃；保存失败只续取同一响应；三层预算不足零 POST；终态坏输出仍记用量。
- 前端：新旧状态、成功后载入产物、预算恢复、失败费用提示、切换卸载、后台执行时工作台可用；全量前端、build、lint。
- 真实隔离 RabbitMQ/Linux Worker：模拟供应商、独立队列/schema/资产，无真实密钥/网络调用。验证解释完成、延迟续取及恢复，保持 Word 任务可运行。
- 自动验证后备份开发数据库和资产，显式迁移 `0009_explanation_tasks`，检查旧表旧列和资产指纹。只执行本步必要迁移，不制造开发测试任务。
- 最后 `script/dev.cmd start`，核对五个项目服务、页面与 API，提供网址供用户手工验收。用户验收前保留运行；验收后停服并更新正式文档。

## 已知限制与待验证项

输入字节上界和预留额是本地准入估算，不能保证供应商账单绝不超限；真实用量按回执保存。无响应编号的未知提交仍需后续人工核对能力。真实模型质量/模型权限/真实价格和额度均不在模拟验证中声称通过。开工时原生服务已停；Docker 查询曾再次有界超时，根因未明。后续项目启动及状态检查正常，未重启全局 Docker，不据此认定间歇超时已修复。

供应商已知响应返回404时，本步保留账本并显示不可恢复，不自动创建替代付费调用；账号停用后的原响应不再自动续取，费用仍可能待核对。预算等待和无调用的缺配置任务可显式恢复；已有调用/策略不会被当前配置静默替换。

## 管理配置方式

仓库的 [策略示例](../../../backend/explanation-policy.example.json) 故意包含无效的必填空值，不能直接用于收费。将其复制为 `backend/.env.explanation-policy.json`（已被 Git 忽略），核实模型支持后台 Responses 与结构化输出后填写模型、价格版本、必需价格、输入预留和单任务上限，再在 `backend/.env` 的 `PAPERASSIST_EXPLANATION_POLICY_FILE` 指向该文件。单价单位是“每百万 token 的微美元”，金额上限单位是“微美元”，1 USD = 1,000,000 微美元。缓存写入单价未知时可保持 null，不用零代替未知价格。

用户和项目累计额度继续通过 `python -m app.manage_model_budgets show/set` 的本地管理入口设置，需明确用户、作用域、金额与预算版本。单任务额度由显式策略在接受任务时冻结。此步实施不填写这些真实金额，开发页面应如实显示尚未配置；历史解释和报告可继续读取。

`OPENAI_API_KEY_FILE` 是统一解释的可选密钥文件，旧绘图仍使用 `OPENAI_API_KEY`。`script/dev.cmd start` 把密钥写入私有运行目录，仅挂载到 Worker；后台密钥变更后需停止并重新启动项目服务，不能把网页“重新读取配置”当成容器密钥更新。API 查询配置无网络模型调用，配置完整也不代表已验证远端权限。

不提交、推送、合并或清理分支；这些仍需用户后续明确授权。
