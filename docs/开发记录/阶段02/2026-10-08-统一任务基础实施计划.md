## 目标与边界

提供统一任务持久化、内部创建/状态服务和有权限的只读查询，为第二步独立执行准备基础。现有绘图、解释、报告入口和扫描器保持原行为。无 Celery/RabbitMQ/LangGraph 安装，无真实模型调用，无生产测试任务或任务创建/恢复/取消 HTTP 入口。

遵循数据库→后端→验收；本步不建立空任务中心。前端只补公共错误码翻译。完成自动验证后备份并显式升级开发库，核对旧记录与资产保持，再通过 `script/dev.cmd start` 提供原流程验收。用户确认验收后停止服务并更新交付记录/阶段进度；没有明确提交信息和授权不提交推送。

## 契约

- 生命周期：`queued/running/waiting_input/waiting_confirmation/succeeded/failed`；阶段：`parse/plan/compute/search/interpret/write/export/verify`。显示状态优先使用等待/终态，只有 running 时映射阶段。
- 初始内部类型只覆盖现有来源可验证的 `boxplot/explanation/word_report`，不是这些业务已经迁移的声明。输入为明确的 file/run/revision，以及按类型必需的 figure/explanation 引用；不接受调用方自填快照或任意研究正文。
- 服务端从已有记录建立快照，校验用户启用、项目归属、文件→统计→图表→解释来源关系及当前配置版本；快照固定来源哈希、工具/提示词版本及当前实际输出语言 `zh-CN`，不把项目英文偏好当作已有英文引擎。
- 创建幂等键按用户、项目、类型唯一；输入请求规范化摘要绑定原始请求。同键同输入在权限检查后返回原任务，即使后续配置变化；同键异输入409。新键须验证当前来源版本。任务、创建事件、outbox 在一个事务写入。
- 状态更新是内部方法，要求 `expected_revision`；queued→running 时记录新 Attempt，running 可变更阶段或进入等待/成功/失败；waiting/failed→queued 须明确原因，后续 HTTP 恢复仍需补输入与恢复幂等契约。succeeded 不允许重新入队。无效转换和过期修订号409。同状态、阶段和原因不增加事件；仅替换等待/终态原因不属于本步合法操作。
- 每任务事件游标从1递增，与状态修订号一致，在锁内分配；不使用可能提交乱序的全局序列作读取水位。
- 四张表：`tasks/task_attempts/task_events/task_outbox`。JSONB 与 timestamptz 用于新增记录，不改旧表格式。Attempt 的租约/心跳和 Outbox 的发送字段先建立契约，本步不实现领取、转发或恢复扫描。
- 只读 API：`GET /api/v1/tasks/{task_id}`，`GET /api/v1/tasks/{task_id}/events?after=0&limit=50`；limit 1–100，after 非负大整数。只返回公开任务/事件投影，不返回原始输入快照、幂等键、租约、内部错误或服务器路径。他人/未知任务统一404；管理员不扩大研究内容权限。
- 保留 `{detail:{code,message,params}}`；任务查询错误另附 `request_id` 和白名单 `details`，响应头 `X-Request-ID` 与正文一致，服务器生成标识，不信任客户端标识。其它旧接口的正文结构保持原样。
