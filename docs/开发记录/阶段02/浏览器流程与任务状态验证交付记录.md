## 浏览器实际流程与数据佐证

1. **预算不足与只读操作。** 执行器实际因隔离任务额度1013微美元小于预留要求1014而拒绝，模型调用和预留均为零。页面显示中英等待说明；刷新、切到空项目再返回、关闭重开深链仍读取同一任务。此阶段19张业务表、项目全行、任务、资产和供应商计数均未改变。
2. **继续原任务并离开页面。** 测试控制仅提高该隔离任务额度；浏览器点击继续，真实`/resume`返回202，原等待得到解决。随后关闭页面，由测试控制显式运行正常绘图执行器，重开同一深链读到完成状态及PNG入口。仍是原task ID、第二次attempt；仅有一次合成模型调用，container/upload/response各一次，没有真实供应商构造。
3. **安全失败重试。** 夹具明确注入已保存的`report_render_failed`；浏览器显示中英错误及重试按钮，真实重试HTTP返回202。正常本地Word执行器完成原任务的第二次attempt，并复用同输入已保存的确定性报告；报告总数2→2。浏览器实际下载42687字节，SHA-256与原Word一致，没有把重试写成另建新报告。
4. **双语状态与费用。** 逐行打开两页中的13条目标任务，两种语言的列表状态、详情状态、处理阶段及输入版本均相符。两种未实现资料/确认等待显示诚实只读说明，无可操作按钮；补充资料样例另核对两语言均无输入框。矩阵浏览与语言切换未改变19张业务表或触发模型调用。绘图成功后未知工具费用仍待核对：内部已计1微美元、剩余预留1013微美元，三个预算层次均保持预留，不显示免费或实际已结清。

旧PNG、Word及其图表/解释/报告JSON在每次控制快照中逐字节比较保持。预算任务仅新增自身PNG，两个流程成果的用户、项目、来源和原任务归属均核对。语言切换只写合成账号偏好；首次未登录`auth/me`的401是正常登录前状态，不是业务失败。
