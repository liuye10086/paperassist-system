## 全局约束与核对规则

1. 仅允许已结束的`model_calls.status=completed|failed`核对；reserved/submitting/submitted/submission_unknown/released拒绝。未知提交保持待核对，金额证据不替代执行最终性证据。
2. token凭证必须精确匹配已保存`provider_response_id`；tool凭证必须匹配`provider_state.container_id`，且当前调用确实使用Code Interpreter。容器跨调用有歧义时拒绝，不自行分摊。没有response的准备失败可以记录工具部分，但不能无凭证认定模型费为零。
3. 凭证类型限供应商逐项费用材料或明确支持回复；记录受限引用、原件SHA256、对象、组件、币种USD和金额。管理员核验原件真实性与覆盖范围，文件摘要只证明文件内容；程序不声称自动认证供应商账单。
4. 金额使用整数微美元；NULL为未知，0必须有明确零费用凭证。原用量、原价格快照、原估算及历史事件不改写。保留本机操作者、时间、原/新实际金额及有符号预算记账差额。凭证正文、密钥、绝对路径不入库或进入API。
5. 同一call/event_key同正文重放返回首次核对回执；不同正文冲突。先幂等检查，再检查expected_revision；不同键并发同revision仅一个成功。修正追加新事件，不删除原记录。全部核对不改变模型/任务执行状态，不新增收费请求。
6. 仅token业务取得token凭证即齐全；绘图必须token和tool均有凭证。原usage_status和pending_count保持原估算语义；新增独立核对状态/统计。
7. 自动验证使用专用测试库、合成凭证及模拟供应商，不调用真实模型、不写开发库核对数值、不改真实额度。自动验证后按既定`script/dev.cmd start`启动验收。

## 数据与预算合同

迁移`0013_cost_reconciliation`仅追加：`model_calls.actual_token_micro_usd`、`actual_tool_micro_usd`（可空非负BigInteger）和`reconciliation_revision`（默认0）；`usage_events.reconciliation`可空JSONB，事件类型增加`reconciliation`。旧列值、旧索引和资产保持；不补造历史实际金额。新字段及事件形状增加数据库约束，迁移可在隔离库往返验证。

核对事件payload保存请求内容、操作者、revision、previous_actual_micro_usd、actual_micro_usd、accounted_before/after_micro_usd、delta_micro_usd及首次返回回执；时间沿用事件created_at。现有(call_id,event_key)唯一约束及schema事务写锁保持。

预算规则：未核对调用保持原算法。部分核对时，accounted保持原合计估算A；旧基线占用B按原估算/原预留与usage状态重建，不使用前一次部分核对提高后的值。已核对部分总和C，未核对部分原预留R（token=总预留−工具预留，tool=工具预留），则总占用为`max(B, C + max(R, A))`，剩余预留为总占用−A。这样不会让已知超额被原预留掩盖，代价是凭证未齐时可能多保留额度。全部齐全后accounted=实际总额、有效预留=0，三级reservation的记账额和状态同事务更新到绝对值；物理`reserved_micro_usd`始终保留最初预留基线，不改写为零或部分核对后的占用。超预算真实金额完整保留并阻止后续准入。迟到观察可以追加原用量，但不能覆盖已核对金额/预算；已完整的原估算保持，原来不完整的估算可以补齐。

必要用例：Rtoken120/Rtool300、原token估算1010，旧占用1310；仅tool实际600时占用至少1610。全部token实际1000/tool600后记账1600、预留0；同键重放不变，token修正900后记账1500并保存差额−100。

## 冻结的实现接口

后端新增`app/domain/model_usage/reconciliation.py`及`reconciliation_contracts.py`（预算纯计算可拆`accounting.py`）。公开内部管理接口：

```python
class ModelReconciliationService:
    def __init__(self, user_id, config=None): ...
    def inspect(self, call_id): ...  # 本机管理详情/历史，不是HTTP接口
    def preview(self, call_id, request): ...  # 只读，完整校验，同形状回执
    def reconcile(self, call_id, request): ...  # 原子追加事件和预算调整
```

`ReconciliationRequest`严格禁止多余字段：`event_key`、`expected_revision`、`component`（token/tool）、`amount_micro_usd`、`evidence_kind`（provider_statement/provider_support）、`evidence_reference`、`evidence_sha256`、`provider_object_id`、`operator`。文本不接受控制/格式字符，引用与操作者长度有界，摘要为64位小写十六进制，金额与修订号为严格整数。`preview/reconcile`回执固定含`call_id/revision/component/actual_micro_usd/reconciliation_status/accounted_before_micro_usd/accounted_after_micro_usd/delta_micro_usd/reserved_after_micro_usd`；重放返回原回执。

HTTP仍仅已有两个GET。API新增字段：

- BudgetView：`accounted_micro_usd`；原`estimated_micro_usd`始终取原内部估算，available按accounted+reserved计算。
- ProjectUsageView/TaskUsageView：`accounted_micro_usd`及`reconciliation={actual_micro_usd,reconciled_count,partial_count,pending_count}`；汇总覆盖全部调用，不只当前页，且不累加三级预算。
- PublicCall：`reconciliation={status,token_micro_usd,tool_micro_usd,tool_applicable,actual_micro_usd,reconciled_at}`，status为pending/partial/reconciled/not_applicable。无任何凭证时actual为NULL；released为not_applicable，真实零值仍显示金额。操作者、引用、摘要、供应商对象及凭证内容不进入公开响应。

前端新增字段为兼容可选；缺失时明确“实际核对数据暂不可用”，不能编造零费用；提供字段却无效时拒绝该响应。两面板显示原估算、预算已计金额、预留和可用额度；另显示实际已核对部分、分项状态与待核对数。不增加POST/编辑入口或技术字段。
