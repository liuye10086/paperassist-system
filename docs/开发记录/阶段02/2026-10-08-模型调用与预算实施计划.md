## 目标与范围

新增统一调用门面、调用/用量/价格快照、用户/项目/任务三级预算预留与结算，以及项目概览只读用量面板。用模拟供应商验证真实数据库事务和官方SDK请求，不调用真实模型。解释、绘图仍使用原入口和恢复机制，后续分别迁入；本步不提前宣称旧入口已受统一预算限制。

相比直接同时改写两个旧执行器，先交付独立门面可保持已验收业务，并验证预算与未知提交边界；相比只建表，本步同时交付可调用的服务、官方Responses文字适配器、管理命令和真实查询页面。Code Interpreter容器调用接入留给绘图迁移，必须在创建容器之前预留预算。

预算暂按累计额度、美元、管理员配置实现，无自动日/月重置；已向用户询问周期偏好，若有新反馈按反馈调整。不设置真实默认金额、不写入真实模型价格，不自动提高额度。测试价格和金额只存在独立测试schema。报价由受信后端策略传入并冻结，不由浏览器提交。

## 全局约束

- 保留Windows API/Vite/PostgreSQL与Linux Worker，复用现有依赖、短写事务和schema级写锁，不引入LangGraph、新服务或通用工作流框架。
- 金额用整数微美元，1 USD = 1,000,000微美元；输入字符串金额只接受有限非负定点数，最多6位小数，不用float记账。
- 供应商返回token数是实际用量；按价格快照计算的金额始终叫内部估算，不称真实账单。缺用量、缺支持的价格、返回模型不匹配或工具费用未知均保留待核对，不记为零。
- 新统一调用缺预算/价格时拒绝发送；未知提交不自动重发、释放预留或视作免费。预留只约束本地并发准入，不承诺远端账单绝对不超限；估算超过预留时完整记录并阻止后续准入。
- 研究正文、提示词全文、API密钥、服务器路径不进入公开模型记录；不改变现有脱敏/材料发送范围。配置由后端固定，材料不能扩展工具权限。
- 前端沿用白灰底、深紫主色，只显示用途、模型、时间、状态、预算及估算，不展示内部ID、哈希、请求/响应编号。
- 不写开发测试任务、不删除旧成果、不重发历史模型请求；无用户授权与提交信息不commit/push。手工验收前仅备份升级数据库，保留全部旧数据/资产。

新增四表，迁移 `0008_model_usage`；模型价格快照直接冻结于调用和用量事件，不建立价格管理平台。

| 表 | 字段与约束 |
| --- | --- |
| `model_budgets` | id、user_id、scope_type(user/project/task)、scope_key、project_id/task_id可空外键、limit_micro_usd、revision、created_at/updated_at；按scope_type/scope_key唯一，CHECK约束作用域对应的外键关系与非负整数金额 |
| `model_calls` | id、user_id/project_id/task_id外键、attempt_no、call_key、input_digest、provider/model、policy_snapshot、price_snapshot、status、provider_status、provider_request_id/provider_response_id、error_code、estimated_cost_micro_usd可空、usage_status、created_at/updated_at；task_id/call_key唯一，provider/response_id唯一，状态和金额约束 |
| `usage_events` | id、call_id外键、event_key、event_digest、event_type(observation/release)、provider_usage可空JSONB、price_snapshot、estimated_cost_micro_usd可空、usage_status、reason_code、created_at；call_id/event_key唯一，不修改旧事件 |
| `budget_reservations` | call_id/budget_id复合主键、reserved_micro_usd、accounted_micro_usd、status(held/settled/released)、updated_at；三层预留同事务创建/结算，汇总不重复计算同一调用的三个范围 |

预算配置、价格单价和预留最大值为 `1_000_000_000_000` 微美元；回执内部估算允许超过该值并完整保存，最高为BigInteger范围。数据库使用BigInteger、时间使用timestamptz。JSONB字段不以 `_json` 命名。普通索引，不为本步扩展partial-index审计框架。预算调整需期望revision，0表示首次建立，降低上限不抹去用量或预留。

`domain/model_usage/contracts.py` 定义严格Pydantic输入：

```python
class PriceSnapshot(BaseModel):
    version: str
    currency: Literal['USD'] = 'USD'
    model: str
    input_micro_usd_per_million: int
    cached_input_micro_usd_per_million: int
    output_micro_usd_per_million: int
    cache_write_micro_usd_per_million: int | None = None

class ModelPolicy(BaseModel):
    model: str
    prompt_version: str
    max_output_tokens: int
    timeout_seconds: int = 45
    tools: list[Literal['code_interpreter']] = []
    price: PriceSnapshot

class CallRequest(BaseModel):
    task_id: str
    expected_task_revision: int
    call_key: str
    input_digest: str
    policy: ModelPolicy
    input_token_allowance: int
    tool_reserve_micro_usd: int = 0
```

整数严格校验，键/版本长度有界，摘要为64位SHA256，策略/价格模型一致。预留值从输入token配额、最大输出、价格及明确工具预留算出并向上取整；允许用量超过配额的回执完整入账，不截断。工具调用即使token已知，工具消耗缺证据仍待核对。当前文字适配器禁止tools非空；保留工具用量分类能力供绘图迁移调用底层服务。

`ModelUsageService(user_id, config=None)` 为后端内部服务，接口返回字典：

```python
set_budget(scope_type, scope_key, limit_micro_usd, expected_revision) -> BudgetView
get_budget(scope_type, scope_key) -> BudgetView
reserve_call(request: CallRequest) -> InternalCall
begin_submission(call_id) -> bool  # 仅reserved原子转submitting为True
record_response(call_id, *, event_key, response_id, request_id, model,
                status, usage, tool_cost_micro_usd=None) -> InternalCall
mark_submission_unknown(call_id, *, error_code, request_id=None) -> InternalCall
release_unsubmitted(call_id, *, event_key, reason_code) -> InternalCall
get_call(call_id) -> InternalCall
project_usage(project_id, *, page=1, page_size=10) -> dict
task_usage(task_id, *, page=1, page_size=10) -> dict
```

InternalCall包含数据库字段，只有内部调用使用。reserve/begin必须核对启用用户、项目归属、Task运行状态、非Word类型及期望revision；已存在同key同摘要/策略/配额的调用先校验归属后复用，跨Attempt稳定，异输入409。begin重复或unknown不再次发送；开始提交后即使进程丢失，submitting也按结果未知处理，保留预留。已知response仅续取。预算查询不推进任务或外部调用。

回执先保存供应商状态及用量，再由后续业务执行器校验文字/JSON/PNG。终态completed/incomplete/failed/cancelled有可计价用量时均可结算估算。非终态不释放预留；缺字段/不支持计价/模型不符则保持held，已知部分估算可记录，占用至少为原预留与已知估算中的较大者。重复event key同摘要复用、异内容409；较旧非终态不得回退已保存终态。门面以不含request ID的回执摘要生成稳定event key，重复轮询不新增相同事件。不同显式event key可追加观察证据，但只更新累计估算、不叠加费用；不能跨key去重而遗漏新key绑定。仅reserved且未开始提交的调用可明确释放，任何网络错误不自动释放。

BudgetView：`scope_type, limit_micro_usd(nullable), revision, estimated_micro_usd, reserved_micro_usd, available_micro_usd(nullable), exceeded`。未配置revision为0、limit/available为null，不能当无限或0额度。

项目查询：`currency='USD', period='cumulative', enforcement_scope='unified_only', user_budget, project_budget, estimated_micro_usd, reserved_micro_usd, pending_count, items, total, page, page_size`。任务查询另含`task_budget`。Call公开项：`id, task_type, model, status, provider_status, usage_status, estimated_cost_micro_usd, created_at, updated_at`；不返回原始快照、摘要、内部错误或供应商标识。unknown金额为null，有明确证据的零token才可为0。

## 审查补充依据（2026-10-08）

现有本地OpenAI SDK 3.20.0与[官方Responses回执定义](https://developers.openai.com/api/reference/resources/responses/methods/retrieve)都列出缓存读取、缓存写入明细。[官方缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)按输入总量扣除这两类后计算普通输入；因此缺少影响计价的明细不能当作明确零值。这里仅核查字段和算法，不采纳真实价格，也没有发起模型请求。

独立审查另确认历史待核对回执以新事件键重放时，必须保留已结算状态。新键可追加证据，但不能将已结算调用改回held；不同内容继续拒绝冲突。
