# 实际用量核对使用说明

状态：2026-10-09已通过用户验收，验收服务已停止。实现范围见[第十步实施计划](2026-10-09-实际用量核对实施计划.md)；验证结果由本步交付记录统一记录。

本功能沿用已有本机运行配置，不需要新增配置项、模型密钥或 Admin API key。核对命令不自动抓取供应商账单，也不发起模型调用。真实项目没有可靠的逐笔供应商金额凭证时，保持“待核对”即可；不要填写示例金额，不要把 token 数量乘单价、内部估算或汇总账单分摊结果当成实际费用。

## 网页查看

项目和任务的用量面板只读展示内部估算、预算已计金额、预留、可用额度，以及实际核对金额和分项状态。未取得凭证的费用仍为未知，不能据此认定免费；有明确零费用凭证后才可录入零。

网页没有核对编辑或提交入口，也不展示内部调用标识、操作者、原件摘要或受限凭证引用。实际费用只能由本机管理员通过下面的命令录入。

## 取得调用标识并只读查看

在 PowerShell 中进入本项目 `backend` 目录。以下只读清单命令从已有本机数据库连接读取目标账号的最近 100 次调用，内部 `call_id` 仅在管理员终端中显示。它不创建预算、不修改数据，也不迁移数据库。

```powershell
Set-Location 'C:\Users\86182\Desktop\paperassist-system\backend'
$reconciliationEmail = Read-Host '输入项目所属账号邮箱'
@'
import json
import sys
from app.auth.service import normalize_email
from app.db.database import database_connection

try:
    email = normalize_email(sys.argv[1])
    with database_connection() as db:
        rows = db.execute('''
            SELECT c.id AS call_id, p.name AS project_name,
                   c.project_id, c.task_id, t.task_type, c.status
            FROM model_calls c
            JOIN users u ON u.id=c.user_id
            JOIN projects p ON p.id=c.project_id AND p.owner_id=u.id
            JOIN tasks t ON t.id=c.task_id AND t.user_id=u.id
            WHERE u.email=%s AND u.active
            ORDER BY c.created_at DESC,c.id DESC LIMIT 100
        ''', (email,)).fetchall()
    print(json.dumps([dict(row) for row in rows], ensure_ascii=False, indent=2))
except Exception:
    print('读取调用清单失败，请核对账号和已有本机运行连接。', file=sys.stderr)
    raise SystemExit(1)
'@ | & .\.venv\Scripts\python.exe - $reconciliationEmail
```

根据项目、任务和供应商凭证确认目标调用，复制它的 `call_id`，再执行：

```powershell
$reconciliationCallId = Read-Host '输入已确认目标调用的 call_id'
.\.venv\Scripts\python.exe -m app.manage_model_reconciliation show --user-email $reconciliationEmail --call-id $reconciliationCallId
```

`show` 只读返回调用状态、`provider_response_id`、`container_id`、当前 `reconciliation_revision`、分项核对金额和核对历史。历史中的操作者、受限引用和摘要属于本机管理信息，请按原件同样的权限保存。

仅 `completed` 或 `failed` 的调用可以核对。未知提交等未确认结束的调用继续待核对，金额凭证不能替代执行状态证据。token 凭证必须明确对应这里的 `provider_response_id`；tool 凭证必须对应这里的 `container_id`，且该调用确实使用 Code Interpreter。容器关联多个调用时不能自行分摊。

## 准备原件和记录文件

接受的材料仅限供应商明确对应该回复或该容器、包含对应费用的逐项材料，或明确支持回复。管理员须核验来源真实性、对象归属、币种和费用覆盖范围；程序不会自动认证供应商真实性。没有 response 的准备失败即使能证明工具费，也不能据此认定模型费为零。

保留收到的原件 bytes，不覆盖旧原件；另建 UTF-8 JSON 记录文件，和原件放在同一本机目录，原件也可位于其子目录。CLI 计算原件 SHA256 并保存摘要、受限引用、对象和操作者；原件正文和原路径不进入核对请求或数据库。摘要只能证明所读取文件的内容，不能证明文件来自供应商。

记录必须且只能包含下面八个字段，不允许重复字段或自行添加 `operator`、`currency`、`amount_micro_usd`、`evidence_sha256`。下面全部待填写内容都使用明显占位符，其中金额和修订号故意不符合录入合同，直接应用会被拒绝。只有取得真实逐对象凭证后才能填写。

```json
{
  "event_key": "__填写本次核对唯一事件键__",
  "expected_revision": "__替换为show返回的整数reconciliation_revision__",
  "component": "__替换为token或tool__",
  "amount_usd": "__填写原件证明的实际USD十进制金额__",
  "evidence_kind": "__替换为provider_statement或provider_support__",
  "evidence_reference": "__填写受限凭证引用__",
  "provider_object_id": "__填写原件对应且与show精确一致的供应商对象标识__",
  "evidence_file": "__填写保留原件的相对文件名__"
}
```

填写规则：

| 字段 | 要求 |
| --- | --- |
| `event_key` | 本次核对的稳定唯一事件键；修正时另用新键。 |
| `expected_revision` | `show` 返回的当前核对修订号，必须填写 JSON 整数，去掉占位符的引号。 |
| `component` | `token` 或 `tool`，每条记录只核对一个费用分项。 |
| `amount_usd` | 以美元 USD 为单位的字符串，普通非负十进制，最多六位小数；保留引号。不得填浮点 JSON 数字、指数、负数、NaN 或其他币种。零也需要明确凭证。 |
| `evidence_kind` | 供应商逐项材料填 `provider_statement`，明确支持回复填 `provider_support`。 |
| `evidence_reference` | 可追溯的受限引用，不填原件正文、密钥或绝对路径。 |
| `provider_object_id` | token 对应回复标识；tool 对应容器标识，均须与保存对象精确匹配。 |
| `evidence_file` | 记录目录内的相对普通文件名，不接受目录外路径、绝对路径、URL、UNC 或映射网络盘。 |

JSON 文件上限 1 MiB，原件上限 64 MiB，空原件拒绝。CLI 自动读取本机当前账号作为操作者，JSON 不能覆盖。程序将 USD 严格转换为整数微美元，回执中的所有 `*_micro_usd` 金额均为美元的百万分之一；金额使用存储上界校验，不以预算配置上限截断实际费用。

## 预览与应用

先确认记录、原件及对象，再输入记录文件路径。以下命令继续使用前面已经确认的账号和调用标识：

```powershell
$reconciliationRecordFile = Read-Host '输入已填好真实凭证的 UTF-8 JSON 记录文件路径'
.\.venv\Scripts\python.exe -m app.manage_model_reconciliation preview --user-email $reconciliationEmail --call-id $reconciliationCallId --record-file $reconciliationRecordFile
```

`preview` 做完整校验并输出拟生成的回执，不写核对数据。确认分项金额、核对状态、预算已计金额、差额和剩余预留后，再执行：

```powershell
.\.venv\Scripts\python.exe -m app.manage_model_reconciliation apply --user-email $reconciliationEmail --call-id $reconciliationCallId --record-file $reconciliationRecordFile
.\.venv\Scripts\python.exe -m app.manage_model_reconciliation show --user-email $reconciliationEmail --call-id $reconciliationCallId
```

`apply` 在事务中重新校验；预览成功不保证并发修改后应用仍成功。回执包含当前事件的修订号、已核对实际金额、核对状态、预算已计金额前后值、有符号差额和剩余预留。失败时只输出受控错误码或通用提示，不输出原件正文、原路径、连接和密钥。

只有 token 费用的业务取得 token 凭证后即可完整结算；绘图须 token 和 tool 两项均有凭证。仅有部分凭证时不会释放预留，若已知费用更高会提高保守占用。全部齐全后按实际合计记账并释放剩余预留，同时更新用户、项目和任务三级预算；原供应商用量、价格快照、内部估算和历史事件继续保留。

实际费用可能高于配置额度。系统保留有凭证的实际金额，使后续准入受预算约束，不把金额压低到额度，也不自动恢复或重新执行任务。本功能不处理收费、支付或退款。

## 重放与修正

相同调用和 `event_key`、相同完整内容重放会返回首次回执，不重复结算。完整内容包括原件摘要和自动操作者；请保留原记录与原件，并由相同本机账号重放。即使后来追加过修正，同键同内容仍返回该旧事件的首次回执。

同键下金额、对象、受限引用或原件 bytes 等内容改变会冲突。需要修正时，保留旧记录和原件，执行 `show` 取得当前修订号，另建记录文件并使用新的 `event_key` 和当前整数 `expected_revision`，再 `preview/apply`。修正追加新的历史事件并保存有符号差额，不覆盖或删除旧核对。

遇到修订冲突先重新 `show` 并核验新历史，不盲改修订号。没有足够凭证、对象不匹配、容器归属有歧义或调用尚未确认结束时，继续保留待核对状态。
