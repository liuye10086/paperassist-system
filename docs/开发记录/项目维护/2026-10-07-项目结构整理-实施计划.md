## 设计选择

后端采用现有技术方案中的 `api/domain/adapters` 方向，补充 `core/db/maintenance`，将混合文件中的路由和业务实现拆开；保留已经内聚的 `auth` 包。前端采用 `app/features/shared/test`，只移动文件并更新依赖，不引入架构库或重新设计状态管理。脚本将入口与实现分开。相比只增加一个包裹所有代码的目录，这样能按职责定位；相比重写业务架构，这次只调整必要边界，便于验证行为保持。

## 任务1：后端分层与测试归组

负责目录：`backend/`。

目标布局：

```text
app/
  main.py / manage_users.py / auth/
  api/           # projects、excel、analysis、descriptive、boxplot、explanations、reports、dependencies、upload_limit
  domain/        # analysis、descriptive、boxplot、explanations、reports、project_summary、explanation_content
  adapters/      # storage、explanation_store、report_store、excel、openai_plot、openai_explanation、report_docx
  core/          # config、errors、paths，确有必要时放共享异常
  db/            # database、schema
  maintenance/   # database_audit、legacy_import、migration_report、recovery_drill
tests/           # 按 api/auth/db/domain/adapters/maintenance/integration 等实际职责归组
```

具体边界与旧新映射见盘点 `script/.runtime/structure-backend-inventory.md`。路由进入 api，纯业务计算和任务轮询进入 domain，外部 SDK/存储/文件读写进入 adapters。保持 FastAPI operationId、DTO、返回格式与状态码。共享 Store/Settings HTTP 依赖进入 api/dependencies，禁止 domain 反向依赖 api。

配置路径集中明确定位 backend/project root；同步 Alembic env、backend/scripts、测试普通/动态导入、mock 查找位置及子进程 cwd。`recovery_drill` 的旧代码与当前代码必须分别解析真实模块位置，不能全局替换旧导入字符串。公共维护 CLI 改为 `app.db.database`、`app.maintenance.*`。

先运行导入/收集检查和必要的路径、恢复加载回归，再运行后端全量测试。测试不得弱化原有断言；不对开发数据库执行升级或恢复。
