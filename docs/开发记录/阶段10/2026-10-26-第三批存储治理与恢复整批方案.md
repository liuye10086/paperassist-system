## 2. 方案比较与推荐默认

| 方案 | 取舍 |
|---|---|
| **推荐：容量/配额可用闭环＋受控删除执行能力＋隔离恢复，原环境继续保留** | 解决第三批主线；删除执行只在本批新建、明确登记的可处置合成夹具中验证，原业务和旧样例不进入执行范围 |
| 只做存储盘点和删除预览 | 风险面与改动较小，但不能解决部分失败恢复、实际清理和独立恢复能力，主要复合项仍待后续 |
| 同时启用原环境自动到期删除、云存储及对外部署 | 缺少保留期限、供应商和发布条件，不推荐纳入本批 |

确认推荐方案意味着批准能力实现和**新建专用合成夹具**的破坏性测试，不批准删除任何已有业务、历史样例、备份或运行材料。原环境执行开关保持关闭；已有内测保留政策继续有效。

| 需要本批一起确定的参数 | 推荐默认及影响 |
|---|---|
| 配额适用范围 | 原有项目/账号默认仅观察、不追溯限额；新项目默认 1 GiB、每用户 5 GiB，可显式收紧。80% 提醒、100% 阻止新增占用，旧成果仍可查询下载；这是内测产品上限，不是性能容量结论 |
| 配额计量 | 已登记的实际持久对象按物理对象唯一计数；用户/项目逻辑归属与全局物理占用分列。预留在同一事务检查，部分失败按实际落盘核对；不能只按上传大小阻止上传而漏掉派生成果 |
| 磁盘保护 | 可用空间低于 `max(10 GiB, 所在卷容量的10%)` 时拒绝新增高占用操作并提示；不足阈值的机器保持只读/查看，不自动清理旧成果。实施时展示测量值和阈值，不能静默降级 |
| 并发 | 保持当前 Worker 并发 1，只读显示；本批不提高或声称可动态调节。BE14 的可调并发子项继续保留，随第四批容量实测确定 |
| 保留及删除 | 原环境 `retain_all`，无自动删除期限。用户可预览、登记请求和查看阻塞原因；执行能力在独立新合成范围启用，明确二次确认对象清单与摘要 |
| 临时文件 | 默认只盘点；清理只针对登记在本批独立临时根目录、已终态且超过24小时、无有效引用/租约/未知调用的对象。未知孤立对象进入人工核对，不因文件名/年龄直接删除 |
| 备份与恢复 | 手动一致备份和手动独立演练，不设自动过期；恢复目录/schema 必须全新，禁止覆盖原环境。记录实际耗时与校验，不承诺尚未批准的生产 RTO/RPO |
| 日志采集 | 专用 `lock_timeout=200ms`、`statement_timeout=1000ms`，连接建立有限期限（建议2秒）；在取得全局写锁**之前**设置，仅用于请求采集。超时放弃本次采集，不改业务响应、不循环重试 |

配额、磁盘保护已随推荐默认获得用户确认；现有上传10 MiB和数据规模上限仍遵循第二批配置/部署取较小值的规则。累计用量报表规模暂不做无目标重构或压测，第四批以明确场景和阈值评估。

- [ ] 在同一事务锁定删除状态，阻止该范围创建新任务/新增引用/发布新产物。在途任务、未收取回执、未知外部结果或预算待核对必须阻塞；本批不实现取消，不以停服务代替终止。

- [ ] 删除任务逐对象记录待处理/处理中/成功/保留/失败，支持相同幂等键恢复及部分失败重试；不能只隐藏项目列表。固定最小墓碑/审计记录供幂等和预算累计使用，研究正文与必要计费依据分开。无法安全分离的不可变历史材料明确保留，不暗中改写账本或快照。

定向验收：执行前新增引用使旧预览失效；跨项目共享文件不误删；在途/未知调用拒绝；部分IO失败后只重试未完成对象；Worker迟到发布被拒；原预算/幂等证据不丢；合法合成删除实际减少主存储文件，保留对象仍可下载且SHA一致。模拟错误只作用于隔离目录，不删除原材料。

## 5. 工作包 C：日志采集专用短超时

修改接点：`backend/app/core/request_id.py`、`backend/app/domain/admin_operations.py::record_request`、`backend/app/db/database.py::database_connection`及其定向测试。

当前写连接在yield前调用 `_write_lock`，因此在 `record_request` 的 `with` 内才设置超时已经太晚。采用显式、仅采集调用使用的连接选项，在事务开始、获取写锁之前设置事务级超时；保持所有业务事务原有锁和数值计算期限，禁止用全局环境值缩短所有业务写事务。

- [ ] 隔离PG持有同schema写锁，先复现采集等待超界，再补采集专用期限。
- [ ] 锁/语句超时回滚并归还连接，保留已发送的状态码、正文及request_id；不自动重试，不写递归日志。安全诊断只含固定code和request_id。
- [ ] 恢复连接后下一次采集正常；未采到的请求不补造成零失败，页面coverage准确说明可能缺采。
- [ ] 定向覆盖连接不可用、持锁、超时清理、释放后恢复、原响应保持、普通业务长写不受影响以及数值计算已有期限不被放宽。

验收阈值：本机隔离PG的锁等待实际在2秒内退出，观察SQLSTATE/事务释放并检查响应不变；1秒语句预算与2秒连接期限分别验证，不把数据库锁超时等同整个HTTP请求的统一期限。该专项不是系统并发容量结论。
