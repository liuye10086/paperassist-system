## 3 关键技术选择

### 3.1 项目和交付

新增 `project_type='research'`，表示使用新需求/交付模型的研究项目。不是新增第四类客户服务；交付类型仍只有 `analysis`、`sci_draft`、`thesis_draft`。

旧项目的 `project_type`、ID及历史任务不改变。迁移为每个旧项目建立一条对应的 SCI 或毕业论文登记，标为 `legacy_inferred`，表示由旧类型迁移，不表示客户新确认了需求。

新项目统一选择研究主题和所需服务，不要求先二选一论文。新 `research` 项目本批可以登记 SCI/毕业论文交付，实际生信到写作由第三批接入；前端和后端均明确这个状态。现有两类旧项目的实际写作功能继续按原合同运行。

### 3.2 生信文件与矩阵

新增通用文件类型 `bio_bundle`、`bio_component`，具体真实格式、压缩和成员角色由生信清单保存。新增只表示原件已取得的 `parse_status='stored'`，用于生信文件；旧 XLSX/DOCX/PDF/PNG/JPEG 类型及解析分支不变。

生信原件上传后显示“已保存，待生信导入”，不创建一个永远queued的旧解析任务，也不显示“已解析”。后续bio_import的候选、正式版本及H5核对状态从相应对象读取，不反向把同一原件的所有用途都改为parsed。

新增 `BioDatasetSourceV1`，不把它直接加入只有 Excel 消费者的 `AnyDatasetAnalysisSource`。本批只让导入、设计引用和数据集读取使用新来源，第二批开放计算消费者时再扩展对应合同。

MTX支持 `matrix coordinate integer general`。保留输入轴顺序，内部发布为观测×特征的 CSR，清单记录从原始特征×条码的转置；不做标准化或筛选。重复矩阵坐标本批明确拒绝，不静默累加；重复基因符号允许，稳定特征ID必须唯一。

### 3.3 需求和设计版本

采用不可变保存：每次显式保存生成新版本，父版本和请求摘要可追溯；确认也产生带确认信息的新版本。GET不回填、修复或新增行。

“待确认”“无”和“已知”使用明确状态，不将空白强制补成一个研究事实。保存草稿允许缺失联系方式、重复或比较信息；确认只对该对象必需条件检查，文件结构导入不因未知供体而停止。

### 3.4 统一任务与发布

新增任务类型 `bio_import`、工作流 `bio_import_v1`，复用既有 task、attempt、outbox、wait 和 checkpoint。

流程使用已有节点词汇：`check → await_confirmation → publish → done`。解析产物先成为候选，用户确认后发布数据集版本；数据集的“结构已核对”不代表“研究设计正确”或“可用于任意推断”。

### 5.1 共用规则

新增表使用TEXT稳定ID、JSONB内容、TIMESTAMPTZ时间和明确外键。所有项目内记录有 `project_id`；需要跨表绑定时使用 `(id,project_id)` 唯一键和组合外键，防止跨项目拼接身份。数据集版本另有 `(id,dataset_id,project_id)` 唯一键，根指针和父版本必须属于同一数据集。

根与版本的循环外键采用具名use_alter或等价的先建表后加约束方式；同一事务内先生成不可变版本，再更新根指针。存储对象是既有全局身份，其项目归属通过storage_references核对，不为其强加新的project_id语义。

不可变内容包括需求/设计版本、已发布数据集版本、成员和来源快照。业务根只更新当前指针、revision和更新时间。更新使用乐观锁：`UPDATE ... WHERE revision=%s`，失败返回409，不覆盖另一窗口。

JSONB至少有对象/数组类型、schema_version及大小约束；运行角色不可绕过不可变触发器修改历史。接口通过Pydantic严格拒绝未知字段、NaN和非法枚举。所有材料与对象引用使用真实外键，不仅存一串ID。

### 5.4 旧项目回填

```python
CR_NAMESPACE = UUID("b9f6f346-4bb9-4f75-9426-4875b4939853")

def legacy_delivery_id(project_id: str, project_type: str) -> str:
```

## 6 后端合同和接口

### 6.1 严格值与需求内容

共同值使用明确状态。以下合同在 `research_intake/contracts.py` 实现，前端保持同样字段语义：

```python
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, model_validator

class DeclaredText(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid", frozen=True)
    state: Literal["known", "pending", "not_applicable"]
    value: str | None = Field(default=None, max_length=4000)

    @model_validator(mode="after")
    def coherent(self):
        if self.state == "known" and not (self.value and self.value.strip()):
            raise ValueError("Known values need explicit text")
        if self.state != "known" and self.value is not None:
            raise ValueError("Pending and inapplicable values are null")
        return self
```

需求 `content_json`固定 schema_version=1，包含以下字段；每组由明确Pydantic模型表达，拒绝任意未声明扩展：

| 字段组 | 内容及限制 |
| --- | --- |
| contact | alias 200、email 320、phone 64、organization 500、discipline 500、filled_date；声明状态与实际值分开 |
| services | 一至三种交付类型，不重复；本批保存登记，不能据此开放未实现写作 |
| progress | protocol/raw_data/report/figures/manuscript/feedback的多选及10000字符说明 |
| scope_items | 最多100项稳定ID、标题、所属交付、planned/completed/pending_review/not_included和来源说明 |
| schedule | first_delivery/final_delivery的带时区时间及priority说明；明确不适用或待确认 |
| analysis_request | 数据类型、起点、预期分析、重点对象、比较和已有标准；最多100个对象及10000字符说明 |
| figure_request | 必须图、原图/重绘/混合策略、已有图片引用和规格声明 |
| sci_request | 期刊/候选、文章定位、篇幅、摘要、图表限制、主线、研究声明、文献及术语要求 |
| thesis_request | 学校、学院、专业、学位、模板、字数、时间、章节、纳入/排除工作及语言要求 |
| material_checklist | 六类材料provided/pending/none，实际引用通过material_refs保存；本地路径只作locator |
| notes | 最多10000字符；内容仅为研究资料，不作为系统命令或自动执行代码 |

草稿只强制schema、类型、范围和有效引用；确认强制至少一种服务、核心问题、优先内容及每项必需字段为known/pending/not_applicable之一。联系方式仍pending时可确认“需求待补”并明确缺口，不因此阻断包导入。

需求确认和“资料齐备”是两个状态：`confirmed=true`表示确认这份需求版本，`blocking_gaps`表示尚不具备某后续操作条件，不将二者混为一个绿色通过。

### 6.2 研究设计内容

设计版本保存：

- experiments：最多50套实验；ID、数据类型、物种/组织/模型、技术、参考、处理阶段及来源。
- groups：稳定ID、缩写、含义和所属实验；组名不可作为唯一跨实验身份。
- samples：最多10000条样本，包含样本ID、实验、组、供体/个体、组织/切片、批次、时间、剂量、性别、年龄及源文件/数据集引用。
- observation：统计单位、biological/technical重复定义、独立/配对/重复/时间/剂量结构；未明确值为pending。
- comparisons：最多100个比较；实验、比较组、参照组、正值含义、效应量阈值、原始/校正P及标准来源。
- exclusions：已有排除、缺失和异常说明；本批只登记，不修改矩阵。
- cross_dataset_links：同样本/同个体不同组织/独立实验/部分对应及实际对应表。
- declarations：设计确认人、版本、已知缺口和来源。确认设计不批准第二批分析算法。

本批样本表采用已上传XLSX现有解析结果或严格CSV/TSV模板映射到上述内容。只预览映射和冲突，用户显式保存后生成设计版本；重复样本ID、未知组和跨项目引用拒绝，未知供体或配对关系显示缺口，不自动猜测。

## 7 生信上传与隔离解析

### 7.1 专用额度

以下是本方案建议确认的上限，不是性能测量成绩。现有文档/Excel额度保持原值；生信额度可由部署进一步收紧，并在批次和任务创建时冻结。

| 配置 | 第一批建议值 | 说明 |
| --- | --- | --- |
| 单个上传原件 | 64 MiB | 可容纳当前31518720字节TAR |
| 单个上传批次 | 10项；前端同时上传1项 | 保留现有批次结构，不增加新并发控制框架 |
| 归档成员 | 256个普通文件 | 目录可跳过，不接受链接、设备和稀疏文件条目 |
| 单成员解压后 | 256 MiB | 按实际流读取计数，不只相信归档头 |
| 本次全部展开内容 | 512 MiB | 包含嵌套gzip及元数据，最多两层受控容器 |
| 特征 | 100000 | 当前58735；稳定ID唯一 |
| 观测 | 100000 | 当前1162；不将观测数当供体数 |
| 稀疏记录 | 10000000 | 当前5011775；拒绝超过限制的预分配 |
| 单图 | 16000000像素，展开字节另计 | 当前组织图3698000像素 |
| 解析子进程 | wall 180秒、CPU 120秒、内存1 GiB | 输出只返回小型索引，矩阵写受控目录 |
| 子进程结果JSON | 2 MiB | 不包含完整矩阵或全部空间/特征正文 |
| 需求或设计JSON | 每份2 MiB | 样本最多10000条，同时受JSON字节约束 |
| 矩阵预览 | 最多40特征×20观测 | 每次最多800个值 |

文件体的64 MiB与multipart头部额外64 KiB分别检查。专用中间件只匹配bio-upload-batches上传项；旧 `/files`、Excel preview和原file-batches仍执行原10 MiB合同。缺少Content-Length、分块上传和伪造profile也不能绕过计数。

`bioinformatics/settings.py`的严格配置至少实现下列已确定字段；实例默认值即本批建议值，部署覆盖只能收紧：

```python

class BioLimits(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid", frozen=True)
```

### 7.2 格式和角色

| 角色 | 接受的真实格式 | 第一批行为 |
| --- | --- | --- |
| archive | TAR、tar.gz/tgz | 有界列举，允许普通文件；不执行脚本 |
| geo_metadata | SOFT、GEO XML、series-matrix文本及其gzip/tgz包装 | 保存GSE/GSM、声明和配套文件；不从本地材料自动发网络请求 |
| package_listing | 本例filelist的TSV/TXT清单 | 作为目录线索，不将列出的URL视为已下载数据 |
| matrix | MatrixMarket coordinate integer general，可gzip | 维度、条目、索引和非负整数检查，形成CSR |
| features | 2或3列TSV，可gzip | 保留稳定ID、显示名和feature_type，未明确类型如实记录 |
| barcodes | 单列TSV，可gzip | 唯一且顺序明确，与矩阵列数一致 |
| positions | 旧无表头tissue_positions_list或新表头CSV | 固定字段映射，保留全部位置和in_tissue标志 |
| scalefactors | JSON | 只接受已声明数值字段及合理有限值 |
| tissue_image/qc_image | PNG/JPEG，可gzip | 检查实际解码尺寸和格式，图像不作OCR或科学解释 |
| alternate_matrix | HDF5 magic的H5，可gzip | 保存及标注internal_not_checked，不读取内部矩阵 |

本批执行范围为单一GSM/Visium配套数据。多样本包保存原件并提示需要拆分或后续支持，不能按文件名任意配对。其他组学表可以登记资料和用途，但不进入Visium解析器。

归档里的GSM前缀可以用于识别配套关系，原成员名和用户确认的角色始终保存；相同角色出现多份不一致内容时返回冲突，要求明确选择。相同内容的SOFT/TXT压缩副本记录等价表示，不增加实验或样本数。

### 7.3 解析顺序

1. 核对原件owner、size、SHA、profile和任务快照，解析前执行处置屏障。
2. 在仅属于本任务的受控目录中枚举成员；拒绝绝对路径、`..`、Windows盘符、链接、重复规范化路径及超限展开。
3. 读取元数据和成员角色，分离空series-matrix表与真正MTX；元数据文本不作为系统指令。
4. 读取features/barcodes并检查唯一稳定ID、重复显示符号、列数和行数。
5. 流式读取MTX头、全部条目、边界、整数范围和记录数；上限内构造稀疏对象，检查重复坐标。
6. 验证positions和scale、图片宽高；矩阵条码必须能在坐标中唯一找到。
7. 记录组织内覆盖关系，不自动删除组织外条码或补齐缺失条码；当前数据应显示1162个条码与组织内集合一致。
8. 生成稳定CSR数组、索引、配套原始内容和核对manifest；时间、临时路径等不进入确定性内容哈希。
9. 父进程复验输出位置、对象大小、SHA和schema，然后按统一存储治理登记候选。

坐标约定为 `x=pxl_col_in_fullres*image_scalef`、`y=pxl_row_in_fullres*image_scalef`，不交换行列、不自动翻转图片。仅在已知图片与缩放关系下进行边界检查，允许约定的1像素舍入容差；不满足关系时显示具体冲突而不是自动校正。

本批canonical矩阵使用三个不可执行的NPY数组，形状为观测×特征：`matrix_data.npy`、`matrix_indices.npy`、`matrix_indptr.npy`。counts使用int64、indices/indptr使用适用的固定整数dtype并记录在manifest，读取时禁用pickle。预览用只读mmap和CSR行索引，不能在HTTP请求里重新解压或稠密化完整矩阵。

### 7.4 Manifest与来源合同

发布manifest使用 `schema_version=1`、`parser_version='geo_visium_import_v1'`、`storage_format='csr_npy_v1'`。示例结构如下，数组对象通过对象ID绑定，值和哈希在实际执行时生成：

```json
{
  "schema_version": 1,
  "parser_version": "geo_visium_import_v1",
  "assay": "visium",
  "source_accessions": {"gse": "GSE262082", "gsm": "GSM8157269"},
  "input_shape": {"features": 58735, "observations": 1162},
  "matrix_orientation": "observations_by_features",
  "stored_entries": 5011775,
  "storage_format": "csr_npy_v1",
  "processing": {"normalized": false, "filtered_by_this_system": false},
  "verification": {
    "structure": "checked",
    "alternate_h5": "internal_not_checked",
    "study_design": "pending"
  }
}
```

实际完整manifest还包含：所有输入文件ID/哈希、原成员名、各产物稳定成员ID/哈希/大小、原轴与转置记录、稳定ID/符号索引、空间列定义、图像大小与缩放、组织内覆盖、warning、parse_settings摘要及原始声明。

稳定成员ID由import_id、role和原成员名确定性生成，数据库的bio_dataset_members再将它绑定到真实storage_objects.id。候选checkpoint保存这种绑定；manifest哈希不依赖临时路径、随机存储ID或时间。这样重试可以核对同一候选，不因重建数据库对象产生不同manifest。

`BioDatasetSourceV1`公开来源最少包含kind、schema_version、project_id、dataset_id、dataset_version_id、version、manifest_sha256、parser_version和source_file_ids。公开响应不包含object_key；内部对象读者根据真实FK及所有权取得路径。

### 8.2 冻结快照

任务快照包含kind=bio_import、workflow_version=bio_import_v1、project、import_id、dataset_id、expected_dataset_revision、逐个原件身份、角色选择、parser_version、完整额度、输出语言和配置摘要。

需求/设计版本可以作为上下文引用，但不作为MTX结构算法输入；用户后来修改联系人或需求文字不应使正确的格式解析失效。发布必须核对真正影响内容的文件、角色、parser/settings、候选SHA和dataset revision；研究设计不足继续作为独立缺口。

`TaskStore.insert_task/enqueue`和现有outbox在创建事务内使用；显式传入已经核对的source_file_ids，并扩展生命周期读取器，使处置屏障不会把新任务当作“来源未知”。

### 8.3 状态与检查点

| 节点 | 统一任务表现 | 必须落盘内容 |
| --- | --- | --- |
| 已登记上传 | 无解析任务或尚未创建导入 | 原件、item身份和profile |
| check | queued/running，phase=parse | 冻结快照、attempt和租约 |
| await_confirmation | waiting_confirmation | 候选manifest对象、核对摘要、checkpoint和wait身份 |
| publish | queued/running，phase=verify | 已确认候选、请求摘要、expected_dataset_revision |
| done | succeeded | 正式版本、成员、当前指针、result_bio_dataset_version_id和事件 |
| 失败 | failed及公开错误 | 保留原件、失败原因、实际资源或阶段和可用候选 |

候选文件必须纳入现有存储登记。不能为了等待确认，把一批未登记的矩阵文件留在盘上却显示容量为零。

### 8.4 原子发布和重试

1. 使用现有 `storage_governance.deterministic.admit_manifest`在写入前成套登记已知叶产物；operation key使用import/task/稳定成员身份。
2. 写叶产物并复验大小和SHA，使用现有settle机制；根据稳定成员ID生成并登记候选manifest。manifest登记失败时叶产物仍归属同任务并占计量，不发布业务版本，也不伪报全部完成。
3. 用户确认后，在租约保护和dataset行revision条件下插入新版本、成员和来源，更新当前指针及任务结果。
4. 重放同一确认返回同一版本；不同内容同键409；并发发布不产生两个同版本号。
5. 数据库回滚而文件已落盘时保留归属和unknown状态；先通过既有reconcile恢复，不能重复计量或新建不相关对象。
6. Worker中断可在源身份和检查点一致时通过现有显式重试恢复，不重复发布。源字节改变或候选损坏时拒绝，并保留失败证据。

上传原件继续复用 `storage.publication`；新派生物使用已有确定性manifest模式。若要扩展支持路径，严格按该模块既有journal和reservation语义实现，不另写一个直接绕过配额的save函数。

任务公开输入、列表、详情、事件、错误分类、重试判断、结果导航和来源审计必须一同接入。只让worker能执行而任务页无法读取，不算本批完成。

### 10.1 最小合成夹具

`backend/tests/helpers/bio_fixtures.py`生成三特征、两观测、一个组织外位置和8×8图像的小包；其中两个基因符号同名、稳定ID不同。gzip固定mtime，tar成员顺序固定。

核心输入如下：

```text
%%MatrixMarket matrix coordinate integer general
3 2 4
1 1 5
2 1 2
1 2 1
3 2 4
```

features为 `ENSG_TEST_1/G1`、`ENSG_TEST_2/SAME`、`ENSG_TEST_3/SAME`，barcodes为AA-1、BB-1。空间位置AA/BB在组织内，CC-1在组织外，缩放为1，坐标在8×8图像范围内。

测试辅助文件中的最小生成代码如下；三个开关分别产生路径越界、重复矩阵坐标和缺少条码对应的真实负例，不读取客户文件：

```python
import gzip
import io
import json
import tarfile
from PIL import Image

def visium_bundle_bytes(*, unsafe_name: str | None = None,
                        duplicate_coordinate: bool = False,
                        missing_barcode: bool = False) -> bytes:
    records = ["1 1 5", "2 1 2", "1 2 1", "3 2 4"]
    if duplicate_coordinate:
        records.append("1 1 7")
    matrix = ("%%MatrixMarket matrix coordinate integer general\n"
              f"3 2 {len(records)}\n" + "\n".join(records) + "\n").encode()
    pixels = io.BytesIO()
    Image.new("RGB", (8, 8), "white").save(pixels, format="PNG")
    parts = {
        "matrix.mtx": matrix,
        "features.tsv": ("ENSG_TEST_1\tG1\tGene Expression\n"
                         "ENSG_TEST_2\tSAME\tGene Expression\n"
                         "ENSG_TEST_3\tSAME\tGene Expression\n").encode(),
        "barcodes.tsv": b"AA-1\n" if missing_barcode else b"AA-1\nBB-1\n",
        "tissue_positions_list.csv": b"AA-1,1,0,0,2,2\nBB-1,1,1,1,4,4\nCC-1,0,2,2,6,6\n",
        "scalefactors_json.json": json.dumps({"tissue_hires_scalef": 1.0,
            "tissue_lowres_scalef": 1.0, "spot_diameter_fullres": 1.0,
            "fiducial_diameter_fullres": 1.0}, sort_keys=True).encode(),
        "tissue_hires_image.png": pixels.getvalue(),
        "tissue_lowres_image.png": pixels.getvalue(),
    }
    output = io.BytesIO()
    with tarfile.open(fileobj=output, mode="w") as archive:
        members = {"GSM9999999_" + name + ".gz": gzip.compress(value, mtime=0)
                   for name, value in parts.items()}
        if unsafe_name is not None:
            members[unsafe_name] = b"synthetic unsafe path"
        for name, value in sorted(members.items()):
            info = tarfile.TarInfo(name)
            info.size, info.mtime, info.uid, info.gid = len(value), 0, 0, 0
            archive.addfile(info, io.BytesIO(value))
    return output.getvalue()
```
