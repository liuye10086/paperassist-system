## 1. 本批完成后能做什么

用户从现有“分析与成果 → 数据分析 → 生信数据集”打开一个固定原始版本，补充或保留未知的样本对应关系，查看 QC 和过滤影响，确认配方，再由 Linux Worker 计算标准化、HVG、PCA、UMAP、Leiden 和 cluster marker。完成后可查看结果表、基因与聚类空间图、人工区域注释，下载处理对象、单图和对应方法/复现文件。

改过滤参数要产生新运行和新处理版本；改颜色、标题或选择其他基因只产生新图片版本；改人工区域或 cluster 标签产生新注释版本。三类改动不会覆盖已发表为正式版本的旧产物。

本批不以大模型生成坐标、聚类、P 值或图像。固定算法完成计算和出图，不需要真实/付费模型调用。将这些事实接入报告及 Results/Methods 写作属于 CR-B03，本批交付的方法记录和结果表不能留到第三批才生成。

## 2. 技术路线及计算环境

### 2.1 方案选择

| 路线 | 对现有系统的影响 | 本批选择 |
| --- | --- | --- |
| 将全部生信依赖装入后端全局环境 | 容易影响已锁定的 NumPy/pandas/OCR 等依赖，API 进程也会加载大型库 | 不采用 |
| 现有 Linux Worker 镜像增加独立环境 `/opt/paperassist-bio` | 沿用任务协议和存储，只增加受控子进程；现有 API/Worker 主环境保留 | **推荐采用** |
| 新建独立 HTTP 计算服务 | 多出服务鉴权、作业身份、网络失败和部署维护合同 | 当前单机规模没有必要；以后扩容另评估 |

新增 `backend/requirements-bio.in`、`backend/requirements-bio.lock.txt`，主工具选定固定候选基线 **Scanpy 1.11.5**，配套 AnnData、h5py、NumPy、SciPy、pandas、scikit-learn、umap-learn、Numba、igraph、Matplotlib 及全部传递依赖必须精确锁定到版本和 wheel 哈希。选择该固定 API 系列是为明确方法和随机种子合同，不追随运行时 latest。[维护者发布页](https://pypi.org/project/scanpy/1.11.5/)确认该发行版存在；**尚未证明本项目的完整依赖组合可用**。

P02 环境门禁负责在独立环境解析并生成完整 lock、安装后 `pip check`、运行真实小矩阵数值/绘图/隔离探针，保存镜像 digest、Python/包版本、BLAS/Numba/字体信息及 lock SHA。门禁失败就停止计算接入，不能修改既有全局依赖来绕过，也不能使用运行时在线安装补齐。若需变更 Scanpy 主版本或科学算法，先更新本方案说明变更。

### 2.2 隔离、容量和运行合同

新增受控 runner，复用现有 Landlock/seccomp 思路；可信库和所需 JIT 核心预热后，**读取任何客户输入前**完成隔离。子进程只读本任务授权的输入，只写本任务输出/临时目录；不获得数据库、消息队列或模型密钥，不访问网络、不运行用户代码、不启动子进程。HDF5 外部插件禁用。Windows 缺少同等隔离时明确阻断计算，不回退到无隔离运行。

| 项目 | 本批建议固定上限及处理 |
| --- | --- |
| 输入矩阵 | observations ≤20,000、features ≤100,000、nnz ≤10,000,000；保留 B01 结构限额，不自动扩大原件上传范围 |
| 稠密运算 | 仅 HVG 子矩阵可稠密化，最多 20,000,000 个值；原全特征矩阵始终稀疏。超过预算要求用户明确减少 HVG/拆分分析，不偷偷抽样或降精度 |
| 运行并发 | 现有业务并发 1；第二批计算并发也为 1，不抢占其他会话栈 |
| CPU/时间 | 数值线程 1，固定 OMP/BLAS/Numba 线程；正式计算 wall 1,200 秒、CPU 900 秒；可信预热另限 180 秒，均记录实际耗用 |
| 内存 | 第二批专属 Worker 容器上限 4GiB；父进程监测计算子进程 RSS 上限 2GiB，并设置可经探针验证的地址空间限制。用户在实施中另行确认：启动前按 Docker Linux 可用内存≥4GiB 核对并监测峰值，替代原 Windows 主机可用内存≥6GiB 的规划门槛；环境不足即阻断，不修改所有历史栈的配置 |
| 输出 | 最多 256 个叶对象，单个≤256MiB、整次≤512MiB，结构化进程回包≤2MiB；完整大表/数组走对象成员，不塞进 checkpoint JSON |
| marker 预算 | cluster≤50、cluster×受检基因≤1,000,000；超限在检验前报告资源阻断，需明确调整新配方，不仅输出前一百万行冒充全量 |
| HTTP 读预览 | 结果表默认 50 行/页、最大 100；矩阵 40×20；空间/降维坐标最多 20,000 点且 JSON≤2MiB；超限应分页/拒绝，不能悄悄漏点 |
| 绘图 | 单图最长边≤4,096 像素、≤16M 像素；默认 300dpi，PNG 预览与 PDF 单图导出；基因面板≤16、marker dotplot/heatmap≤100 基因 |
| 数字/文字 | 禁止非有限 JSON 数字；NA 用 null+reason；标题≤200 字，基因以稳定 ID 请求；没有任意表达式、Python/R 代码、路径或 URL 参数 |
| 配额 | 继续使用已有项目/用户 storage governance，检查当前 observe/enforced 状态及实际额度；显示本次预估与可用量，写前整套 admit，发布时 settle；不自动删历史对象腾空间 |

固定资源是初始工程合同，真实 GSE 的时间/内存结果尚未测得。若上述预算不足，保留失败证据和原件，明确列出调整建议，不能宣称已通过。

## 3. 来源、H5 与处理数据合同

### 3.1 原始来源与映射

继续使用 `BioDatasetSourceV1` 指向已发布 raw 版本及 manifest SHA，不能读取随时变化的 current_version 代替用户选定版本，也不能转成旧 Excel 工作表来源。

新增 `BioObservationMapV1`：对固定 raw 版本的 barcode 对应 sample_id、section、donor、batch、group，以及各字段的 known/pending/not_applicable 状态。barcode 必须真实存在且唯一，缺少条码明确列为 unmapped；输入可为编辑表或有列映射的 CSV/TSV/XLSX，复用既有有界表格读取，最多 20,000 条。完全未知的映射也可保存并做探索分析。

实验设计引用固定 `research_design_versions.id`。其中 sample_id 当前存在于设计 JSON，因此数据库对设计版本做真实 scoped FK，应用层在该冻结 JSON 中验证 sample_id；不能伪称有一个不存在的 samples 表外键。四个组织片段不自动生成四个供体，GSM/GSE 不直接充当独立重复。

### 3.2 H5 读取与等价核对

扩展 `bio_import`，新增 `bio_import_v2`，保持 `bio_import_v1` 已有任务可回读/恢复。v2 请求增加明确的 `matrix_representation=mtx|10x_h5` 与 `compare_alternate`；仍使用现有原件、候选和显式确认流程，不修改 v1 的不可变输入。

支持范围固定为 10x v3 `/matrix`：data、indices、indptr、shape、barcodes、features/id、name、feature_type。按 CSC features×barcodes 读入，转成本系统 observations×features CSR；检查整数非负有限 counts、轴唯一、指针范围、索引范围、声明大小和实际维度。[10x 官方格式说明](https://www.10xgenomics.com/support/software/cell-ranger/latest/analysis/outputs/cr-outputs-h5-matrices)作为格式依据。

读取前检查 HDF5 对象数量、shape、dtype、字符串长度、逻辑分配和解压预算。拒绝 soft/external link、virtual dataset、外部 storage 及未知过滤器；按有界切片读取，不先将整个数据集展开再做限额检查。[h5py 文档](https://docs.h5py.org/en/stable/high/dataset.html)说明可在读取前获得 shape/dtype/nbytes，并支持切片读取。

同时有 MTX/H5 时：

1. 核对来源 GSM、feature 稳定 ID/type 与 barcode 集合；重复符号不参与合并。
2. 同顺序直接比较；仅顺序不同则记录明确的轴置换，再比较全部规范化 CSR counts。合并结构性重复坐标、移除显式零时保留处理记录，counts 总量必须相同。
3. 输出 `identical`、`order_reindexed_equal`、`mismatch`、`not_comparable`，保留输入/规范化轴/数值摘要和比较器版本，不能仅凭维度相同判等。
4. 确认后发布到**同一 bio_datasets 根的新版本**；H5 与 MTX 不增加样本数，不把同一表示重复建立成独立生物学数据集。
5. 第一批旧版本继续显示 `internal_not_checked`；新版本保存新 attestation。mismatch 不发布“已等价”版本；原有效 MTX 仍可单独分析，但明确 H5 尚未与之证实一致，不能静默改选数据。

H5-only 在同时有合格坐标/缩放/组织图时可建立可分析版本；缺少配套信息时列出缺口。任意其他 HDF5、Seurat、未知 H5AD 不按 10x 强行解释。

### 3.3 处理版本与产物

新增严格的 `BioProcessedDatasetSourceV1`，核心字段为 kind=`bio_processed_dataset_version`、schema_version、project_id、processed_dataset_version_id、analysis_run_id、raw_source、recipe_version_id、manifest_sha256、engine_version、environment_digest。它属于生信来源族，不能扩大旧 `AnyDatasetAnalysisSource` 的 Excel 语义。

处理 manifest 至少保存：

- raw 来源及所有实际读取成员哈希、映射/设计/配方版本、代码包与环境 digest、随机种子、资源、开始结束时间和执行步骤状态。
- raw 顺序的 obs/feature 索引，保留/排除 mask、逐条原因；处理轴到 raw 轴的一对一映射。
- raw QC、过滤后 QC、filtered counts、normalized、log1p、HVG 和 PCA、图邻接、UMAP、cluster；精确 layer 定义、dtype、shape、nnz 和哈希。
- marker 全部受检表和 Top 表、cluster 汇总、批次/切片分层描述、不可计算原因、默认图、方法及复现文件。

规范数组/TSV 是可独立核对的成员，同时输出标准 H5AD：`X=log1p`、`layers['counts']=过滤后原整数子矩阵`、`layers['normalized']=归一化子矩阵`，obs/var 保留稳定轴和 raw index，obsm 保存 PCA/UMAP/spatial，obsp 保存邻接，uns 保存来源及参数。原始完整 counts 仍引用 raw 版本；不谎称 H5AD 的过滤后 counts 是完整未过滤原矩阵。

H5AD 由本系统生成后在隔离环境回读核验各层、轴、稀疏数值和 manifest 身份；该能力是本系统契约的回读验真，不能当作通用外部分析对象导入。

## 4. 明确的科学配方

配方版本命名 `visium_explore_v1`，下表为**建议默认值**，不是客户实验事实，也不是适用于所有研究的阈值。用户必须在 QC 候选页确认 configured/effective 参数后执行。算法、层、特征集合和校正范围不得依赖库的隐式默认值。

| 步骤 | 输入、固定方法和默认参数 | 结果与异常语义 |
| --- | --- | --- |
| raw QC | 全 raw 整数矩阵；每 spot total counts、detected genes、零比例、in_tissue；每 gene nonzero spots/总 counts；按有效映射分层 | 不把稀疏零当 NA。若物种/线粒体规则未确认，mt fraction=null+reason，不显示 0%；可选择明确的 feature ID 集合或确认的前缀规则并保存来源 |
| 过滤 | 默认 in_tissue_only=false，spot min_counts=1、min_genes=1，gene min_spots=3；不默认按 mt 比例或高 counts 删除；仅指定 Gene Expression 类型参与此配方 | 顺序固定为表达类型→spot 阈值→gene 阈值→移除因此归零的 spot；不递归多轮过滤。过滤前后及每步数量可对账，原因可重叠并另给排除并集 |
| 质量提示 | 小提琴/直方/散点显示极端值候选；有 section/batch 时分层对照；可记录明确 raw barcode 排除列表 | 异常提示不自动删除。供体/重复信息不足时，“重复一致性不可评估”；不自动做 batch correction 或双细胞过滤 |
| normalize/log | 对过滤后保留 Gene Expression 基因总 counts 做 normalize_total target_sum=10,000；自然对数 log1p；稀疏 float32 输出 | 记录归一化分母、尺度和层；零分母 spot 已显式排除。counts 不覆盖，不对输入已经标准化的未知层再假定 raw |
| HVG | log1p 层、flavor=seurat、n_top=min(2,000,可用基因数)、n_bins=20；并列按稳定 feature ID 作确定性裁定 | 保存均值、离散度、排序及 chosen mask；常量或不足的基因列出原因，不自动切换 seurat_v3/raw-count 模型 |
| scale/PCA | 仅 HVG，均值中心化、样本标准差缩放、clip=10；排除零方差；PCA arpack，n_comps=min(30,n_obs-1,n_hvg-1)，seed=0，输出 float32 | QC 候选显示计划维度及数据依赖的裁定规则，结果记录实际有效数/原因；有效 n_obs<5、HVG<3 或 PCA<2 阻断完整配方，不以另一种降维替代 |
| 邻接 | PCA 指定的全部有效 PCs；n_neighbors=min(15,n_obs-1)、metric=euclidean、method=umap、transformer=sklearn、seed=0 | 保存 distances/connectivities 和 barcode 顺序；不利用空间邻近冒充转录相似性 |
| UMAP | 上述邻接；2 维、min_dist=0.5、spread=1.0、n_epochs=500、seed=0、单线程 | 记录实际参数；失败不能拿 PCA 的两列伪装为 UMAP |
| Leiden | flavor=igraph、directed=false、use_weights=true、n_iterations=2、resolution=0.5、seed=0 | cluster 按其最小 raw barcode index 规范编号；编号不是细胞类型，分辨率改变要新配方/运行 |
| marker | log1p 未缩放层、所有过滤后受检表达基因；每 cluster 对 rest，Wilcoxon、tie_correct=true、BH 在该 cluster 的全部受检基因内校正 | 保留 score、原始 P、q、group/rest spot 数、检测比例；效应量另明确计算为 log2((mean normalized group+1e-9)/(mean normalized rest+1e-9))，不误称库的近似 logfoldchanges 是同一指标 |
| 方法及打包 | 只从实际 executed steps、参数和产物生成事实说明，不调用模型扩写 | 每步 completed/not_computable/not_requested+reason；意外计算错误为任务失败，不伪装成合法 NA |

HVG 的 log 输入要求见 [Scanpy HVG](https://scanpy.readthedocs.io/en/stable/generated/scanpy.pp.highly_variable_genes.html)；PCA 显式 solver 和 seed 对照 [1.11 系列 PCA](https://scanpy.readthedocs.io/en/1.11.x/generated/scanpy.pp.pca.html)；Leiden 的实现/随机状态对照 [1.11 系列 Leiden](https://scanpy.readthedocs.io/en/1.11.x/generated/scanpy.tl.leiden.html)。正式实现须以选定 1.11.5 的实际 API 探针复核全部参数，而非套用最新版本签名。

marker 只描述同一次聚类内的 **spot 层探索信号**。同数据聚类再找 marker、空间依赖、同供体相关性均限制 P 值的生物学解释，不能当作疾病/孕周/供体组间差异。Scanpy [rank_genes_groups 说明](https://scanpy.readthedocs.io/en/latest/api/generated/scanpy.tl.rank_genes_groups.html)提示细胞层比较的独立性问题；本批据此设置门禁，供体层比较留 B04。

只有一个 cluster、某侧 spots<3、全常量或数学检验不成立时，marker 状态明确为 not_computable 并列原因，不用 P=1、P=0 或空“成功表”掩盖。该已定义退化结果可随有效处理版本发布，但页面不得声称“所有步骤均可计算”；默认 marker 图显示缺口说明。未定义的异常、超时、OOM、输入损坏、隔离失败或必要文件缺失一律不发布正式处理版本。

### 7.3 任务、确认、失败与原子发布

分析：`queued → running(check/raw QC) → waiting_confirmation → queued → running(compute/verify) → publish → succeeded`。这里括号内是工作含义；DB status/phase/checkpoint 的取值按现有合同，不直接写入描述性字符串。

1. 启动时固定原始来源/成员哈希、配方、映射/设计、engine/环境和资源合同；父进程校验后将规范输入交受控子进程。
2. raw QC、过滤 mask、有效维度、预计图表和缺口形成候选及 digest。存储准入后保留候选；创建 `bio_analysis_confirmation`，结束 attempt/lease，等待用户时不占 Worker。
3. 候选确认有效期建议 24 小时；过期确认明确拒绝，按既有 wait 失效收尾策略记录原因并保留材料。更改配方必须新建版本/运行，不能用新参数确认旧候选。
4. 确认后重查来源/hash/wait/revision，执行固定步骤。全体输出先在任务临时目录完成、校验，再整套 storage admit，逐一不可覆盖写入；重复叶对象也计入该次 manifest 身份。
5. 父进程验证 shape/dtype/finite、axes、mask 数量、数值层、坐标映射、实际输出文件及 SHA，不能只相信子进程的 success=true。
6. 一次事务 settle 对象、写处理版本及全部 artifact/默认 figure 版本与成员、更新 run/task 结果指针、checkpoint done。事务失败不出现正式半成品；已经写出的预留对象保留给原身份恢复和审计。
7. 按需 `bio_figure` 复用这套准入/校验/发布，仅写图片版本及成员，不写新的处理数据或 cluster。默认图 task_id 属于分析任务，图配置仍独立冻结。

重试使用现有 recoverable/fatal 分类、attempt fencing 和租约；失去租约的老 Worker 不能发布。写中断只允许按原 key/hash/size 显式 rebuild；来源损坏/原版本消失、配方不符或不兼容环境不能自动换来源继续。未来换镜像重跑应是新运行，除非满足原冻结环境/代码身份。

明确错误至少覆盖：environment_unavailable、isolation_unavailable、h5_unsupported、h5_matrix_mismatch、bio_input_integrity_changed、bio_recipe_invalid、bio_confirmation_stale、bio_insufficient_observations、bio_resource_exceeded、bio_output_invalid、storage_admission_failed。最终错误码命名遵循现有 errors 合同，原件和历史版本保持，不展示堆栈/私有路径。

### 10.1 可复现标准

固定 seed 还不够，UMAP 单线程与版本/环境共同冻结；其并行与随机行为见 [UMAP 官方复现说明](https://umap-learn.readthedocs.io/en/latest/reproducibility.html)。

- 相同镜像、代码、CPU 架构、线程和输入时：整数数组/axes/masks/cluster 规范编号及比较结果完全一致；表按稳定键排序，除运行 ID/时间字段外内容一致。
- float32 normalized/log1p、PCA 和 UMAP 数组拟定 `rtol=1e-5, atol=1e-6`；PCA 比较先按每个主成分绝对载荷最大的稳定 ID 统一符号。marker P/q/effect 使用 float64，拟定 `rtol=1e-8, atol=1e-12`，并核对 NA mask 和受检集合。
- PNG/PDF 排除运行时间/随机 document ID 等非绘图 metadata 后，固定环境要求规范字节哈希一致；H5AD 不强求容器压缩字节相同，比较规范层/轴/属性及稀疏数值。
- 算法/硬件平台改变不保证坐标逐位一致；本批全新环境复现使用同一固定镜像平台。超容差要报告数值/图影响，不能事后放宽标准凑通过或只看“图大致一样”。
