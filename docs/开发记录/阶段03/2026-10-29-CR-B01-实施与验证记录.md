## 2. 数据库、任务与存储

新增表：`research_intakes`、`research_deliveries`、`research_requirement_versions`、`research_design_versions`、`research_material_refs`、`bio_datasets`、`bio_imports`、`bio_import_files`、`bio_dataset_versions`、`bio_dataset_members`。

旧项目仅回填 `legacy_inferred` 交付及 intake 根，不虚构需求/设计版本，不自动认领 owner 为空的历史项目。新 research 创建、根及交付在一个事务中写入；同键回放先核对摘要。

需求与设计分别保存不可变版本，共享根 revision CAS；真实材料均通过同项目 FK。unknown/pending/not_applicable、确认状态和 blocking_gaps分开表达。只读 `design-table-previews` POST 不写业务状态，是本批幂等键要求的明确例外；上传 item 自身为稳定身份。

文件增加 `bio_bundle`/`bio_component` 与 `stored`；原文档 profile 和 10MiB 限额保留。新增任务 `bio_import`，工作流 `bio_import_v1`，复用 `check → await_confirmation → publish → done`，等待时结束租约。公开结果通过 `result_bio_dataset_version_id` 和 `BioDatasetSourceV1` 关联版本。

所有候选叶对象、manifest 与候选 JSON 使用既有 storage governance 的整套 admit、不可覆盖写入、settle。失败保留原件与已预留对象；明确重试只恢复原 key/hash/size。发布重查原件、候选、wait/checkpoint、用户决定和 dataset revision，版本、成员、结果指针及 done 在一个事务内提交。

同名等价元数据允许保持独立来源：成员唯一键为 `(dataset_version_id, source_file_id, role, source_member_name)`，避免不同原件的等价表示在确认后冲突。derived NPY/索引下载使用实际扩展名；解压成员去掉 `.gz`，原始成员名另存为来源信息。
