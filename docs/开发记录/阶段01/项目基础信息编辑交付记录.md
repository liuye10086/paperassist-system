## 2. 接口与资料保留规则

`PATCH /api/v1/projects/{project_id}` 接收非空JSON对象：

```json
{"name": "新的项目名称", "research_topic": "新的研究主题"}
```

两个字段可只提交一个。成功返回200及现有Project结构；未提交字段、ID、owner、类型、创建时间、文件数和资料关联不变。名称去首尾空白后1–120字符，主题1–500字符，仅接受字符串。同值提交不更新时间，实际变更后的更新时间不倒退。

| 情况 | 结果 |
| --- | --- |
| 提交 `project_type`，包括提交原类型 | 422，`project_type_immutable` |
| 空对象、null、空白/超长/非字符串字段，或提交其他不可改字段 | 422，`project_update_invalid` |
| 合法更新请求指向不存在或他人的项目 | 404，`project_not_found`；管理员也不能绕过 |
| 未登录或缺少有效CSRF | 沿用401/403认证保护 |
| 数据库写入失败 | 事务回滚，503及安全错误摘要 |

类型锁定与字段白名单同时应用于HTTP和 `ProjectStore.update_project` 持久化入口，不是只隐藏网页控件；不限制持有数据库DDL凭据的人工SQL操作。同一项目多标签编辑采用最后成功提交覆盖的简单规则，页面只提交本次改变的字段，尚无协作编辑冲突合并。

历史统计、图表、解释和Word报告的来源快照与文件字节保持不变。修改项目资料不会自动重生成旧报告；同一成果重复导出继续返回原报告。尚未生成的报告使用首次导出时的项目资料。
