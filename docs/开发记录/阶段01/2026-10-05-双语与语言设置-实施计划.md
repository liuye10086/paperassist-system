> **For agentic workers:** 使用 `subagent-driven-development` 按任务实施，先写失败用例，再实现与审查。用户最初确认开始阶段01第5项，要求开发完成后等待验收。2026-10-05用户已反馈验收通过，并授权更新文档后按指定信息提交推送；此授权不包含开始下一步。

**Goal:** 完成 S01-DB24、BE20、BE23、FE13、FE14、QA14 的开发与验证。

**Architecture:** 使用受支持的 `zh-CN` / `en` 标识，用户 `ui_language` 与项目 `default_output_language` 独立持久化。前端共享词典及响应式语言状态，在渲染时翻译文案和错误，不修改用户资料、统计值或历史成果。保留现有 HTTP 状态和错误码，追加可翻译参数，未知服务异常使用安全通用提示。

**Tech Stack:** PostgreSQL、Alembic、SQLAlchemy Core、FastAPI、React、TypeScript、pytest、Vitest。

## 全局约束与设计选择

- 沿用当前 `feat/auth-project-isolation` 分支与用户验收目录；工作区起点干净，HEAD 为 `6d22d1f`。
- 两种可行方案：引入完整 i18n 库，或使用现有 React 的共享词典。当前仅两种语言、无复数规则需求，选择后者，避免引入额外依赖；不做 DOM 文本替换或自动机器翻译。
- 用户语言只影响界面；项目默认语言是后续生成任务的默认选择。当前阶段不扩展生成引擎或重新生成报告，不回写历史任务、报告、图表及统计快照。
- 旧账号、旧项目及未显式指定的新项目默认 `zh-CN`；非法语言在 API 和数据库层拒绝。
- 登录与 `/auth/me` 返回用户语言；偏好接口只修改当前有效会话的用户，保持 CSRF、来源、停用与会话检查。保存语言不调用 `setApiSession`，不使项目请求失效。
- 切换用户/登出清理原用户偏好和工作区；匿名界面切换仅保存在内存。迟到响应、超时及卸载不能污染后续账号。
- 现有项目基础信息 PATCH 保持名称/主题契约，新增独立项目语言接口；任何读写都执行项目归属检查。
- HTTP 错误采用 `{detail: {code, message, params}}`，保留 message 兼容旧客户端；前端只使用已知 code 和安全参数，未知错误显示本地兜底，不回显服务端异常/秘密。
- 测试只用 `paperassist_system_test` 与每例 `pa_test_<uuid32>`，合成资料和临时资产；关闭 worker 和真实 API key，不调用云端。
- 开发库升级须先完成隔离验证、备份和原数据/资产核对；迁移仅追加语言列及约束。任何无法验证的部分明确记录。
- 不捆绑第6项运维分权或公开注册/邮件；仅按用户明确授权提交、推送。
