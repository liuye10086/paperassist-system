## 本轮实现

- runtime/migration 配置和连接入口分离。迁移秘密单独从 `backend/.env.migrations` 加载，缺失即失败，不回退运行URL；校验相同环境、主机/端口、数据库、schema及不同用户名。
- Alembic在DDL前核验真实数据库、当前用户和会话用户，选择schema并输出脱敏目标摘要。外部已有事务保留回滚控制，外部裸连接显式提交；offline仍禁止。SQLite导入走迁移账号，保留identity `RESTART`的事务回滚语义。
- 每次迁移末按metadata白名单授权业务DML及sequence USAGE/SELECT，版本表只读。`check`核查真实运行角色属性、成员关系、owner/CREATE/TEMP、表及序列权限。
- `0005_ownership_indexes`新增四个索引：项目 `(owner_id, updated_at DESC, id ASC)`，以及解释、解释任务、报告各自的 `analysis_run_id`。原列类型、数据与旧索引保持不变。
- `python -m app.database_audit`只读核对列、PK/FK/UNIQUE/CHECK、约束validated状态、索引有效性及排序、版本、JSON/时间格式、成果来源链。只输出位置和计数；SQL归一化保留字符串字面值，JSON拒绝NaN/Infinity/浮点溢出。
- 测试fixture、故障注入、版本表修改和升降级使用迁移账号，普通业务DML保持运行账号；每例继续使用独立测试schema。
- `script/setup-database-roles.cmd`由用户在本机输入管理员凭据创建角色；先备份配置、保存pending凭据，检查权限后替换运行配置。失败提示阶段和安全SQLSTATE，不输出密码、连接串或原始异常。
