## 实现与接口

- 新增Alembic `0003_password_security`，仅增加 `session_revocations`、`password_recovery_codes`、`auth_password_attempts` 及索引；原有业务表和账号/会话表结构不变。metadata与迁移镜像一致。
- `auth/revocations.py` 统一在调用方写事务中删除会话并保存摘要、用户、原因、时间、来源。仅实际删除的会话形成审计，重复撤销不重复记账。审计失败会回滚密码变更、恢复码消费及会话删除。
- 覆盖 `logout/absolute_expired/idle_expired/account_disabled/account_enabled/admin_password_reset/password_changed/password_recovered`；来源为 `web/cli/session`。审计不保存原会话令牌、CSRF或密码。
- `auth/passwords.py` 负责签发与消费恢复码、自行改密、独立限流。沿用数据库写事务锁，事务内重新核验会话、CSRF、账号状态和期限；并发消费同一码仅一次成功。
- 恢复码由32字节密码学随机数生成，数据库只保存SHA256摘要；15分钟到期、单次有效，分别保留 `used_at/revoked_at`。重新签发、改密、本机重置及停用/启用账号使待用恢复码失效。签发本身不撤销现有会话。
- 15分钟内敏感操作最多每账号/恢复码5次失败、每直接IP30次失败，失败计数提交后才返回错误，429带 `Retry-After: 900`。通过身份与限流检查后才计算新密码摘要。

| 接口 | 请求及结果 |
| --- | --- |
| `POST /api/v1/auth/change-password` | JSON `current_password/new_password`；已登录、CSRF及可信来源；成功204清Cookie，错误旧密码400/`invalid_current_password` |
| `POST /api/v1/auth/reset-password` | JSON `recovery_code/new_password`；匿名可用但仍检查web安全标头及来源；成功204清Cookie，过期/重复/撤销/无效/停用账号统一400/`invalid_recovery_code` |
| 两个密码接口 | 12–128字符；格式错误422/`invalid_request`，限流429/`password_rate_limited`，不回显输入秘密；成功均撤销该用户全部旧会话，不自动登录 |

前端新增 `PasswordForm.tsx`：登录后“修改密码”、登录页“忘记密码”，包含有标签的密码及确认字段、错误提示、防重提交、取消和15秒超时。凭据仅留在内存；成功清空API会话、工作区与hash，广播跨标签会话变化并要求重新登录。两个密码接口纳入迟到Cookie响应重同步。长度按Unicode码点校验；登录框同时修复UTF-16截断，支持128个emoji密码。

## 管理员与用户操作

1. 已知当前密码：登录后点击“修改密码”，输入当前密码、新密码及确认值，成功后重新登录。
2. 忘记密码：管理员先通过已建立的联系渠道线下核验账号持有人身份；系统不替代这一步人工判断。
3. 管理员在 `backend` 目录的交互式终端运行 `.\.venv\Scripts\python.exe -m app.manage_users issue-recovery --email user@example.local`，替换为真实目标邮箱，确认已核验后输入 `YES`。
4. 恢复码仅在终端显示一次，拒绝非TTY与重定向；通过已核验渠道交给账号本人。本人在“忘记密码”页输入恢复码并设置新密码，成功后重新登录。

既有本机 `reset-password` 保留。不开公开注册、邮件、管理员网页；不读取或修改真实管理员密码，不在聊天中收集新密码。完整命令见[仓库README](../../../README.md#修改密码与密码恢复)。
