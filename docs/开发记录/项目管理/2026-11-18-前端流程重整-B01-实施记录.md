## 二、文字扫描测试

- `findTechnicalText(root, { rawValues, systemIds, allowValues, exclude })` 返回 `{ kind, value, where }` 列表。扫描范围：每个元素自身的文字（相邻文本节点先拼接再匹配，因为 React 会把 `{name}.{ext}` 渲染成多个节点）；只读或禁用的输入框、文本框的值，以及按钮型输入框的值；`aria-label`、`title`、`placeholder`、`alt`、`aria-valuetext`、`aria-description` 和 `option`/`optgroup` 的 `label`。可编辑输入框和文本框里的用户输入不扫描。
- 规则：UUID；12 位以上、同时含数字和字母的十六进制串（前面是 `-` 的也报，落在 UUID 内的不重复报）；调用方登记的系统 ID（`systemIds`，完整值及前 8 位、前 12 位截断，组件测试把全部桩 UUID 和哈希登记进去）；`snake_case` 内部代码；存储路径（`目录/文件.扩展名`、三段以上或两段带扩展名的绝对路径、盘符路径）；JSON 片段（单双引号键名均可）；`[object Object]` 和 `XxxError:`；调用方列出的原始状态值（`rawValues`，整词匹配）。
- 豁免范围：`http(s)://` 网址在匹配前整段剔除，网址的查询参数、锚点和路径段里的 `snake_case` 词、哈希都不报。DOI、PMID、邮箱和日期不报，剂量写法（如 `1/2.5mg`、`5 mg /kg/d`）也不报。`snake_case` 词只在紧跟“.扩展名”“(n).扩展名”“ (n).扩展名”或“@域名”时视为用户内容。下列写法目前仍会报出：主名和扩展名之间夹着其他文字（如 `raw_counts final.csv`）；不带扩展名的名称（如 `serum_boxplot`、`smith_2020`）；`a/b.csv` 形式的相对路径，包括压缩包内路径和 `and/or.pdf`。相对路径是否算用户文件名，要等 DESIGN.md 9.1 定下口径再改规则。
- 用户内容（DESIGN.md 9.1）：渲染出来的用户变量名、列名、样本编号和引用键必须原样显示。所在元素要加 `data-user-content` 标记（或由调用方传入 `exclude` 选择器），也可以把夹具里的具体值列入 `allowValues`。不得为了让扫描为 0 而改写或隐藏这些值。带标记的元素整棵子树（含属性）都不扫描。
- 未覆盖：`undefined`、`NaN`、全大写或短横线错误码（如 `RESEARCH_SOURCE_NOT_FOUND`、`research-source-not-found`）、带点的文案键（如 `errors.task_input_invalid`）、camelCase 字段名，以及中文措辞问题（如“公共稿件”“清洁 DOCX”）。B03 的“扫描 0 项”只证明页面不含 UUID、哈希、登记的系统 ID、内部代码、路径、JSON 和上面两种开发符号，总案第七节其余条目仍需逐页核对。
- 基线页面（数据分析）：客户任务进度、交付列表、交付详情与文件、上传资料列表，均为中文，四项通过。另有一条英文进度页用例：两种语言的原始码来自同一套数据映射，所以没有把全部用例跑两遍；英文用例只列 `snake_case` 状态值，因为 draft、failed 这类单词在英文界面是正常文案。桩数据只覆盖进度状态 `needs_materials`，其余 5 个状态值在这组数据下不会出现；后续批次可以按 6 种状态各渲染一次。每个页面先用 `findByText` 确认自身内容已经显示，再扫描整个 `document.body`。
- 已知泄露用正向断言记录当前唯一的泄露（文献主张核对的内部语境哈希，总案 B03-6）：`toEqual([{ kind: 'hex', value: <哈希>, where: 'text' }])`。B03 修复后该用例会转红，须改为 `toEqual([])`；渲染失败、文案变化或新增泄露也会直接转红。该用例只渲染初始状态，主张 ID、书目版本 ID、复核 ID 和原始状态值要在创建主张、选择证据、保存决定之后才显示，没有覆盖到。所以改成 `toEqual([])` 不代表 B03-6 已全部修完：B03 须为 WritingClaimReview 的交互后状态，以及 WritingScienceReview.tsx:64、WritingLive.tsx:83、ProjectManuscripts.tsx:195 补文字扫描用例。
- “扫描结果为 0 项”的口径（总案 B03、B04 验收）：盘点第十节中归 B03 且当前可达的页面，即 WritingClaimReview（含交互后状态）、WritingScienceReview、JournalFormatPanel、JournalResults，须由 B03 加入 `customerTechnicalText.test.tsx` 并以 `it()` 通过。B04 须加入 SchoolTemplates 的来源路径和缺名时的版本 ID。全部加入并通过，才算达成“0 项”。ReturnContinuationPanel 的“公共稿件”“清洁 DOCX”是中文措辞，扫描器识别不了，改为 B04 的文案验收，用明确的 `rawValues` 或单独断言。ProjectManuscripts.tsx:195（当前不可达）和 WritingLive.tsx:83（只出现在旧稿）不纳入本轮基线。B01 没有给 SCI 和毕业论文页面建基线。

- 接口设计没有改变 D1–D8 的结论，只补充了实现细节：摘要接口路径与规则、新状态 `materials_submitted` 和补交记录表、客户论文项目重复新建返回 409、模板预览接口、派单 `status` 参数、返回令牌参数。
