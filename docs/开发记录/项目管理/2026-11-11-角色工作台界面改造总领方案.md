## 共用界面和现有基础

三套界面采用统一的侧栏布局、折叠方式和选中样式，以及顶栏的语言和账号菜单。管理员顶栏显示当前管理页面，客户与分析员进入项目后共用步骤组件，各自显示对应流程。各角色只加载自己的业务页面。 [当前角色入口](../../../frontend/src/app/App.tsx) [共用侧栏框架](../../../frontend/src/features/projects/WorkspaceShell.tsx) [共用步骤组件](../../../frontend/src/features/projects/WorkspaceSteps.tsx)

管理员可审核注册申请、管理账号和分配项目。客户使用五步工作台提交需求、跟踪进度和查看交付。分析员从本人项目或分配列表进入分析工作区。项目归属保留在客户账号，后端按当前分配授予指定分析员访问和操作权限。 [管理员工作台](../../../frontend/src/features/operations/AdminWorkspace.tsx) [客户工作台](../../../frontend/src/features/customer/CustomerWorkspace.tsx) [项目授权](../../../backend/app/auth/project_access.py)

## 第 3 批 管理员界面首版

管理员登录后默认打开「审核管理」的待审列表。三个主要入口固定在侧栏，已有系统任务、用量统计、运行日志、配置治理、存储治理和运行状态放在下方可折叠的「运营工具」分组。顶部显示当前页标题、语言和账号操作。

```text
顶部   审核管理                                  界面语言  账号
─────────────────────────────────────────────────────────────
侧栏               主区域
● 审核管理         [待审核]  [审核通过]  [审核驳回]
  账号管理         [搜索申请邮箱]  [刷新]
  权限管理         称呼  邮箱  单位  申请时间  状态  [审核申请]
▸ 运营工具
                   点开申请 → 查看资料 → 通过并分配角色 / 驳回
```

| 页面 | 首版显示与操作 |
| --- | --- |
| 审核管理 | 按审核状态和邮箱查找申请，分页列表呈现称呼、邮箱、单位、时间和状态。点开后在详情查看申请说明，选择角色并通过，或填写原因后驳回。已审核申请可查看决定、角色、审核人和原因。 |
| 账号管理 | 按邮箱、角色和启用状态查找已通过账号。复用启停、角色调整和变更审计。注册审核决定统一在「审核管理」办理。 |
| 权限管理 | 首版展示三种角色当前可进入的页面和可执行的关键操作，从这里可跳到「账号管理」调整具体账号。第 5 批在此页接入分配、更换、撤回及分配记录。 |

审核列表通过管理员专用接口读取申请摘要，详情与审核决定复用原接口。刷新后可恢复当前管理页。 [管理员审核接口](../../../backend/app/api/admin.py) [管理员工作台](../../../frontend/src/features/operations/AdminWorkspace.tsx)

Edge 自测走通默认待审、邮箱搜索、审批和驳回、账号启停及审计、权限说明和刷新恢复。客户与分析员看不到管理入口，直接访问审核列表接口均返回 `403`。用户随后确认第 3 批验收通过。 [第 3 批实施与验收记录](../阶段10/2026-11-11-角色工作台第3批管理员界面-实施与验收记录.md)

## 第 4 批 客户界面与三排需求选择

客户侧栏提供「新建项目」「我的项目」和当前项目入口。进入项目后，顶栏显示已确认的 **5 步**并标出当前所在步骤。

| 步骤 | 客户操作 |
| --- | --- |
| 1. 项目资料 | 新建项目，填写项目名称和研究目标。 |
| 2. 上传资料 | 上传原始资料和补充文件，查看上传结果。 |
| 3. 选择需求 | 勾选所需分析和交付，保存草稿或提交需求。 |
| 4. 任务进度 | 查看待分配、分析中、待补资料、已交付等真实状态。收到补充请求时可补交资料或反馈。 |
| 5. 查看交付 | 查看和下载已发布给客户的图件、报告或交付包，并提交反馈。 |

「选择需求」使用三排带勾选状态的多选按钮，窄屏按排折行。

| 需求排 | 选项示例 | 选择规则 |
| --- | --- | --- |
| 第一排 分析类型 | 单细胞 RNA 测序数据分析、RNA 转录组学分析（Bulk RNA-seq）、空间转录组分析 | 可选择一个或多个分析类型。 |
| 第二排 个性化分析 | 差异表达、富集、拟时分析 | 按已选分析类型显示适用选项。例如拟时分析放在单细胞下，Bulk 可选择差异表达和富集。 |
| 第三排 图件与交付 | 热图、火山图、UMAP 图、Word 报告、交付包 | 图件绑定到对应分析类型，Word 报告和 ZIP 交付包可作为项目交付选项。 |

同时选了多个分析类型时，后两排分别按类型分组。例如同一项目可为单细胞选择拟时分析和 UMAP 图，为 Bulk 选择差异表达和火山图。页面提供补充说明，用来登记目录以外的需求。复用现有需求草稿与版本，保存后可以重新打开核对。提交只登记需求，分析员核对数据与研究设计后决定怎样执行。 [现有需求数据结构](../../../backend/app/domain/research_intake/contracts.py)

需求提交后进入「待分配」，任务进度按最新正式提交读取。客户可补交资料、发送项目反馈，并查看、下载本人项目中已发布的交付和提交交付反馈。服务端按角色、项目归属和发布状态检查访问。第 4 批使用隔离样例完成验收，第 5 批联通实际派单和分析员发布流程。 [客户工作台接口](../../../backend/app/api/customer_workspace.py)

## 第 5 批 分析员界面与项目分配

分析员复用现有项目与分析界面，侧栏以「我的项目」「分配给我的项目」和当前项目的分析入口为主。项目中保留项目资料、材料与数据整理、需求和分析方案、执行分析、结果与分析交付。稿件写作、期刊和评审返修入口从分析员导航移出。已有分析入口和本人历史项目纳入回归检查。

管理员在「权限管理」选择项目和分析员，完成分配、更换或撤回。分配记录独立于项目所有权，操作记入审计。分析员按项目权限读取所需资料、确认方法、运行分析并发布可交付的结果。管理员处理分配时查看项目基本资料与状态。项目详情、任务、文件、结果和下载都由后端检查当前角色与项目授权，客户只接收自己项目的进度和已发布交付。

Edge 自测走通**客户提交需求 → 管理员分配 → 分析员处理并发布 → 客户查看进度、下载和反馈**。分组描述统计任务实际受理并由 Linux Worker 完成，4 条样本的总体均值为 2.5。客户下载的 Word 与 ZIP 内的 Word 内容一致。权限验证覆盖未分配的分析员、其他客户、更换或撤回后的原分析员，以及撤回后客户对已发布交付的访问。用户随后确认第 5 批验收通过。 [第 5 批实施与验收记录](../阶段10/2026-11-11-角色工作台第5批分析员界面与项目分配-实施与验收记录.md)

## 每批实施和验收顺序

1. **确认开工。** 每批开工前由用户确认该批范围。
2. **实施和自测。** 完成该批代码与定向检查，由实施者控制用户打开的 Edge，走一遍涉及的角色、正常流程和权限边界。验证优先使用测试库及合成资料。
3. **启动服务交付用户验收。** 提供访问地址、可用测试账号、验收步骤及仍待核实的内容。保持本批验收服务运行，有反馈就在本批修正和复测。
4. **验收后收尾。** 用户确认通过后，关闭本批为验收启动的相关服务，再更新总领方案进度、实施与验收记录及文档索引。收尾完成后等用户确认下一批。
