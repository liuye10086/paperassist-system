## 4. 推荐设计与最小改动

### 4.1 选择与存储

| 方案 | 取舍 |
| --- | --- |
| **推荐：固定版本关联＋一个版本化输出配置** | 两侧正文仍由既有稿件版本管理，只保存关联、术语、声明、学校补充用途和盲审规则；旧稿/旧下载保持有效 |
| 把中英文复制进新的通用稿件模型 | 重复正文、来源和审核状态，迁移及一致性负担更大，本包不采用 |
| 每次导出临时翻译或仅加 UI 清单 | 前者增加调用和变化，后者不能固定交付依据，均不能完整满足 W2 |

拟新增一个受 owner/project/root 约束的追加式配置版本表，保存 `base_version_id`、可选 `peer_version_id`、配置 JSON、revision、请求身份和摘要。复用已有根稿锁/期望 revision、幂等与数据库约束；不增加独立发布状态机。一个配置中只引用固定版本及其已有 SHA，不递归复制来源闭包；规范化后在调用内传递，不层层解析或重复全量算哈希。

既有 `ExportRequest.school` 和旧调用保持兼容。拟增可选 `presentation_version_id`、`language_view`（`zh-CN` / `en` / `zh-CN-en`）、`review_mode`（`identified` / `blind`）；导出记录冻结这些选择与配置摘要，复用 `manuscript_docx` / PDF 任务和鉴权下载。确需新增导出关联列时一并纳入同一增量迁移，不改旧迁移。字段命名可在实现时按现有合同微调，不改变本方案语义。

新增归属、固定版本、幂等冲突和并发修订校验是必要边界；不为已规范化内部数据增加通用防御层。旧请求不带新配置时维持旧行为。

### 4.2 关联双语与一致性

- 每个关联组显式列两侧章节/段落 ID，支持一对一、一对多、多对一及缺译/不对应。禁止按排序自动认定对应。新版本使用旧关联时显示需复核；历史固定配置和导出仍保留原来有效状态，不能倒改历史。
- 默认逐段中文后英文；可选各自单语。参考文献按稳定引用身份归并并复用现有格式器，不因中英相邻而重复列两套参考文献。学校单语视图仍保留模板明确要求的另一语言摘要等章节。
- 比较已绑定的科学事实、数值/单位/NA/方向及来源身份；引用比较稳定文献/证据身份，允许正常显示序号重排；图比较逻辑身份、语言版本和题注。无法结构化证明的词义/结论强度显示待人工核对，不用简单词法结论冒充语义验证。
- 术语表保存中文、英文、允许变体及来源/确认状态，报告冲突或未匹配位置；不擅自全局替换专名。图内语言优先复用既有图语言版本和明确例外；缺少可编辑来源的图保留原图并列项，不做 OCR/付费翻译或科学重绘。
- 现有语言清单按每个导出位置的预期语言核对中英相邻段落，不关闭全稿语言门禁来放过混语。改变科学正文仍走现有科学审核；配置操作不能绕过正文审核。

### 4.3 学校内容、声明与目标要求

- 复用 `SchoolExportOptions`、`SchoolManualChapter`、双摘要、关键词、目录及模板确认。补充缩略词/附录/成果/致谢的用途、来源和必填缺口，绑定稳定章节 ID。若模板确需新增章节，走原有显式确认/新版本流程，不悄悄改旧确认的 purpose。
- 纳入/排除清单绑定实际章节/资料；保留已有方法和限制。学校最低篇幅与期刊上限同时记录所含部分、语言和计数规则，冲突展示待决定，不自动裁剪结果。W1 简报整稿 `max_words`/`max_figures` 保留原口径；摘要/正文/表数沿用期刊有限检查，不扩成自动改写或新的生成硬约束。
- 作者顺序、通讯作者、单位、基金及编号、伦理批准/豁免、注册、利益冲突、数据可用性分别保存状态和依据。复用 `known/pending/not_applicable` 的既有声明语义，`not_applicable` 需理由；可绑定需求版本、用户声明或已有文件定位。不默认给出任何合规结论。
- 缺材料允许保存草稿并清楚显示待补，不标为可正式投稿/符合真实学校要求。学校签名、成果列表、致谢、声明采用真实提供内容；工程演示明确标样例，不虚构客户信息。
- 指南沿用已有固定版本及有限规则：正文/摘要长度、图/表/引用数量、必要章节/顺序等。未支持的引用格式或未确认口径保留待定，不宣称完全符合期刊。不得强行把综述/方法论文改回研究稿结构。

### 4.4 独立盲审派生与输出

- 配置明确哪些身份字段、章节及文本须隐藏，哪些自引/伦理编号等需保留或人工决定；不凭姓氏猜测、全局删除参考文献作者。普通稿始终保留真实来源和内容。
- 从固定输入新建盲审派生 DOCX，检查正文、表格/题注、页眉页脚、脚注尾注、文档属性、批注/修订作者、替代文本和关联/附件名称等实际存在的 OOXML 部件。生成路径能清除的身份按规则处理；不能可靠处理的项目明确列项，不静默保留后标“完成”。
- PDF 必须由同一盲审 DOCX 导出并绑定其 SHA；检查文本、元数据及实际存在的批注/附件名称等。普通 PDF 不能混入盲审导出记录。检查使用现有 DOCX/XML/PDF 库，不增加泛化脱敏平台。
- 图片、扫描签名、嵌入对象及未识别身份列人工检查。缺乏确认时保持“仍需人工核对”；本包默认不修改原图或调用 OCR。若用户之后需要图像掩码，仅产生派生副本并另定具体材料范围。
- 前端提供保存配置、关联缺口、声明待补、普通/盲审预览及下载入口，复用现有草稿、深链、任务进度与中断恢复。不把字段的保存成功显示为语义、合规或盲审质量通过。
