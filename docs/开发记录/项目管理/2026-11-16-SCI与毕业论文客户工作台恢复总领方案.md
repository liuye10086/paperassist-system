在「我的项目」恢复客户自主完成 SCI 论文和毕业论文的流程。客户在同一个「新建项目」入口选择项目类型，论文项目在客户工作台内完成资料准备、写作、复核、版本管理和 Word 下载。分四批推进，先验证建项与授权，再分别打通两类论文，最后接回返修和历史入口。

## 1. 实施前基线

- 登录后已经按管理员、客户、分析员进入不同工作台。客户建项固定提交 `research` 和 `['analysis']`，详情页也固定走需求、进度、交付流程。服务端已经识别 `research`、`sci`、`thesis`，客户权限表目前只覆盖分析项目的提交资料、需求和交付等操作，论文接口需逐项接入。 [角色入口](../../../frontend/src/app/App.tsx) [客户建项](../../../frontend/src/features/customer/CustomerProjectCreate.tsx) [客户工作台](../../../frontend/src/features/customer/CustomerWorkspace.tsx) [客户权限](../../../backend/app/auth/permissions.py)
- 旧工作区仍有稿件、文献、期刊、学校模板和返修组件，分析员使用的 `analysisOnly` 分支隐藏写作入口。共享写作契约已有原始研究 `research` 和叙述性综述 `narrative_review`。这些代码可以作为接线起点，客户角色下的全链仍需验收。 [旧组件接线](../../../frontend/src/features/projects/ProjectWorkspace.tsx) [文章结构契约](../../../backend/app/domain/manuscript_writing/article_contract.py)
- A19 已验收的历史证据覆盖固定成果 → SCI／学校 Results/Methods 候选 → 新稿 → Word。该证据可复用来核对来源、版本及下载契约。完整论文生成、真实学校和期刊规则、实际 Word/WPS 版式以及曾记录的长耗时仍需按本轮场景核对。 [A19 用户验收与遗留事项](../阶段06/2026-11-04-A19-用户验收与遗留事项.md)

## 2. 建项表单与角色边界

| 下拉选项 | 现有类型 | 建项内容 | 创建后入口 |
| --- | --- | --- | --- |
| 分析项目 | `research` | 项目名称、研究目标，以 `['analysis']` 初始化 | 项目资料 → 上传资料 → 选择需求 → 任务进度 → 查看交付 |
| SCI 论文 | `sci` | 项目名称、研究目标，以及下表的五项 SCI 字段 | 项目资料 → 写作资料与引用 → 稿件与复核 → 期刊适配与 Word → 返修 |
| 毕业论文 | `thesis` | 项目名称、研究目标，学校、学位信息和模板在项目内设置 | 项目资料 → 学校模板与写作资料 → 章节与复核 → Word → 论文意见 |

建项默认显示「分析项目」，客户可在提交前切换。提交成功后沿用项目类型固定的规则。复用现有项目语言偏好、名称和研究目标校验，并同步项目卡片、筛选和可访问标签。论文导航沿用客户工作台布局，进入子页时按需加载。 [界面规范](../../../DESIGN.md)

| SCI 字段 | 建项交互与校验 | 写作用途 |
| --- | --- | --- |
| 论文类型 | 必选「研究型论文」或「综述」，对应现有 `research` 或 `narrative_review` | 研究型稿件组织原始结果与方法。综述围绕文献范围、主题和结论 |
| 主要结果或结论 | 必填一段文字。研究型提示填写主要结果，综述提示填写综合结论 | 作为客户提供的写作材料，后续与结果、图表或文献逐项关联 |
| 目标期刊 | 必须单选，首版拟提供「Nature 子刊」「Science」「其他期刊」。选其他须填写刊名，选 Nature 子刊可先记录系列意向，也可填写具体刊名 | 带入期刊页面。正式格式检查时由客户选定具体刊名及适用的指南版本 |
| 关键词 | 输入后点「添加关键词」，可逐条移除。至少一条有效值，去除首尾空白并检查重复，沿用现有写作字段上限 | 预填写作和参考文献检索，保留用户确认后的版本 |
| 图表计划（Figure plan） | 点「添加图表计划」逐项录入，可删除或调整顺序，至少一项。每项填写标题和拟表达的内容，例如「图 1 · 队列纳入流程」 | 带入写作资料，在有实际图表时关联固定来源和图注 |

上表按讨论顺序将五个字段理解为 SCI 建项必填项。毕业论文先沿用通用建项字段，综述按现有叙述性综述实现。期刊候选及补填规则是首版设计建议。图表计划和客户结论均标示为客户提供的材料，进入正式稿件时以已选择和核对的来源为依据。

| 角色 | 论文项目中的职责和访问 |
| --- | --- |
| 客户 | 管理本人项目的资料、文献、稿件、版本、期刊／学校信息、返修和 Word 成品。创建及使用论文项目均由客户直接完成 |
| 管理员 | 账号、全局配置和运行状态沿用现有运营权限。论文项目从可新派单范围排除，稿件、来源和成品继续按研究内容权限隔离 |
| 分析员 | 通过现有分配链执行分析项目。已有论文项目的历史派单先在隔离样例中核对。方案保留已授权的分析操作至解除分配，该分配只授予现有分析范围 |

凡资料确需另行统计或生信计算，沿用分析项目和已发布交付，客户可把有权限的 Word、数据说明或图表上传到论文项目并标记来源。旧「送入写作」继续用于其已支持的同项目场景。新增跨项目直连若有需求，再依据交付版本和项目所有权设计。

#### B02 实施与验证记录

- 客户工作台已接入资料与引用、稿件与复核、期刊适配和固定版本 Word。研究稿将有明确出处的用户报告结果和图件绑定到事实稿，报告数值沿用原值和材料来源，归类为用户报告的上下文。综述从已核验文献进入叙述性结构，新增或改写的文献主张重新核验后生成引文和书目。
- 两类稿件均走冻结材料预览、明确授权、候选、逐段科学复核和 Word 语言清单，再采用为固定版本。写作提交失去回执时可用原请求键手动核对重试。Word 失败恢复绑定原任务及稿件版本。资料、写作记录与下载同时校验客户、项目和关联材料。SCI 成品入口仅提供 `.docx`。
