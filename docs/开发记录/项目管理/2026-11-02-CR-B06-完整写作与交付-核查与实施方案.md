## 4. 架构与范围选择

**推荐：在现有服务中增加少量版本化合同和必要记录。** 资料及交付要求→固定来源/稿件基础版本→写作候选→科学/语言复核→显式发布→精确版本导出→交付冻结；沿用现有 owner/project、幂等、任务恢复、存储和鉴权。

不选“只靠通用 instructions 和人工清单”：代码改动少，但不能可靠区分综述证据、限定重构范围、关联双语或冻结最终交付。不选“重建通用写作引擎/模板系统/全局缓存”：与现有服务重复，扩大迁移和回归范围。

新的结构/范围/声明/对照配置优先随现有不可变版本保存；确有独立生命周期的交付快照及验收事件才新增最少必要存储。是否新增迁移由各包实际存储需求决定，执行前重新核对迁移末端，只向后新增，不预占迁移号、不改已用迁移、不修改历史快照。
