## 一、开始前要准备的环境

1. 用 `script/dev.cmd` 启动。它会同时启动 API、前端和 Worker 容器。如果单独启动 API，要另执行 `python -I script/dev/worker_stack.py start`，否则写作、解析、导出任务会一直排队（B01 实测时遇到过）。
2. 开发库 `paperassist_system` 迁移到最新：`cd backend && python -m app.db.database upgrade`，再执行 `check`，应输出 `schema is current (0090_material_submissions)`。
3. 账号：客户、管理员、分析员三个验收账号，见用户桌面“启动文档.txt”。B05 另需客户 B、客户 C（越权与空状态），可由管理员审核新注册得到。
4. 实测脚本：`~/b01-tools/`。`run.sh` 设置 Playwright 和账号文件路径；`measure.cjs` 里有 B01 的 t1–t4 任务脚本、辅助派单和发布脚本，以及 `probe3`（列出页面所有控件）。可以直接扩展。
5. 计数口径（B01 页面盘点第十一节）：
   - 业务点击：只计必须的点击，下拉选择和勾选算点击；输入文字、系统文件选择框和滚动不算。
   - 重选：页面已经知道、却要用户再选一次的对象。
   - 往返：离开办理页去别处，再回来，算 1 次。
6. 文字扫描：客户页面不得出现系统 ID、哈希、内部代码、存储路径、JSON。规则见 `frontend/src/test/technicalText.ts`，可以在 Edge 里用同样的规则抽查。
7. 生成正文会真实调用外部模型并计费。开始前请管理员为测试项目和客户配置用户级、项目级写作预算（B04 T5 除外）。
8. 文件选择由用户操作。
