## 2 产品目标与使用场景

### 2.1 产品目标

研究人员或项目执行人员可以登记客户需求，导入数据及既有材料，确认研究设计，执行有版本的分析，核对图表和发现，再生成分析报告、SCI 初稿或毕业论文初稿。修改需求、数据、方法或图表时，系统能指出受影响成果，并保留旧版本。

论文中的结果应对应已经完成并有来源的研究；拟开展实验进入后续研究计划或展望。公共数据再分析、客户原始实验、外部报告、文献发现和图像观察分别记录来源与核验状态。

### 2.2 必须支持的业务路径

| 场景 | 进入时已有内容 | 主要流程 | 可交付成果 |
| --- | --- | --- | --- |
| 独立数据分析 | 矩阵、结果表、Cq 或其他已支持数据 | 需求、数据核对、设计、分析、图表、复核 | 分析报告、结果表、图、图注、方法及代码 |
| 分析后写 SCI | 待分析数据和研究问题 | 分析完成后整理研究发现、文献及稿件 | 分析成果及 SCI 初稿 |
| 分析后写毕业论文 | 数据、学校规范及已完成研究 | 分析成果与学校章节关联、写作、检查 | 分析成果及毕业论文初稿 |
| 同一研究多项交付 | 同一套研究资料 | 分别建立分析、SCI、毕业论文交付记录 | 多份独立版本成果，共享来源 |
| 已有结果直接写作 | 客户结果表、报告、方法和图 | 标注外部结果来源，补缺、核对、写作 | 有明确来源与局限的初稿 |
| 已有图表复核或重绘 | 原图及可能存在的原始数据 | 登记使用策略，核对信息，重绘或排版 | 原图复用版、重绘版、拼图和图注 |

| 资料尚不完整 | 方案、部分数据或说明 | 保存需求，展示缺口，补充后续办 | 需求和材料清单；具备条件的部分成果 |

### 2.3 人员与权限

沿用现有账号、项目所有权和管理员研究内容边界。客户姓名代称、邮箱、手机号及单位属于业务联系资料，不自动创建账号或增加共享权限；通知、邮件、客户门户、多人协作不因本方案自动启用。

## 4 核心业务对象与状态

以下是逻辑对象，最终表名、字段和接口在各批实施方案中确定。它们补充现有服务，不建立第二套任务、预算或对象存储体系。

### 4.1 研究项目与交付记录

- **研究项目**：保存研究问题、资料和所有权，允许关联多套独立实验和公共数据。
- **客户需求版本**：保存共同信息、选用模块、优先级、期限、已完成及待完成内容、来源文件和确认记录。
- **交付记录**：类型为数据分析、SCI 初稿或毕业论文初稿；各自保存范围、语言、目标规范、来源快照、版本和验收状态。
- **研究设计版本**：保存样本单位、重复、组别、比较方向、协变量、批次、对应关系及确认记录。

建议新项目不再强制用户先在 SCI 和毕业论文之间二选一。旧 `project_type` 保留兼容映射，新业务依据交付记录决定能力、稿件种类和目标规范；历史数据不自动转换、复制或修改。

同一研究可以同时有 SCI 和毕业论文交付，但两者有独立章节、稿件、导出和验收记录。共享研究发现并不表示一份稿件修改后另一份自动改写。

### 4.2 数据到论文的对象链

数据链为：原文件与包成员 → 生信数据集版本 → 样本及特征注释 → 研究设计与分析配置 → 执行记录 → 结果表和方法记录 → 图表版本 → 研究发现 → 报告或稿件版本 → 导出与交付包。

每一环使用稳定 ID、来源摘要及明确版本；大型矩阵、图片和分析对象保存在受控存储中，数据库保存身份、元数据和引用。禁止用文件名、显示顺序或数组下标代替稳定身份。

### 4.3 业务进度和任务状态

需求可以处于草稿、待补充、待确认、已确认或被新版本取代；交付可以处于待开始、进行中、待复核、待用户验收、已验收或被新版本替代。上述为业务进度，实际计算继续使用既有任务状态和检查点。

“代码已支持”“合成验证通过”“真实数据流程已执行”“方法及科研结论已复核”“真实模型已验证”“用户已验收”分别记录，不相互替代。客户端状态未知、调用未知和产物未核验继续保留未知，不推定失败或成功。

### 4.4 来源与核验状态

| 来源或状态 | 允许的使用方式 | 必须保留的含义 |
| --- | --- | --- |
| 客户实验及记录 | 依据真实材料分析或写作 | 与公共数据和文献区分 |
| 本系统计算结果 | 在已保存输入和参数下引用 | 不自动证明设计正确或研究结论成立 |
| 客户或外部工具结果 | 复核、引用或在取得数据后重新分析 | 未重算时不能标成本系统计算 |
| 公共数据再分析 | 新建真实分析记录并注明原始研究 | 不写成客户亲自完成的实验 |
| 文献或图谱证据 | 支持背景、比较、假设或独立验证 | 不转写为本研究观测结果 |
| 图片或 OCR 观察 | 记录看见的文字与图像内容 | 人工转录核对不等于统计或研究事实已核实 |
| 机制解释或未来实验 | 作为解释、局限或研究计划 | 不写成已经完成或已经证实 |

### 6.2 数据集内容

生信数据集至少保存：数据类型、物种、平台、来源及用途、输入处理阶段、参考与注释版本、矩阵维度和稀疏性、稳定特征 ID、观测 ID、样本表、图像坐标关系、成员身份、解析版本、父版本和处理记录。

### 6.4 首条空间分析流程

1. **导入和核对**：识别包成员、数据表示、条码、特征、坐标和图像；展示研究设计缺口。
2. **设计和质量计划**：确定分析用途、观测层级、过滤和标准化方案；用户确认需要的规则。
3. **质控和处理**：生成质量指标、排除记录和独立处理版本，原始 counts 始终保留。
4. **降维和聚类**：记录特征选择、PCA、邻居、UMAP、聚类参数和种子，不以某个图形外观选择研究结论。
5. **marker 与注释**：生成 marker 表、热图或点图；细胞类型或区域解释保留依据及人工复核。
6. **空间表达**：依据正确图像、坐标和缩放生成空间图，检查旋转、翻转、裁切、标签及色标。
7. **适用的比较**：只有设计和方法条件满足才提供对应推断；不满足时保留探索描述及限制。
8. **成果承接**：冻结结果、图和方法，形成研究发现，送入分析报告及论文。

空间去卷积、轨迹、细胞通讯、跨切片配准等不作为默认步骤。需求明确且方法、数据和验证条件齐备时，再纳入对应批次的独立工作包。

### 6.5 方法与参数原则

- 区分 counts、TPM/FPKM、强度、标准化数据、相对丰度和已汇总结果，不能混用同一输入合同。
- 统计单位、比较方向、配对和重复关系先于算法选择；不知道时允许保存，但相关推断等待补充。
- 过滤、变换、缺失处理、批次处理及模型调整保存实际规则和影响，不按显著性反复挑选。
- 显式保存多重校正方法及比较族、完整结果和不可计算原因；没有显著发现仍是合法结果。
- 物种映射、基因集背景、排序指标及特征选择属于方法的一部分，进入交付记录。
- 固定工具可以执行已确认参数；模型可协助解释或起草建议，不自动确认实验设计和方法前提。

## 7 图表 研究发现与写作衔接

### 7.1 单图和拼图

单图至少绑定分析结果、数据版本、绘图配置、绘图代码或模板、语言、标签、色标、格式和哈希。空间图另绑定图像、缩放、坐标和观测集合。已有图直接复用时，记录原件和声明来源，不生成不存在的计算绑定。

拼图保存布局、面板顺序、字母、小图名、单图版本及裁切范围。更新某个单图产生新的拼图候选，不自动覆盖其他面板或已导出稿件。单图和拼图分别下载；图注使用相同来源。

图的颜色、字体、尺寸和面板位置可以单独修订；筛选对象、标准化、组别、检验或数值变换属于分析变化，必须生成相应结果版本。图内统计标注只能引用实际保存的结果，不能手工填入一个无来源 P 值后标为已验证。

### 7.2 研究发现

研究发现用于连接计算和正文，至少保存：

- 要回答的研究问题和属于哪项交付。
- 输入数据和研究设计版本，实际方法及运行记录。
- 关键对象、比较方向、数值、单位、样本口径、统计信息及不可计算项。
- 支持该发现的结果表、单图、拼图和图注。
- 原始观察、外部结果、文献解释、机制线索和局限的分类。
- 必需补充项、冲突证据、人工复核决定和允许表达的范围。

系统能依据研究发现列出“可直接陈述”“需要限定表述”“等待补充”的内容。解释不能只依据图片外观；原始表格和方法记录随图一起进入写作。

### 7.3 报告集合与多来源

保留当前同源集合合同，为新多源报告增加独立合同版本。多源报告保存每个数据集、设计、结果、图和文献的精确版本，逐项说明用途和对应关系，不因为合并进一份 Word 就合并样本量或汇总新的 P 值。

报告送入稿件时传递所选报告版本、研究发现顺序、图注和来源；不得要求用户重新选择后丢失原选择，也不把报告全文无区分地当作研究结果。SCI 与毕业论文使用共用读取和版本服务，分别组织内容。

### 7.4 上游变化影响

| 变化 | 至少需要指出的影响 | 用户可采取的操作 |
| --- | --- | --- |
| 客户改变纳入范围或主线 | 研究发现、章节和交付清单 | 生成需求新版本，确认需更新的交付 |
| 样本或矩阵变化 | 依赖该数据的结果、图、报告和正文 | 新建数据版本并重新分析 |
| 阈值、组别、比较方向或算法变化 | 筛选、效应解释、图注及相关结论 | 新建分析运行并复核 |
| 仅修改图形外观 | 图版本、拼图和相应导出 | 生成新图并选择是否更新稿件 |
| 文献或数据库证据变化 | 引用段落、讨论、机制说明 | 重新核验并修改受影响内容 |
| 模板或期刊要求变化 | 结构、格式和目标导出 | 重新绑定目标规范并检查 |

影响标记不自动重算、不自动调用模型、不自动发布候选；历史成果仍保留原版本身份。

## 8 SCI 与毕业论文写作完善

### 8.1 共用写作服务

两类论文继续共用材料、研究发现、章节、引用、检查、版本和导出服务。新增交付类型、文章结构、写作范围和目标要求，不复制一套论文系统。

写作需要冻结交付需求、基础稿、研究发现、数据与方法、图注、参考文献和模板。任务语言、模型配置、提示词和授权身份随任务保存；后来修改项目设置不改变已提交任务。

### 8.2 写作模式

| 模式 | 必需输入 | 主要验收边界 |
| --- | --- | --- |
| 完整初稿 | 已确认结构、完成研究、发现、方法和文献 | 结构符合类型；证据不足内容保持缺口，不虚构补齐 |
| 指定章节 | 章节身份、来源和修改要求 | 只生成选定范围，其他章节及绑定保留 |
| 结果与讨论 | 结果发现、可解释范围和文献 | Results 与 Discussion 的证据用途清楚 |
| 既有初稿重构 | 原稿、目标主线、需保留内容 | 新版本可核对重排和改写范围，保留原文来源 |
| 语言润色 | 冻结正文、术语和输出语言 | 数值、事实、引用、结论强度不因润色改变 |
| 按意见修订 | 基础稿、意见、决定和证据 | 意见、修改、回复和版本相互对应 |
| 毕业论文扩充 | 原稿、章节要求和可用研究材料 | 扩充依据真实材料，缺材料不靠重复文字满足字数 |
| 格式整理 | 固定正文及模板 | 不因排版改变研究内容，导出可回溯 |

### 8.3 不同文章类型

原始研究以真实实验或再分析结果为基础；简报依目标篇幅和必要章节组织；综述以文献和主题证据组织，不能复用原创实验 Results 作为必填结构；方法论文区分方法说明、实际验证、适用范围和限制。每种类型先定义可执行结构、所需材料和检查规则，再开放生成。

学校论文以冻结模板和确认章节为依据，可以有综述、分析过程、实验结果及其他学校要求。不能只将 SCI 七部分改标题当作完整毕业论文适配。

### 8.4 语言和篇幅

界面语言、项目默认输出语言、交付语言和原图语言分别保存。首轮完善明确支持中文和英文；中英对照作为关联稿件或关联段落能力实现，不将双语界面当作双语正文。

建议中英对照采用稳定段落对应，同一份研究发现作为两种语言的事实来源；导出先提供逐段对照及单语言文件。左右并排、具体排版及其他语言在该批确认时确定，不假定所有模板都适合相同排版。

篇幅检查明确正文、摘要、图注和参考文献的计入范围以及中文/英文计数口径。最低字数与最高字数分别处理；学校最低篇幅、期刊上限、图表数量和客户要求冲突时展示冲突并等待决定，不自动删减事实。

### 8.5 作者信息 伦理与盲审

作者、单位、基金、伦理或注册、利益冲突、数据开放、致谢及成果清单依真实材料填写，缺失保持未提供或不适用。记录这些字段不等于确认研究合规或作者资格。

盲审版是独立导出配置和产物，保留原稿。按已确认学校要求检查可识别的正文、封面、页眉页脚、文件属性、批注修订及相关图片文字，给出需要人工检查的剩余项。不承诺仅靠自动扫描就完成所有匿名化。

### 8.6 真实模型与质量验证

保留当前统一外发预览、材料范围、预算和授权。学校稿真实授权链必须专项补齐，不能简单删除拦截后视为已具备完整能力。合成响应可以验证工程连接，不能证明自由写作、翻译、长论文质量或领域解释成立。

先完成不调用模型也可复核的事实、方法和来源承接，再在用户另行确认材料、模型、任务范围及预算后进行真实验证。科研事实、语义、引用和学校/期刊适配分别记录结果。

## 9 技术衔接与兼容原则

### 9.1 方案选择

| 路径 | 适用价值 | 成本或限制 | 建议 |
| --- | --- | --- | --- |
| 在现有系统增加固定生信流程 | 能保留项目、任务、版本、稿件和导出链路，持续形成数据到论文的业务 | 需要建立生信对象和适配层，并验证方法 | 作为主路径 |
| 先导入外部工具结果 | 能较快服务已有结果或旧分析项目 | 若只做导入，不能满足系统自身分析和重现需求 | 作为正式输入路径及过渡方式 |
| 全面更换框架或重写平台 | 可重新安排所有结构 | 重复建设已完成能力，迁移和历史兼容成本高 | 当前不采用 |

### 9.2 生信执行环境

建议保留现有 Python/FastAPI 后端和队列，新增受控生信执行环境。Python 空间主线采用 AnnData、Scanpy、Squidpy 等候选工具；需要客户既有 Seurat 流程或 R 方法时增加固定 R 适配器。

[AnnData 官方合同](https://anndata.readthedocs.io/en/stable/generated/anndata.AnnData.html)提供矩阵、观测、特征和派生层的对象结构；[Squidpy Visium 读取说明](https://squidpy.readthedocs.io/en/stable/api/squidpy.read.visium.html)包含图像、坐标与缩放参数；[Seurat 空间分析说明](https://satijalab.org/seurat/articles/spatial_vignette.html)覆盖标准化、降维、聚类和空间展示。工具存在相应功能，不表示已经适配本项目或通过客户数据验证。

具体依赖版本、兼容组合、镜像、CPU、内存、线程、临时磁盘和时间额度在对应批次核对并锁定。本方案不承诺固定运行时间，不直接把现有 30 秒子进程合同放大为所有任务的无限制运行。

生信执行与既有固定统计可以有不同执行额度，但继续使用统一任务身份、调度、租约、检查点、错误和产物登记。长任务不占用 HTTP 请求等待计算；恢复前核对输入与检查点，不重新执行未知外部调用。

### 9.3 数据存储和格式

采用稀疏矩阵和有版本分析对象，避免将组学矩阵整体转换为 Python/JSON 单元格列表、逐格数据库记录或前端完整表格。预览提供维度、稀疏性、少量切片、样本与特征索引，按需分页读取。

生信上传和解压额度与已有文档/Excel额度分别配置；不为接收当前约 31.5 MB 数据包而全局放宽所有格式。额度需覆盖压缩大小、展开大小、成员数量、矩阵形状及稀疏记录数，并在接收和解析阶段一致执行。

归档处理应核对路径、链接及成员类型，拒绝越出目标目录和不受控展开；从归档读取数据不执行其中脚本。重绘或复现代码由固定工具产生，客户提供脚本的实际执行须另有支持合同。

### 9.4 来源和合同扩展

新增生信来源类型及对应结果、图、研究发现和交付引用；旧数据来源及旧任务继续按原合同解释。不能把生信矩阵伪装成 Excel 工作表，或用自由 JSON 标签绕过原来源校验。

源对象之间使用真实关联和所有权校验，新增引用时同步考虑下载、生命周期、容量、备份、审计及下游变化。跨数据集功能只放宽明确确认的版本合同，不移除旧报告的同源检查。

### 9.5 现有代码影响范围

下列路径为实施前核对入口，不是本轮修改清单。新目录名称和迁移号须在对应实施方案中按当时基线确定。

1. 既有账号、项目、样稿、模板、原图、结果、解释、引用、任务和导出继续可查。

## 10 六批交付范围

六批是功能工作包，不是工期承诺。每批先形成实施方案，说明数据库、后端、前端、验证和用户验收；用户确认后再执行。大范围批次可以在实施方案中拆成有完整产物的子工作包，但不擅自增减目标。

### 10.1 总体依赖

主路径为 `CR-B01 → CR-B02 → CR-B03`，先形成当前空间数据到分析报告及初稿的闭环。`CR-B04` 完善差异、富集和候选，`CR-B05` 扩展数据类型及证据整合，`CR-B06` 汇总完整写作与交付要求。

图表、方法记录、结果导出和检查不能全部拖到第六批。每批必须交付本批结果所需的表、图和方法，第六批补齐完整规格和组合交付。某一其他组学流程尚未完成，不应阻断已经满足条件的空间数据报告。

### 10.2 第一批 CR-B01 共同需求与生信数据接入

**目标**：让真实研究资料和客户要求进入正确业务模型，为计算和写作提供可靠输入。

**范围**：

- 共同信息、交付组合、首次/最终交付、优先级、资料清单和需求版本。
- 纯分析项目、历史 SCI/thesis 项目和多交付研究的兼容设计。
- 实验、样本、重复、分组、来源、数据阶段、比较方向和待确认项。
- GEO/Visium 包及 MTX 配套文件读取，空间图像/坐标关联，稀疏数据集版本。
- 对未解析 H5 和其他格式显示准确能力状态；分类登记不算该组学分析已经实现。
- 类型化需求和设计信息与现有分析计划、任务及来源连接。

**独立交付物**：需求档案、材料清单、样本表、生信数据集详情、导入核对报告和原件下载。

**验收门槛**：纯分析无需强选论文类型；历史项目正常；当前 GSE 包可通过 MTX 路径建立真实数据集；条码、特征和空间文件一致；缺失设计如实显示；换项目不串数据；导入失败原件可查。

**边界**：不执行完整聚类、差异或富集，不生成真实模型论文，不承诺所有 H5/其他组学格式已解析，不新增原始测序流程。

本文件只定义第一批交付边界，第一批的表结构、接口、组件、迁移、命令和测试步骤留待用户确认总领方案后编写。

### 10.3 第二批 CR-B02 空间转录组分析与出图

**目标**：在已导入的当前 GSE 数据上建立可重现、可解释的空间分析流程。

**范围**：

- 生信执行环境、固定工具和资源合同，H5 读取及适用表示的一致性核对。
- 质量指标、过滤、标准化、特征选择、PCA/UMAP、聚类和 marker。
- 质量图、降维图、marker 图、基因及聚类空间图。
- 切片/区域注释、实际统计单位和设计缺口；探索分析与生物学推断分开。
- 参数、种子、环境、代码、结果表和方法记录。

**独立交付物**：空间分析运行、处理数据版本、结果表、单图、方法及复现信息。

**验收门槛**：实际读入和计算成功；counts 不被覆盖；过滤数量可对账；重复执行在声明的确定性或容差内；空间图与输入位置一致；人为核对区域和注释；失败或资源不足不发布错误结果。

**边界**：缺少供体和分组设计时，不宣布孕周、疾病或其他生物学比较成立。当前数据不足以支持的结论保持缺口。

### 10.4 第三批 CR-B03 分析成果到论文的首条闭环

**目标**：将第二批实际产物变为有来源的报告和 Results/Methods 初稿，验证业务方向。

**范围**：

- 研究发现、方法说明、关键值、结果表、图注及冲突的结构化表达。
- 所选分析/报告版本进入写作，保留图顺序、图注和来源选择。
- 原图、重绘、拼图基本能力及必要的图像导出。
- 分析 Word、结果 Excel、图和方法文件；SCI 与学校共用事实承接。
- 现有报告或外部结果的直接写作路径，保留未重算状态。
- 学校稿写作链的专项兼容与授权设计；真实模型验证需要单独明确材料和预算。

**独立交付物**：当前数据的分析报告、图表包、研究发现及 Results/Methods 候选稿。

**验收门槛**：正文关键数值能指回结果；Methods 对应实际执行步骤；图号与面板对应；外部结果和公共数据来源准确；修改来源后产生影响；候选显式发布，原稿和旧导出保留。

**边界**：该批首先验证事实承接和目标章节，不因生成部分章节宣称完整 SCI、综述、双语或毕业论文质量已通过。合成与真实模型证据分别记录。

### 10.5 第四批 CR-B04 差异 富集与候选筛选

**目标**：提供研究问题驱动的差异、功能解释和候选筛选能力。

**范围**：

- 依据类型和设计定义可支持的差异方法、比较集合、效应和校正口径。
- GO、KEGG、GSEA、自定义集合、功能分类、背景/排序及映射记录。
- 交集、同方向、阈值、指定对象、排除及优先级规则。
- 序列/结构注释导入；明确特征提取范围，复杂工具可由第五批承接。
- 差异表、富集表、候选表、火山、热图、富集、Venn/UpSet 等图。

**独立交付物**：带方法和来源的差异、富集及候选分析包，可进入研究发现和稿件。

**验收门槛**：比较方向一致；校正范围正确；背景和未映射项可查；没有显著发现时正常交付；筛选每一步数量可对账；改变阈值不会覆盖旧结果；数据库使用方式和版本明确。

**边界**：不把多组比较或区域比较默认视为有充分生物学重复；不因外部 API 或数据库名称可用就宣称许可、完整性或独立验证已成立。

### 10.6 第五批 CR-B05 其他数据与证据整合

**目标**：扩展为完整客户需求所需的多类数据处理和跨数据证据能力。

这是范围较大的工作包，实施方案按下表拆成独立可验收子工作包；只完成其中一类时保留其他类未完成。

| 子工作包 | 目标输入和最低成果 | 需要独立明确的内容 |
| --- | --- | --- |
| bulk 转录组 | counts 或明确处理阶段矩阵、样本表；质控、适用差异和图 | 输入尺度、设计、批次和比较 |
| 单细胞 | 支持的稀疏矩阵或分析对象；质量、降维、聚类、marker 和注释记录 | 细胞/供体层级、过滤、注释依据及适用比较 |
| 代谢组和蛋白组 | 定量、结果和对象注释；质量、适用比较、候选和图 | 缺失、尺度、标准化、鉴定及映射可信度 |
| 微生物组 | 特征或分类丰度、样本信息；组成、多样性及适用比较结果 | 测量流程、数据尺度、分类版本和统计方案 |
| qPCR | Cq、板位、内参、重复与条件；可追溯计算、复核和图 | 计算及汇总、校准、检验输入和异常规则 |
| 表型 行为学和临床数据 | 结构化表及设计；复用统计、质量和图表成果 | 单位、配对、重复、时间/剂量及实际支持的方法 |
| 序列或结构特征 | 已确认注释或支持格式；特征表和筛选依据 | 序列/结构类别、特征定义、工具和验证 |
| 多组学整合 | 多数据集及对应表；相关、通路或网络与一致性结果 | 能对应的层级、匹配范围、缺失和校正 |
| 外部证据 | 文献、图谱、独立公共数据、敲除/突变记录 | 来源、物种、组织、版本、许可和验证范围 |

**独立交付物**：每类数据的完整分析记录和成果包，以及跨数据的候选证据对应表。

**验收门槛**：每个子工作包在其输入和设计范围内通过方法及真实数据核对；跨数据只使用明确对应关系；独立验证来源成立；没有证据显示缺失，不能用零值代替未知。

**边界**：不一次承诺任意组学、任意原始格式、任意建模；轨迹、通讯、结构预测、分子对接和其他专用算法需单独确认范围。特征表导入不自动算作特征提取工具已完成。

### 10.7 第六批 CR-B06 完整写作与交付

**目标**：补齐 SCI 和毕业论文的完整业务要求及最终交付规格。

**范围**：

- 原始研究、简报、综述、方法论文的结构和证据合同。
- 完整稿、指定章节、结果讨论、扩充重构、润色及按意见修订。

- 学校章节、范围、摘要、缩略词、附录、成果、致谢、盲审及最终模板检查。

**验收门槛**：各交付类型和写作模式逐项核对；真实模型和双语质量有独立证据；学校/期刊约束及已知限制可查；Word 和 PDF 实际检查；图表、正文、引用、数据和代码版本一致。

**边界**：不承诺投稿录用、学位通过、机制实验成立或不同软件分页完全一致；缺失材料、未支持语言及真实验证未完成项继续保留。

## 11 验证 复核与验收

### 11.1 分开记录证据

| 证据层次 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 静态源码和合同核对 | 是否存在入口、字段和规则 | 实际运行、真实材料及用户验收 |
| 合成/离线工程测试 | 权限、版本、错误、任务和来源等行为 | 真实数据、模型质量和科研结论 |
| 真实本地数据执行 | 真实格式、规模、工具和产物链可运行 | 方法适用性、重复设计和结论正确性 |
| 独立数值及方法复核 | 在明确合同内的数值、口径和统计行为 | 所有数据集、所有方法和因果解释 |
| 真实模型及外部证据验证 | 对已批准材料的实际写作/检索表现 | 未执行的其他模型、语言和研究范围 |
| 用户统一验收 | 用户认可明确交付范围 | 自动升级为完整产品、生产发布或科研认证 |

### 11.2 各批共同检查

1. **需求覆盖**：逐项列出本批 CR 编号、来源、实现入口、证据、限制和验收决定。
2. **权限与隔离**：上传、数据集、分析、图、稿件、报告和下载按项目归属核对；管理员不获得研究内容旁路。
3. **版本与恢复**：任务恢复、刷新、同名文件、配置变化和候选发布保持正确身份；未知外部调用不重复提交。
4. **数据保留**：原件、历史样例、旧结果和备份保留；新增资源有明确归属，不触发自动清理。
5. **真实输入和负例**：用该批支持格式核对有效、缺成员、维度不符、设计缺失和已发现错误，不为假设场景无限增加保护。
6. **图表和文档目视检查**：核对标注、色标、方向、面板、中文、字体、缺图、裁切、分页和对应关系。
7. **语言与交互**：核对新增文案、草稿、错误、加载、重试、失权及深链，不把局部双语当全库语言已穷尽。
8. **范围验证**：按变更影响运行必要检查；已经通过且相关代码未变的测试不重复跑，不默认全量回归。

资源或环境受阻的测试记录为受阻，不能算通过。不得为了补齐通过数擅自安装依赖、启动容器或扩大发生费用的范围。

### 11.3 生信专项验证

- 小型可人工核对数据用于维度、条码、变换、方向和数量对账；真实 GSE 用于格式和完整流程。
- 对适用统计使用独立参照或已知输入核对结果，声明比较容差；不能仅重复调用同一实现形成自证。
- 固定随机种子、线程与环境；说明哪些结果允许数值容差或算法非确定性，图像字节一致不是所有流程的默认要求。
- 矩阵和图像核对包括轴顺序、坐标、尺度、组织内标志、过滤集合和特征 ID。
- 观察单位和独立重复的正确性由研究设计复核，不能只靠数据行数检查。
- 质控和阈值结果按完整数据口径产生，预览抽样不能作为正式计算输入而不说明。

### 11.4 进入下一批的条件

本批范围内必需项已实现并具备对应证据；遗留项明确标注承接或等待条件；用户统一验收通过。新一批先出实施方案，用户确认后再执行。

如果只确认部分交付，记录部分验收和剩余项，不将整个批次或整类组学标为完成。一次方案确认不自动授权后续真实/付费调用、提交、推送、发布或清理。
