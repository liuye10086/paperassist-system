### 3.1 AWS（保留历史研究，不再作为当前开户路线） 的已知限制

- Ready2Run 官方目录中三条 scRNA 流程各有 119 GiB 输入上限，不能由本平台提高；目录估计时长不是本项目性能承诺。
- 目录证明流程存在，不证明它支持所有 10x 3′/5′、Flex、VDJ、Multiome 或非 10x 建库；不得从最新版 nf-core 功能倒推 AWS 部署版本。
- 查询使用 `ListWorkflows(type='READY2RUN')`、`GetWorkflow`、`ListWorkflowVersions`；不猜 workflow ID、版本名称或参数名。
- `StartRun.requestId` 是幂等标识；本地仍永久保存相同请求的 token 和参数摘要，不假定云端去重期限无限。
- 输出以 GetRun 的 `runOutputUri` 为准，不凭输入的 outputUri 拼接真实结果位置。
- 官方默认配额包括动态存储 50 个并发 run、静态 10 个、每 run 25 个并发 task、最长 604800 秒、StartRun 5 TPS；实际账号可用额度未验证。本项目首期限制每项目一个活跃 run，逐样本调度。
- 新加坡 Ready2Run 有官方地域支持记录；当前 STARsolo 是否在拟用账号/地域可列出并运行，仍未验证。
- 不再面向新客户开放的 variant/annotation stores 属于 Analytics，不应误写为 Workflows 停服。

### 3.2 Cell Ranger 保留方案

保留统一提供商接口和 `cellranger` 流程类型，但不宣称已有可执行云应用。若以后启用：注册固定版本的私有工作流，使用合规的镜像/工具和参考；单独检查 10x 授权、再分发和代客户处理范围。兼容单文库 count 与 Flex/multiplex 所需 multi 分开，Multiome 不能混用。默认关闭额外自动/云端注释，避免未经授权上传或改变方法。

## 4. 统一接口与流程注册

统一的是传输、任务控制和产物合同，不是不同实验的生物学参数。

### 4.1 接口边界

服务端提供以下能力：

- `capabilities()`：返回 provider、可配置流程、账号/资源/许可阻塞项及证据等级；不返回密钥。
- `begin_upload()` / `sign_part()` / `list_parts()` / `complete_upload()` / `abort_upload()`：限定项目和文件的云分片上传。
- `submit_run()` / `get_run()` / `cancel_run()`：冻结配置、保存幂等请求与远端 ID、轮询并映射状态。
- `list_outputs()` / `stream_output()`：从已核实 run 输出前缀读取指定文件，拒绝任意用户 URL。
- `collect_outputs()` 与前端矩阵选择：形成受管原件并填入现有导入表单；复用已有候选审核，不增加云端确认页。

下一阶段阿里云适配器映射 CreateRun/GetRun/AbortRun，OSS 提供文件传输；已有 AWS 适配器保留为未启用的历史实现。bulk RNA 使用独立 workflow profile、参数及输出合同，不复用 scRNA 的 barcode/UMI 参数。

### 4.2 受控流程注册表

每个允许执行的 profile 固定：provider、region、workflow type/ID/version、工具及版本、参考身份、物种、platform/chemistry/read structure、参数映射、必需输出角色、资源上限、允许输入总量、许可/账号核验状态。

用户请求仅选择审核过的 profile、样本和上传记录，不可提交任意 workflow ID、角色 ARN、bucket、镜像、命令或参数字典。注册项缺失或未经核对时返回阻塞原因，不用猜测值补齐。

服务端配置独立于原有模型 API 配置。阿里云接入使用 RAM 角色/受限服务端凭据；长期 key 仅在确实需要时通过服务端受限环境配置，不要求用户在聊天中提供。仓库只提交无秘密示例。

## 5. 上传、提交、轮询及回接

1. 用户在平台填写样本/捕获单位、物种、平台、chemistry、供者关系和 FASTQ 对应关系，选择已登记流程。
2. 后端验证项目所有权、允许格式、文件尺寸及总量，创建持久上传会话和唯一对象键。
3. 目标为浏览器按分片直传 OSS（当前已实现的是 S3，需要阿里云适配后启用）；后端签名限定 bucket/key/uploadId/partNumber/有效期；校验按 OSS SDK 能力实现。浏览器不拿长期密钥，不把整份 FASTQ 载入内存。
4. 持久保存 upload ID、已完成分片及完整性信息；刷新后从服务端 ListParts 恢复。重新选择的本地文件必须与会话身份匹配，不能仅比较文件名。
5. CompleteMultipartUpload 前核对分片列表、顺序、范围及总大小；完成后核验 HeadObject 的长度、版本和 checksum。multipart ETag/组合 SHA256 不当作原始全文件 SHA256。
6. 上传完成仅表示字节传输完成，不等于 FASTQ 配对、gzip/read 结构和生物学适用性全部通过；相应预检查在受控工作流或已核实的输入验证步骤执行。
7. 页面展示外部处理与计费说明，用户一次点击提交；后端在事务内冻结输入/工作流/参考/费用授权及 requestId，登记任务，再由现有 outbox 调度。
8. 目标 Worker 在短事务外调用阿里云 CreateRun（已有 AWS 对应 StartRun），成功后保存 run ID。请求超时或回执落库不确定时进入 `submission_unknown`；不能生成新 token 自动再提交。
9. 已有 run ID 只查询状态。短轮询后 defer，将 next poll time 持久化，避免 Worker 长期等待。429/暂时网络失败只重试查询；提供商失败不自动产生新的付费分析。
10. 用户取消先登记意图；提交已发生时调用 AbortRun（已有 AWS 对应 CancelRun） 并继续查询至终态。未知提交结果先核实，不能把本地取消等同远端取消。
11. 远端成功后，检查输出前缀和角色清单，取得 filtered/raw counts（按实际流程）、features/barcodes 或合格 H5、QC、日志和运行元数据。缺失必需输出记为 `bio_cloud_output_invalid`，本地状态 `blocked`；保留远端真实终态。
12. 结果按配额流式下载到受管存储，核对大小/哈希；关联 provider/run、工作流版本、样本、参考与原始输入记录。
13. 接回现有 `BioDatasetService.create` 和 SingleCellImportRequest v4，沿用既有导入候选审核；之后复用现有下游计算和报告入口。

页面主状态：未配置/阻塞、上传中、待提交、排队中、分析中、获取/验证结果、完成、失败、取消中、已取消。内部同时保存 provider 原始状态、提交未知状态、任务 revision、错误代码及下一步操作。禁止将上传完成或 provider success 直接映射成整个研究完成。

## 6. 可靠性、权限与费用控制

### 6.1 幂等与恢复

- 同项目 Idempotency-Key 对应同请求摘要；同 key 不同内容返回 409。
- 使用数据库唯一约束、任务租约及 revision fencing；不用内存字典承担幂等和恢复。
- 提交身份先落库，receipt 后落库。未知提交不自动换 token；恢复时查同身份远端记录或使用经核实的同 token 重放策略。不得声称跨网络天然 exactly-once。
- 查询可以退避重试；真实计算重跑必须形成显式新 attempt/费用授权，不能把一次 failed run 当普通网络失败。
- 上传完成回执未知时查询对象及 multipart 状态，不直接新建同名上传并覆盖。
- 用户关闭浏览器不会取消已接受的云任务；后台状态继续持久更新。
- callbacks 非首期依赖；未来接入时验证签名、重放窗口及事件去重，轮询仍作补偿。

### 6.2 数据与凭据

- 每次读写都验证 owner/project；签名 URL 对应单对象/单分片，短期有效。错误信息和日志不输出凭据、签名 URL 或完整提供商响应中的敏感字段。
- 输入对象键由服务端生成，启用版本/身份核对；提交前确认对象未变。远端结果限定为已登记输出 bucket/prefix 下的对象，不接受任意下载 URL。
- 保留实际使用的输入版本/校验类型及输出哈希；不能把 provider ETag 伪装成 SHA256。
- 采用服务端与执行角色权限分离、最小 bucket 前缀权限和日志权限。具体 IAM、存储加密、CORS及保留期在账号初始化清单中核验。

- 取消任务不自动删除已上传原件或现有研究结果。云存储保留及清理按另行确认的生命周期策略执行。
