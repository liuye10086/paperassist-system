## 3. 图型语义：推荐合同

### 3.1 保留独立确认，不把新计算藏在外观编辑里

纯配色、尺寸、字体等显示调整只生成配置/图新版本，不改统计结果。新增字段、显示分组、聚合、分母、纳入记录或核密度计算时，先形成**本地描述性投影子计划**：绑定原已确认结果及同一整理版本/工作表，冻结变量、单位、参与行、缺失和聚合规则，展示实际影响，复用现有确认/检查点后执行固定程序，保存独立投影结果及来源。

投影结果是真实计算，不是新的假设检验，也不是未执行的绘图提示。不能把原结果中没有的字段直接塞入云端payload。展示原统计结论的图严格使用原统计有效行；独立描述性投影则继承已确认的研究人群/选区，按自身字段确定有效行，单独保存并显示投影n及排除原因，不借用或改写原统计n。只有改变原统计结论使用的变量、选区或样本口径，才须重新确认分析计划并产生新的统计结果；描述性投影不能替代原方法重算。图表配置确认、外发材料确认和预算准入各有用途，互不替代。

复用的是确认、决定、检查点和恢复机制，**投影确认采用独立类型/来源引用及发布路径，不调用会更新`analysis_setups`的旧计划发布函数，也不伪装成`confirmed_analysis_plans`的新统计计划**。批准回执、冻结配置与投影结果按租约和事务绑定，不能因编辑图表改变当前统计配置或使其它任务无故失效。

新增折线、小提琴和分组柱状统一采用：分组字段缺失/非法默认阻断；用户可在投影子计划明确选择排除并确认实际行数，或补数据形成新版本，不自动合成“缺失组”。选区中的其它缺失处理按下表显式展示并确认。散点沿用原相关有效行，不能借此排除规则悄悄删点。

### 3.2 新增及补齐图型

| 图型 | 推荐明确口径 |
| --- | --- |
| 热力图 | 复用共同完整记录的Pearson/Spearman矩阵，保存行列变量顺序、n、固定`[-1,1]`发散色带、零点、可见色标/刻度及系数标签。保持探索性矩阵，不增加P、区间、显著性星号、聚类或插补。 |
| 散点图 | X/Y与原相关的全部有效记录保持一致；可加一个分类字段作显示分组，但这些行必须都有合法组值。缺组值默认阻断，不悄悄删点后沿用旧n/r。补数据用新数据版本；缩小选区须重新确认并重算相关。分组不自动新增组内检验，推荐首轮不画拟合线。 |
| 折线图 | 一个明确时间/有限数值/有序类别X，一个数值Y，可选分类分组。时间/数值按值排序，有序类别由用户给顺序，不默认Excel行序为时间。默认同组同X唯一；重复时阻断，只有预先选择“同组同X算术均值”才聚合，保存原行、有效n及缺失数。已知X的Y缺失保留空位断线，聚合桶全缺失也断线；部分有效按有效值均值。X缺失列入排除审计，不插值、填零、平滑或外推。无记录的时点不自行认定为缺失；固定随访时点需明确预期时点后才判断空位。本批不增加个体轨迹或重复测量推断。 |
| 柱状图 | 预先选择计数、比例或均值。计数单位为纳入记录，不默认等于独立人数；比例固定为“当前组内各类别有效记录数/该组全部有效类别记录数”，无分组用总体分母，显示分母及缺失排除。默认展示全部纳入类别，组内合计100%。限定类别必须作为投影人群过滤重新明确确认，分母只取确认后的类别集合并在图注写明：如A/B/C为20/30/50，明确仅纳入A/B后为40%/60%，不是保持总体分母的20%/30%。不提供纯显示隐藏类别后改变分母的操作；不加权、不累计。均值显示有效n，默认无误差线，可选实际样本SD（`ddof=1`），n不足时显示空值原因。只有同一估计量、同一记录口径的已算区间可复用，不能把回归系数区间当均值区间；计数/比例不新算推断区间。 |
| 小提琴图 | 固定一维高斯KDE、Scott带宽、等权记录；每组至少3条且方差大于0作为首轮产品支持门槛，不能称为统计有效性的普遍定理。保存每组n、带宽、观测范围、256点网格与密度，叠加中位数/Q1/Q3。各组使用同一密度到宽度的比例，不按n放大宽度；展示截于各组观测范围，不重归一为新概率，不作边界校正，图注说明平滑与截断。常量/不足组明确拒绝密度图并提示可选箱线，不自动换图。 |

小提琴带宽建议依据[现有SciPy组件的高斯KDE与Scott规则说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.gaussian_kde.html)；该参考仅用于算法设计，不表示升级项目已锁定的SciPy版本。带宽影响平滑程度，不能把平滑外观解释成独立研究结论。

已有箱线、森林、ROC、KM接入统一配置/图注/编号；保留各自原方法与来源守卫。森林只用实际OLS系数/Logistic OR，ROC只用冻结评分，KM仍为右删失估计。配对连接图继续独立回归验证。

### 3.3 固定计算及外发材料

本地只运行受限固定代码，独立保存期望值与排除来源；不运行模型生成代码。新增投影使用既有科学计算依赖，未发现必须新增统计库的理由；若实现核查发现必须增加依赖，先说明用途，不一次安装候选库。

| 图型 | 最小外发材料与核验方式 |
| --- | --- |
| 热力/散点 | 已确认的必要成对数值/矩阵输入及脱敏显示分组；期望系数和完整核对结果留本地，按现有云端独立计算边界核对。 |
| 折线 | 必要的脱敏X/Y/组值、确认顺序/聚合/缺失规则；云端计算绘图序列，本地核对每个点、n、顺序及断线位置。日期若需平移须显式确认且本地/云端一致，不擅自改变数据。 |
| 柱状 | 必要类别/组值或数值、冻结分母/聚合/误差线规则；独立核对计数、比例、均值、SD及参与记录口径。 |
| 小提琴 | 必要匿名数值/组标签及固定核密度规则；本地期望密度不作为云端计算答案，独立核对网格、带宽、密度及叠加统计。 |
| 已有方法图 | 继续原披露合同；森林为已计算效应的绘图一致性核验，不能改称云端独立拟合。 |

原文件、主体ID、来源坐标、无关列和本地核对答案不加入新payload；分类标签、日期及自填标题也可能含敏感内容，继续逐次预览/脱敏。中文/英文标题、单位、图例和说明使用冻结任务语言。

继续既有绘图/解释模型`gpt-5.6-sol`及已确认额度：绘图任务1美元、解释0.5美元，既有用户/测试项目累计各5美元；保留实际历史消耗，不能重置或把准入预留当供应商硬扣费上限。新图/改图可能增加调用次数；自动测试不付费，不默认这笔余额足够生成全部验收图。真实外发由用户在应用确认材料及现有预算后触发；不足或未知费用按既有等待/核对流程处理。

## 4. 编辑与图号：推荐合同

- 允许标题、显示别名、补充图注、预设配色、合理尺寸/字体及显示顺序；保留原字段到别名的映射。方法、真实数值、误差线语义、参考线、统计标记和单位含义受程序约束，不能任意改点、删异常或补显著性。单位文字不隐含数值换算；语义变化回到投影或分析计划确认。
- 用户自填说明记录作者与来源，不能冒充程序已核验的统计事实；数值/统计标记由事实引用填入。自由文字的科学含义仍需用户审阅，不宣称程序能证明所有标题和图注语义正确。
- 保存配置不调用模型；点击生成前说明本次重绘材料与可能费用。新图拥有新ID与PNG，旧图、原解释、Word保持。配置版本和renderer版本分别保存，不把配置哈希塞入renderer字段规避唯一键。
- **新PNG不烧录可变报告序号**，但保留图标题、坐标/单位、图例及适用数值。独立图的图号作用域是自身成果包；报告中图号作用域是该集合版本，按顺序冻结“图1、图2……”。图旁、图注、预览、Word及正文引用消费同一编号映射；不盲替换旧正文的“图1”。
- 默认独立下载提供原PNG和紧邻绑定的说明文件组成成果包，说明含图号/标题/图注/缩写/统计标记及来源；同时保留原PNG单独下载。成果包不是额外图格式，PNG基线不变。Word直接嵌入原PNG字节，图号/图注置于图旁，不重新绘制、压缩或裁改像素。
- 历史PNG和历史Word原样可读可下载。带固定旧编号且会冲突的旧图不悄悄纳入规范新集合；明确提示生成兼容新合同的图版本，沿外发/预算流程由用户主动触发。未重生成时继续使用历史报告，不暗中改图或收费。
- 仅颜色/尺寸/字体等纯样式变化且事实摘要完全一致时，可建立**新的解释记录/绑定**复用已有六节文字，记录`derived_from`和兼容核验依据，并指向新figure ID及SHA；不沿用旧解释ID冒充新图，不伪造新的模型回执。标题、变量别名、图注或数据语义改变时，重新检查事实及文字引用；无法证明兼容就提示重新解释，收费调用仍由用户确认触发。

备选是把最终报告编号写入PNG，但重排也可能需要新图及费用。推荐编号解耦，降低无关重绘；自由画布、任意脚本和SVG继续后续。

## 5. 报告集合与自动整理：推荐合同

### 集合范围与来源

首轮限定同用户、同项目、同一不可变整理数据版本/工作表、同语言，允许多个已确认计划/结果、每结果多图。同源不要求共用当前`setup_revision`；用户可显式选择来源完整可核验的历史计划结果。没有已确认计划引用的早期成果继续按旧入口读取，不伪造确认记录来加入新流程。

每项冻结实际计划/结果/投影/配置/图/解释版本和哈希、顺序及图注。新版本可用只提示“有更新”，不自动替换旧项；来源损坏、越权或事实不一致才阻断。用户决定替换内容后生成新集合版本，不能把“不是最新”与“来源无效”混为一谈。

同一图在一个集合版本中不重复计入，不同图可以共享同一统计结果。数据概况按来源去重；各结果保留各自有效n/排除口径，不相加n冒充主体总人数，不跨结果生成新P或合并效应。

### 九类内容与解释

统一预览数据概况、数据质量、处理方式、分析方法、统计结果、带标签图表、逐图/结果六节解释、主要发现、分析总结；同时显示局限和待补充项。只消费实际已有的ProfileScan、整理/排除回执和结果，不以“未删除异常”冒充完整质量策略，不杜撰未扫描的字段质量。

每个重要结果必须有来源对应的六节解释；同一结果的多个纯样式图可共享事实基础但各自绑定。没有解释或存在事实冲突时明确待补充，不静默跳过。主要发现和总结先用已核验事实及已保存解释本地组织，互相矛盾或异质的结果分别列出，不生成新的因果结论或付费总评。

### 自动化与版本

用户选定内容、顺序并保存启用集合后，所需图与解释齐备即自动本地生成Word；单结果保留快捷默认集合。没有集合时不能扫描全项目替用户自动选结果。

自动意图与依赖持久化，等待不占Worker；解释发布推进依赖，同时由后台补偿扫描恢复“解释已发布但推进进程退出”的窗口。齐备后锁定请求、重新校验、冻结最终快照，并在同一事务写任务/事件/outbox。浏览器轮询只读状态，不承担唯一触发责任。

自动首次导出为该集合版本的第1个导出版本；同请求重试仍是同一导出，不重复发布。显式“生成新版报告”产生新的导出版本和请求键，即便输入未变也保留此次导出意图；连续点击同一请求保持幂等。集合修改则产生新集合版本，旧任务迟到完成只能发布历史成果，不能覆盖当前指针。

自动整理只执行本地Word，不自动创建收费图或解释任务。跨数据版本/工作表/语言综合报告作为可选扩大范围，需另定来源分层、主体重叠与翻译口径；不默认纳入A，也不删除其后续需求。

## 6. 推荐迁移与数据保留方案

### 6.1 结构建议，尚未编写DDL

| 对象 | 推荐持久内容与约束 |
| --- | --- |

| `figure_projection_results` | 已确认子计划的输入/行来源、规则、实际固定计算结果、工具版本及摘要；按确认配置和工具版本幂等。样式版本可显式复用同一投影，不重复计算或改写原统计结果。 |

| `report_collections`及`report_collection_versions` | 集合身份/当前指针与不可变版本分开；版本冻结来源、语言、选项和顺序摘要，`(collection_id, revision)`唯一。 |

| `report_build_requests` | 持久自动意图、依赖状态、导出revision、幂等键、任务引用及齐备时冻结的完整输入快照。按集合版本/renderer/导出revision唯一，同次请求输入摘要冲突拒绝。 |
| `collection_reports` | 独立保存新集合报告、导出版本、完整input_json、元数据、SHA与资产引用，build request唯一。旧`reports`表及唯一键、旧下载链保留。 |

新的本地投影/集合报告消费者需要相应任务合同或workflow版本、输出引用及数据库CHECK扩展；复用任务/outbox/租约/恢复实现，不新建队列框架。绘图和解释继续既有模型政策/预算边界；新增本地消费者不产生模型费用。所有新表进入metadata、审计和运行角色权限白名单，运行角色不获DDL权限。

同时扩展`file_lifecycle/references.py`、`lineage.py`及相应审计：将图配置、投影、集合/集合报告、等待依赖但尚未创建task的导出意图及候选资产纳入文件依赖、重解析影响、任务来源展示和保留/阻塞回执。旧评估回执保留当时快照，新评估按新合同读取；不能只新增外键而漏掉JSON、待办或任务外的引用。

### 6.2 旧图唯一键的明确例外

现有`figures_input_key`若原样保留，会阻止同run/renderer的第二个配置。推荐在事务内只对这项已识别约束进行白名单替换：

```text
legacy唯一性：(analysis_run_id, renderer_version)
              WHERE figure_config_version_id IS NULL
新配置唯一性：(figure_config_version_id, renderer_version)
              WHERE figure_config_version_id IS NOT NULL
```

保留的是旧行值与legacy唯一性语义，**不是声称130个旧索引全部原样不变**。删除原唯一约束/关联索引并创建上述索引须列入精确差异白名单；其余旧索引不变。部分唯一索引可限制指定行集合，参见[PostgreSQL官方说明](https://www.postgresql.org/docs/current/indexes-partial.html)。

同时修正所有legacy按run/renderer读取，显式只取NULL配置；新查询必须带配置版本或figure ID。`storage.py`、旧成果保存、图任务缓存/候选发布及`ON CONFLICT`路径均纳入审查，不能只改DDL。另建整套figure成果表虽可保留旧索引，却会迫使解释和任务FK双轨，不推荐。

新配置图/集合使用独立版本化来源解析，允许已确认且完整可核验的冻结历史结果；按其自身计划/数据/资产核验，不要求每项等于当前setup。旧单图API的当前配置门禁保持，不全局放宽来源保护。创建、执行、发布、下载均逐项检查项目归属、active用户、完整来源与哈希。

### 6.3 实际迁移前后流程

1. **隔离验证先行。**在`paperassist_system_test`与随机`pa_test_<32hex>` schema/临时资产中构造独立合成旧记录，验证0025→新revision、历史读取、唯一性、并发、权限和失败恢复；不把开发真实数据复制进自动业务测试，不使用真实账号。
2. **冻结迁移清单。**列出实际新增表/列/约束/索引、允许替换的唯一约束和源码SHA；与方案比较。业务范围或保留策略有实质变化再集中说明，常规实现不逐项请求确认。
3. **确认全部writer停止。**API/Vite、Worker、dispatcher、RabbitMQ及其它本项目写入者均独立核验；当前Docker状态不可读时不得迁移。读取最新迁移及任务状态，不能复用今天的静态快照当迁移现场证据。
4. **成套备份。**沿用一致性数据库快照＋`pg_dump`归档、`pg_restore --list`目录检查及归档SHA；同时复制全部资产并逐项SHA核对，保留schema/索引/序列/权限清单、迁移清单与必要私有配置备份。私有内容只在既有忽略目录，不打印密钥或写入Git。旧备份不删除；`--list`不冒称另库恢复演练。
5. **有界事务升级。**校验目标库/schema/revision及迁移账号，设置锁等待/语句超时。备份失败、写入未停止、旧指纹变化或未列入白名单的差异均停止，不能绕过核验。旧列投影指纹必须一致；新增NULL列不能拿全行指纹直接与旧快照相比。新表不自动写入业务样本或伪造历史确认记录。
6. **提交前后复核。**确认旧ID、旧JSON和所有原列值保持，索引差异仅来自白名单，运行角色权限/审计通过，原件及历史图/解释/Word字节完整。旧任务、决定、检查点、费用/预留/未知调用和新旧资产全部保留。新增索引有效且ready；数据库/资产备份相互对应。
7. **失败保留。**事务提交前失败回滚该迁移事务；提交后核验失败停止交付，保留备份、当前库和诊断。运行回退优先关闭新入口/派发并保留兼容读取，不自动恢复旧备份覆盖新数据。新业务已产生时downgrade必须拒绝删除新表/列；现有代码要求精确schema head，不能承诺旧二进制直接运行。确需恢复时先保全新增资料，再单独给出具体恢复方案。

迁移会增加结构和新成果，预期总表/索引/资产数可能增长；核验目标是原数据与旧成果保持及增量差异准确，而非机械要求总数永远不变。没有自动删除期限或物理清理，统一实际清理仍留阶段10。
