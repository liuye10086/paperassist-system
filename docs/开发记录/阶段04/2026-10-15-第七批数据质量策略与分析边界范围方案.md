## 三项需要集中决定的处理规则

推荐三项均采用A。确认这些规则是因为它们决定哪些记录进入分析；具体版本字段、分页、错误码、测试组织及常规修复由批内连续完成，不另拆审批。

| 决策 | 推荐A | 其它选择及取舍 |
| --- | --- | --- |
| 缺失值 | 整理阶段不填补；沿用已确认的逐字段修剪/缺失标记。缺失记录仍保留，各分析计划只按自身所选变量执行已批准的完整记录/完整对规则。 | B：本批加入指定填补。必须另外明确算法、适用变量、参数和统计影响，实施范围明显扩大；不能用默认均值代替用户决定。 |
| 异常值/人工排除 | IQR只作候选提示，默认保留。允许用户明确选定源行、填写理由，预览后确认全行排除；理由标为用户声明。 | B：仅提示，本批不提供人工排除。更保守，但确认有误的记录仍需从外部修正后重新上传。 |
| 重复值 | 默认保留；可选当前版本全部字段的类型敏感整行精确去重，保留仍有效的最小源行号。 | B：仅提示，本批不提供去重。按主体ID、最新时间、近似值或跨来源去重均不在A/B范围内。 |

推荐A的确切含义：

- 不按IQR、模型残差、P值或诊断自动删行，不进行缩尾、单位换算、文本转数值或猜测日期；不通过整理绕过研究设计、类型或方法前提检查。
- 重复比较覆盖当前版本矩形的**全部字段**，不是某个分析临时选中的列；在确认的字段处理完成后比较。数值用Decimal值比较，`number 1`与`number 1.0`等价；`text "1"`、`number 1`、`boolean true`各不相同，非空文本区分大小写。缺格、空白与纯空白文本沿用现有质量检测的缺失等价规则，明确显示此规则；只有启用修剪时，`" A "`才会变成`"A"`。不执行额外隐式转换。
- 全空行不自动归入重复组，仍保留或由用户明确选行排除。所谓“保留首条”是保留本轮手选排除之后仍有效的第一条，不是无条件保留原组首条。
- 当前版本中已经排除的行不会因后续选择“保留”而恢复。恢复须从尚含该行的更早版本另派生，或走既有原始整理入口；结构变更只走原始整理入口。旧版本始终可读。
- 关闭本轮修剪或缺失标记只停止新增处理，不还原父版本已经修剪或标记缺失的单元格；恢复原值须从尚含原值的更早版本派生或走原始整理入口。
- 整理保留源行数为0时阻断发布，保留草稿、预览与决定历史；仍有保留源行但某方法没有完整有效记录时，由该方法的计划检查阻断。

## 实际业务流程与数量口径

### 一、从已发布整理版本继续处理

原始Excel继续走已有整理入口。第七批新增“按此版本处理质量问题”，以一个已发布整理版本为直接父版本；冻结该版本的有效数据、字段、单位、原始矩形及来源，不自动取最新版本。继承字段身份和结构；改表头、扩大范围仍走现有原始整理入口。

固定顺序：读取并核对父版本 → 继承有效源行 → 排除本轮明确选择的行 → 对剩余行执行修剪、再执行精确缺失标记 → 对处理后的剩余行执行所选去重 → 重新计算质量概况。先手选排除再去重，避免首条被去重保留后又被排除而导致整组消失。

“处理前”概况指直接父版本有效行在本轮手选排除之前的状态；“处理后”指新版本有效行。原始root的区域数量和累计排除另外列出，继承排除通过不可变父回执追溯；多轮派生不把直接父版本记录数误称为原始记录数。

### 二、确认完整影响，而非确认前20项

沿用现有持久等待、修订号、候选输入摘要、用户决定、幂等发布和Worker释放。修改规则后原预览失效，重新生成完整预览才可确认；旧revision、迟到决定、错误来源或篡改回执均拒绝。

页面给出汇总及每页20项的完整影响分页，支持按操作/原因筛选、真实来源定位和完整明细下载。每项保留源行或单元格坐标、操作、理由、处理前后值或可核验父记录引用；重复排除另存保留源行。下载受现有用户/项目权限控制，按需读取并下载已冻结的完整回执，不重新计算回执。

同一单元格经历修剪再变成缺失，只算一个变化单元格，可保留两个有序操作。因后续去重被排除的行上的单元格变化与最终保留数据变化分开计数。实际排除按源行集合计数，候选命中不等于实际删除；一行命中多原因只扣一次。

数量统一为：

1. 原始选定区域记录数 − 累计整理排除 = 当前整理保留记录数。
2. 当前整理保留记录数 − 本分析实际排除 = 本分析有效记录/完整对。
3. 累计整理排除拆分为继承、本轮手选、本轮重复，类别按固定执行顺序互斥；多重候选原因另保留，不重复加总。

缺失单元格数、缺失行数、异常候选数、重复组成员数和重复额外行数分别命名。有效n不一概称为“人数”；Wilcoxon零差值仍属完整对，KM事件/删失也不是额外排除。每个方法保留已批准的统计语义。

### 三、新版本必须再次确认分析计划

发布后产生新的整理版本；可复制旧分析选择为候选，但必须重新检查字段、类型、单位、组/配对ID、完整记录数和设计声明，并独立确认。整理确认不替代计划确认或外发/预算确认。

所有消费者统一读取显式有效源行：字段概况、资料定位、描述/相关/比较/回归/ROC/KM、图表投影、解释事实和报告。特别覆盖柱状、折线、小提琴图的描述性投影，防止排除记录重新进入图表。

本批不增加云端资料范围。完整影响明细、原始坐标及人工理由保留本地；云端绘图/解释只沿用既有授权的脱敏材料契约与确认流程。新来源必须生成新材料和来源摘要，不能复用旧确认。自动验证使用替身，不触发真实付费调用。

### 四、同源成果与中英文界面

复用现有科研工作台，在质量区、规则表单、影响确认、版本历史和计划审核中增加相关信息；保留当前简洁样式。显示可读版本与源坐标，不把内部UUID、哈希或规则编号作为用户决策信息。用户自填理由、字段和研究原文不自动改写或翻译。

报告冻结该版本的处理前后概况、批准策略、实际影响摘要和回执引用。Word给出易读摘要与理由，完整明细在应用中可下载；不把数万条明细强行塞入正文。同一整理版本的不同计划可以有不同n，逐计划展示；不同整理版本继续拒绝放入同一集合，即使原始文件相同。

修正单图Word的固定“未去重/未删异常”文案，区分整理阶段与统计阶段。旧v1无完整明细时说明“旧版本未记录此明细”，不能编造零处理。旧成果和旧报告快照保持原值，不用新质量算法反向重建旧合同导致旧集合失效。

## 现有方法边界与资源验证

本批支撑工作是让新质量版本安全进入现有方法，补齐边界矩阵与有界执行，不改变统计清单或提高容量。以下是静态核对的代码合同/默认值，不是本机运行时容量承诺；多个维度不能默认同时取满。

| 方法 | 保留的规模/关键边界 |
| --- | --- |
| 描述统计 | 无独立10000行限制；继承来源对象/坐标限制。1数值列＋可选1组列，最多20有效组；1完整行可返回部分指标，常量合法。 |
| Pearson、Spearman | 共同完整记录3—10000；pair两列，matrix为2—10列；常量/近常量拒绝。保留Spearman精确/固定Monte Carlo/渐近分支。 |
| 独立Welch t、Mann–Whitney U | 纳入观察合计最多10000，每组至少3；两个参与组。秩方法的常量组语义不改成一律拒绝。 |
| 配对t、Wilcoxon | 完整对3—10000；宽表ID与有序两测量。ID非空唯一、零差值/退化差值按各方法既定规则处理。 |
| 多组Welch、Kruskal–Wallis | 纳入观察合计最多10000；3—6组，每组分别至少3/5；既定全组对Holm最多15对。 |
| OLS、二元Logistic | 原始选定来源矩形最多10000行，不能用质量排除绕过；1—8原始协变量，分类2—6水平，展开斜率最多20。样本下限、编码/参考组、分离、秩亏和收敛守卫保留。 |
| ROC/AUC、右删失KM | 同样先限制来源矩形最多10000行；ROC保留编码/方向/评估角色要求；KM保留ID、时间、事件和最多6组边界。ROC常量分数、KM全删失按已批准语义返回并说明缺指标。 |

质量排除后的ID检查针对当前保留记录，但必须明确展示上游排除及理由；质量操作不证明剩余记录满足独立性。不同方法的“10000行”分别是纳入行/完整对或源矩形，界面和错误不能统一改写为“10000有效行”。来源合同另有4MiB对象、100000行坐标等限制；实际上传配置在实施时核查，不直接将配置默认值当产品保证。
