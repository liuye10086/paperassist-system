## 3 科学计算合同

### 3.1 先冻结比较设计

每个比较必须保存 `contrast_id`、显示名、`numerator`、`denominator`、输入数据／处理／映射／区域版本、物种、特征命名空间、统计单位、独立重复依据、方法、过滤、校正范围和分析目的。

- 统一方向是 **numerator 相对 denominator**。正效应为 numerator 更高；交换两组产生新计划和新结果。
- “其余区域”按所选固定观测全集求补集，保存实际 barcode 列表／哈希；不随着上游新版改变。
- 多个来源的观测键为 `(processed_version_id, barcode)`，不凭同名 barcode 合并。
- H5/MTX 同一数据的重复表示不得重复计为独立输入。来源样本、canonical 身份及用户对应表共同检查。
- 多数据集要求同物种和明确参考／基因 ID 版本兼容。基因轴采用显式共同稳定 ID；非共同基因列入排除表，禁止按 symbol 静默合并。
- 区域重叠时阻断两组比较，直到明确无重叠的分配；未分配 spot 留在排除表，不自动归入对照。
- 多重比较族冻结比较 ID 集合；新增比较生成新计划并重新生成该族结果，不能把新比较插入旧 q 值。

### 3.2 空间区域探索

支持同一已处理空间数据中的固定 cluster／区域比较；不重新执行 QC、PCA、UMAP 或聚类。

1. 检验输入为已冻结的 `log1p` 层；按基因执行双侧秩和检验，记录 tie correction 及无 continuity correction 的具体算法合同。
2. 两侧至少 3 个 spot 为本产品计算门槛；不把它表述为独立重复充分或统计功效达标。
3. 效应为 `log2((mean_normalized_numerator + 1e-9)/(mean_normalized_denominator + 1e-9))`，字段名为 `effect_log2_normalized`，保留均值、counts>0 检出率和两侧 spot 数。
4. 输出全部比较特征，常量、样本不足等用数值 null + `not_computable_reason`；不把 NA 写成 0。
5. 前端、表格、图注、报告和事实稿统一携带 `inference_scope=spot_exploratory`。基于同一表达数据聚类再比较须额外标记 `data_driven_grouping=true`，P/q 仅作探索性排序，不包装为独立验证。
6. p=0 的数值下溢保留原始结果及说明；图用显式显示下限，不能把绘图裁剪值写回结果表。

### 3.3 有独立供体重复的比较

对选定且通过质控的 spot，回到原始整数 counts，按已确认的供体和条件聚合；不对 log1p、TPM、FPKM 或归一化小数求和后冒充 counts。

| 设计 | 聚合与公式 | 提交门槛 |
| --- | --- | --- |
| 非配对 | 同一固定区域／分层内，每供体一个独立聚合样本；`~ condition`，或 `~ batch + condition` | 每组至少 3 个独立供体；供体不能跨两个条件；每个聚合单元条件与批次唯一 |
| 配对区域／条件 | 每供体每条件一个聚合单元；`~ donor + condition` | 至少 3 个完整供体对；缺失配对默认阻断，可在新计划中明确排除不完整供体并留记录 |

这些数量是保守的产品准入规则，不是样本量设计或功效保证。供体独立性须有对应表和人工确认，软件只能检查一致性，不能证明现实中的独立性。将同一供体的切片或组织块拆成多个 donor 不能通过验收。

聚合使用输入的保留 spot，但以原始 Gene Expression 特征为基础，不局限于 HVG 或 Top markers。输出 `pseudobulk_counts.tsv`、聚合单元表、每单元 spot 数及来源列表、共同特征／排除表。默认基因预过滤为聚合总 counts ≥10；全部基因仍在最终差异表中，预过滤行标注原因。

拟固定 PyDESeq2 0.5.4，负二项模型与 Wald 检验，单线程、`low_memory=True`；`size_factors_fit_type='poscounts'`、`refit_cooks=False`、`cooks_filter=True`、`independent_filter=False`。本批不做 LFC shrinkage，输出 `effect_log2fc`、`lfc_se`、`wald_statistic`、`base_mean`、原始 P 和项目统一定义的 q。由项目关闭自适应 independent filtering，以便按已冻结比较族统一校正；不能把输出称为“R DESeq2 默认配置完全一致”。

正式提交前检查：映射已确认、counts 非负整数、零文库、组数、配对、批次混杂、设计矩阵满列秩、残差自由度>0、过滤后特征非空、资源预算。任一不满足返回具体阻断原因；**禁止静默切换为 spot 检验、删除批次项或移除异常供体**。运行中不收敛保留具体行原因／诊断；整体拟合失败不发布完整成功结果。

PyDESeq2 的 counts/metadata、contrast 与过滤参数以其官方合同为依据；本节数量门槛、允许公式和过滤选择是项目设计。[输入与流程](https://pydeseq2.readthedocs.io/en/stable/auto_examples/plot_minimal_pydeseq2_pipeline.html)、[统计参数](https://pydeseq2.readthedocs.io/en/v0.5.4/api/docstrings/pydeseq2.ds.DeseqStats.html)。独立重复与聚合的取舍参考原始研究；不能将其单细胞评估结论自动等同于本客户空间数据已获验证。[Squair 等，2021](https://www.nature.com/articles/s41467-021-25960-2)。

### 3.4 差异结果与多重校正

统一差异表至少包括：`row_key/feature_id/symbol/contrast_id/numerator/denominator/observation_level/inference_scope/effect_name/effect_value/effect_unit/statistic/p_value/q_within_contrast/q_global_family/correction_family_id/n_numerator/n_denominator/test_status/reason/provenance`；供体数与 spot 数使用不同字段。

- 默认决策使用 `q_within_contrast`（BH），并可选择整组比较的 `q_global_family`（BH）。二者独立命名，不覆盖旧 q。
- 比较族分母为预先纳入检验的特征×比较；预过滤排除项不计入。纳入后不可计算项在内部校正向量取 1，输出仍为 null 并保留原因；记录 family size、有效 P 数及 NA 数。
- 不在筛出显著基因或取 Top N 后才做校正。校正数值用手工小例及独立库调用验证，不修改旧 B02 marker 结果口径。[SciPy 校正文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.false_discovery_control.html)。
- 提供默认候选阈值 q≤0.05、|效应|≥1，仅是待确认的筛选初值，不作为通用生物学标准；阈值变更只建立筛选版本，不重新拟合。
- 外部结果的原始 P、原始 q、方法和校正范围单独保留。只有用户声明并确认完整受检全集且 P 列有效时，才可另算 `system_recomputed_q`；不能覆盖或将其称为原工具 q。只提供 Top 表时禁止此重算。

### 3.5 资源、映射与功能分类

资源为项目内不可变版本，分 `gene_sets`、`id_mapping`、`feature_annotation`。保存来源机构／URL、资源名称、release/date、物种 taxonomy ID、ID 命名空间、原文件 SHA、导入器版本、使用依据及再分发范围。接受系统已有文件身份，不接受任意服务器路径、脚本或自动执行内容。

- GO：支持固定 GO-basic OBO 与匹配 GAF 2.2，检查 header 版本、物种、`NOT`、obsolete/alt ID 和 evidence code；默认剔除 `NOT`，保留其他 evidence code 并记录过滤规则。仅按 `is_a`、`part_of` 向上归并，禁止按 `has_part` 或任意关系传播。根 term 不参加富集。[GO 资源要求](https://www.geneontology.org/docs/download-go-annotations/)、[GO 关系规则](https://geneontology.org/docs/ontology-relations/)。
- GO 功能分类支持 namespace（BP/MF/CC）和显式 GO-slim 映射；多标签计数注明不互斥，不把 term 数量当作独立机制数量。
- KEGG：支持具有来源、版本及使用依据的 GMT 或 term-gene 表；资源未准备时显示“资源未配置”。不内置抓取，不自动购买，不以第三方接口存在代替使用依据。是否允许放入交付 ZIP 由资源记录控制。[KEGG 官方使用说明](https://www.genome.jp/kegg/legal.html)。
- 自定义集合：GMT、两列 TSV/CSV 或明确映射的 XLSX；相同 term ID 的名称冲突必须处理，集合内部重复基因去重并记数。
- ID 映射默认接受一对一映射；一对多、过期、未知和跨物种项分别列出。ORA 的多个原始 ID 指向同一目标基因只计一次并保留对应明细；GSEA 的多对一排序冲突默认排除，不能自动选最小 P 或最大效应。
- 不自动跨物种转同源基因，不静默剥去 Ensembl 版本号；如资源明确要求去版本号，作为固定转换规则记录原值、结果及碰撞检查。
- 序列／结构注释保留 `feature_id/field/value/value_type/unit/source/evidence_status`；“无此特征”与“未提供注释”分开。此路径只导入已有注释，不宣称完成特征提取。

资源更新创建新版本并提示下游影响；旧结果继续引用旧资源。公共资源可以按确认后的方案从官方来源读取到本地缓存，计算 worker 始终断网。客户数据和基因列表不上传到外部分析网站。

### 3.6 ORA 与 GSEA

**ORA**：使用单侧超几何富集，`P(X≥k)`。背景默认来自所选比较中纳入检验的基因，经同一映射和去重；前景必须是背景子集。无完整背景的外部 Top 表需要明确背景文件后才能运行，不能默用整个人基因组。[GO 背景原则](https://www.geneontology.org/docs/go-enrichment-analysis/)。

保存 `N/n/K/k`、背景列表、前景列表、命中基因、GeneRatio、BgRatio、enrichment ratio、P、BH q、term 资源版本和排除原因。默认按 contrast×direction×collection 定义校正族；若选择合并多个 collection，先冻结合并成员再联合校正。大小过滤按与背景相交后的集合计算，默认 15–500，可在计划中配置；零命中 term 的 P=1，仍在完整合格 term 表中。前景为空是合法“无候选”结果，返回空图说明和方法记录，不能伪造显著 term。

**GSEA prerank**：使用完整有限有符号排序向量，不先截显著基因。供体路径默认 Wald statistic，探索路径默认秩和 z；外部路径必须明确选取有方向的统计量。未提供效应方向的 P 值列表不能自动转成带符号排名。

拟固定 GSEApy 1.3.1 的 `prerank`，显式 `method='permutation'`、`permutation_num=1000`、`weight=1`、`min_size=15`、`max_size=500`、`threads=1`、`seed=0`、`ascending=None`、`no_plot=True`，只传本地集合，不传在线 library 名称。排序先按 statistic 降序、稳定 ID 升序固定；并列比例和处理规则进入 Methods。全部为零或无法形成有效排序时返回不可计算原因。

保存 ES、NES、nominal P、GSEA 自身 `fdr_q_value`、FWER、leading edge、排序向量、有效集合范围与参数。GSEA 的 FDR 不重命名为 BH；按固定联合集合构建 null 分布，不把分块任务分别算出的 FDR 直接拼接。置换结果为 0 时保留原值与分辨率说明，不声称无限显著或展示超出置换支持的精度。[GSEApy 参数](https://gseapy.readthedocs.io/en/latest/run.html)、[固定版本发布页](https://pypi.org/project/gseapy/1.3.1/)。

### 3.7 候选配方与排序

每个配方引用固定结果版本、比较方向、映射和注释版本。首版支持最多 10 个来源、20 个顺序步骤：

1. 统一稳定 ID 和方向，列明不可比项。
2. 每来源阈值过滤；明确使用原 q、重算 q 或哪一比较族 q。
3. union、intersection、至少 k 个来源出现；每来源对同一候选最多计一次。
4. 同方向、指定包含、指定排除、注释条件；包含列表不能绕过物种／来源／设计限制。未在结果中的指定对象进入单独缺证清单。
5. 输出各步骤输入数、通过数、排除数、具体排除原因，以及每候选每来源的证据、冲突和缺失。

默认优先级为可解释的字典序：同方向支持来源数降序、冲突数升序、预先选定主比较的 q 升序、该比较绝对效应降序、稳定 ID 升序。缺失值置后并保留 unknown；支持来源数不自动叫“独立实验数”。同数据不同阈值／不同格式不重复计支持。

可选加权模式只接受用户预先定义的有限证据项、0–1 量表和固定权重，输出每项分值及加权分子、已知权重覆盖率。必需项未知时总分 null；可选项未知不按 0 代入，展示 `partial_score`，不可与完整分数混排为同一“置信度”。不得从 P/q 转造“成功概率”或从语言模型主观赋分。

### 4.2 必须落在数据库的约束

- 所有行有 owner/project 归属；与项目 FK 保持现有权限结构，跨项目不能仅凭全局 UUID 拼接。
- 版本表 `(root/plan, version, project)` 唯一，父版本属于同一根；计划更新必须匹配 `expected_revision`。
- 请求键同 owner/project/操作唯一；相同键不同 payload 返回冲突，unknown 回查原键，不重新 POST。
- `task_id`、run 和正式结果建立同项目、同 kind 的复合 FK／唯一约束，避免把另一个任务的成功产物贴入当前结果。
- `plan_sources` 每个 source_kind 仅允许对应一个目标 FK：`bio_processed_dataset_version`→`bio_processed_dataset_versions`、`bio_observation_map_version`→`bio_observation_map_versions`、`bio_annotation_version`→`bio_annotation_versions`、`research_design_version`→`research_design_versions`、`bio_resource_version`→`bio_resource_versions`、`bio_insight_result_version`→`bio_insight_result_versions`、`original_file`→`files`。原文件另保存精确 parse version 与 locator。`source_id` 不能作为无 FK 的万能引用。
- 资源与结果 manifest/object/hash 成对，SHA-256 正则、非负 size、成员 key 白名单和唯一性与现有资产规则保持一致。
- 冻结内容禁止更新；仅允许发布前 manifest 从 null 到完整值的既有发布方式。修改阈值、资源、分组或方向均新建版本。
- 草稿的decision为draft；用户确认时建立新的confirmed版本并保存确认人/时间，不原地修改草稿。run只接受confirmed版本，提交时再次检查固定来源与设计；确认动作本身不能绕过阻断。
- JSON 只保存有界配置／摘要，单个配置≤4 MiB；全基因表、barcode 对应、背景和集合均进存储成员，不堆入 JSON。
- 新依赖的文件生命周期采用 RESTRICT／引用阻断，不因删除计划根级联清理已引用成果。

## 8 计算环境、容量与重现

### 8.1 固定环境

建立独立 `/opt/paperassist-bio-insights/bin/python`。基线沿用现有 Python 3.11/Linux 与 NumPy 2.2.6、SciPy 1.16.3、pandas 2.3.3、AnnData 0.12.3，候选新增 `pydeseq2==0.5.4`、`gseapy==1.3.1`。这两个发布版本已核对存在，但与本仓库完整 wheel lock、隔离机制和 2 GiB RSS 的兼容性**尚未验证**。[PyDESeq2 发布说明](https://pypi.org/project/pydeseq2/0.5.4/)。

T01 在独立镜像生成带 SHA 的 Linux wheel lock，并做聚合／拟合／GSEA／绘图及禁止网络／子进程探针。只有通过后，capabilities 才允许执行相应方法；若依赖无法与固定主版本兼容，先记录实际冲突并调整方案，不擅自升级 B02/B03 环境或关闭隔离。原科学环境和旧 image 保留。

### 8.2 首版容量合同

以下为产品受控上限，不是声称全部上限组合都已跑通；T01/T09 会记录实际可运行规模和峰值，超限在提交前阻断，不静默抽样或截断。

| 对象 | 计划门槛 |
| --- | --- |
| 原空间输入 | 每任务合计≤20,000 spot、100,000 特征、10,000,000 非零项；每次读取采用稀疏／分块 |
| 聚合数据 | ≤200 个聚合单元，稠密值≤20,000,000；最多 10 比较，特征×比较≤1,000,000 |

### 8.3 重现包

每条完成路径包含：输入正式来源及 SHA、冻结计划、观测/聚合对应、资源 release 和许可范围、映射／排除表、完整结果、背景或排序、方法参数、环境 lock/digest、代码版本摘要、随机种子、图配置和 plot-data、manifest 与校验脚本。

包提供 `verify`（离线身份和表计数）、`recompute`（使用固定输入和环境重新计算）、`render`（只重绘）三个明确操作。重绘不得调用比较／富集引擎。新结果写独立目录，不覆盖包内原件。不能再分发的资源只附元数据与 SHA，并在 README 明确须另提供的文件；这种包不标为完全自包含或已完成全离线重算。

确定性字段要求相同环境下精确一致：ID、方向、样本／候选集合、计数、NA 原因和参数；数值重算对同锁定环境使用 P/q 绝对误差≤1e-10、效应/ES/NES绝对误差≤1e-8并记录差异表，任何放宽须解释实际差异。不要求带创建时间的 ZIP 字节一致；图先校验 plot-data，再按相同渲染环境核对像素／矢量内容。
