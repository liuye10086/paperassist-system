## 2. 已实施内容

### 2.1 输入合同与来源

- `TabularSampleMetadataMapping` 固定 canonical 字段：`sample_id`、`condition`、`biological_unit_id`，并支持 `pair_id`、`batch`、`donor`、`sample_role` 的原始列映射。
- Bulk 导入允许显式 `input_origin`，可区分 `bulk_rna`、`single_cell_expression`、`tpm`、`fpkm`、`log`、`vst`、`rlog`、`z_score` 和 `unknown`；Bulk counts 不能声明为单细胞、TPM/FPKM 或其他非 raw-count 来源。
- `quality_reports` 以独立原件角色 `upstream_quality_report` 登记，来源和报告类型写入冻结导入配置及 manifest；质量报告不参与矩阵重算测序质量指标。
- 生信原件上传入口保留并扩展 `.html`、`.pdf` 质量报告格式，仍受 B01 的 128 MiB 上传边界约束。
- 可选 B02 字段对旧 tabular 请求保持兼容：没有新字段的旧请求不会被序列化为额外空字段。

### 2.2 样本映射与诊断

- 导入器写入 `sample_mapping.json`，版本为 `bulk_sample_mapping_v1`，记录 canonical 字段映射、原始文件、工作表、表头行、样本顺序和来源行号。
- Bulk 必须能定位 `sample_id`、`condition`、`biological_unit_id`；空值、重复样本、样本集合缺失/多出均阻断导入。
- 矩阵列、重复 feature ID、缺失 counts、非法数值、非有限值、负值和非整数 counts 的错误包含文件、行、列、样本 ID 或 feature ID 坐标；不做静默聚合。
- manifest 的 `checks` 保留 `sample_mapping` 与 `quality_reports` 审计记录，原始文件和原始标识保持不变。

### 2.3 研究设计接线

- Bulk 分析能力接口返回固定输入的 `sample_ids` 和样本映射摘要，用于前端预览。
- 保存 Bulk 分析配方且选择 `design_version_id` 时，后端对研究设计样本集合与输入样本集合做精确对账；缺失或多出样本以具体列表返回 `bio_design_sample_mismatch`，不会把不匹配拖到后续模型阶段。
- 前端研究设计模块读取所选版本的样本列表，显示设计样本数、输入样本数以及缺失/多出样本；实验设计 UUID 原值继续写入配方请求。

### 2.4 前端模板和说明

- `TabularImportFields` 提供 counts 矩阵 CSV 模板、sample metadata TSV 模板和明确的“仅用于演示格式，不代表真实测序或质量结果”提示。
- 增加 Bulk canonical 列映射输入、质量报告原件选择、输入来源/尺度声明和 512 样本列限制。
- B01 容量提示统一为 Bulk 文件 128 MiB、展开 256 MiB、512 个样本列、500 万单元格；不再显示旧的 10 MiB/255/100 万 Bulk 门槛。
- 导入核对页显示样本映射记录与上游质量报告来源，继续保留研究设计入口。
