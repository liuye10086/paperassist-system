## 业务合同

### 研究需求

新增 `research_request` 对象：

```json
{
  "question": "描述两组样本的测量值分布",
  "output_language": "zh-CN",
  "population": "合成研究样本",
  "study_design": "横断面观察",
  "observation_unit": "每行一名受试者",
  "observation_structure": "independent",
  "relationship_description": "",
  "output_requirements": "总体及分组描述统计"
}
```

语言为 `zh-CN` / `en`。观察结构为 `independent` / `paired` / `repeated` / `unknown`。
问题保留用户原始文字（最长4000字符，拒绝全空白），不以模型或关键词猜测方法。其他说明最长2000字符；缺少人群、设计、观察单位或结构为unknown时必须补充；paired/repeated还要求关系说明。输出要求是说明字段，不是任意统计方法或数据筛选执行指令。实际方法始终明确显示为描述统计。

新入口始终提交研究对象。兼容已有不带研究对象的v1 API请求，但v1任务不得事后伪装成已审核研究设计的v2任务。v2状态、决定、计划和结果的研究对象必须与冻结及修订记录一致。

### 等待、修订与确认

- 缺资料：真实 `waiting_input` / `analysis_plan_input`，检查点 `await_input`，保存缺字段清单并释放Worker。
- 补资料：复用决定接口的 `revise`（完整研究对象替换，可同时修改selection），写独立决定和新检查点，返回队列重新检查。补资料不等于批准。
- 资料齐全：`waiting_confirmation` / `analysis_plan_confirmation`，明确确认后发布。
- approve不允许修改研究对象或selection；revise至少提供研究对象或selection之一。旧v1决定严格兼容。
- `task_revision`、`wait_id`、`checkpoint_id`、`plan_revision`和冻结输入均需核验；重复同键重放首次回执，旧决定不得影响新计划。
- 换数据版本或工作表创建新计划；同一冻结来源下允许修改问题、语言、人群/设计/观察结构说明、输出要求和既有字段、分组、单位，重新检查并确认。
- paired/repeated只保存关系声明，并明确结果按行描述、未执行配对/重复测量推断或相关性调整。

### 新统计结果与历史兼容

v2结果继续原有总体/分组统计字段，增加 `schema_version: 2` 和 `analysis_context`，保存确认计划快照、研究需求、固定方法/参数、有效/排除口径、单位、舍入规则和不适用指标原因；引擎环境沿用真实运行记录。
P值、效应量和置信区间本批均不计算，使用null及明确原因。不能以默认值补造历史信息。
旧结果不强制重写、不改变ID或哈希；v2当前/历史读路径、图表/解释/Word本地兼容路径验证新的计划上下文，保持来源绑定。新原文不得默认进入云端材料。
