## 范围与行为

- 新增 `frontend/src/features/bio-cloud/`：能力检查、上传会话与运行记录、单样本单文库 L001 R1/R2 表单、单次明确提交动作授权、正数 USD 预算、状态/取消/查询取回、授权产物下载。
- `BioImports.tsx` 新增按需打开云工作区入口，保留原矩阵入口和原布局；完成产物仅选择 matrix/features/barcodes，切换 v4/mtx 后仍要求用户命名并发起现有导入审核。不调用云 `/import` POST，不自动发布数据集。已有导入草稿被替换前明确确认；已有草稿离开保护仍有效。
- 默认无账号、未启用、没有 account_verified profile 或分片大小不符时阻塞上传/提交，显示“未开通/未核验”“真实云验证未执行”。只列服务端已核验 profile，不猜流程、参考或建库支持。
- 上传按固定 16 MiB 分块，逐片 SHA256 base64；已有分片先全部与本地重新选择的文件逐片核对，通过后才发送缺失片，防止后续已有片不匹配时提前混入其他文件的数据。每次仅读取一个分片，不读取整个 FASTQ。失败后重新选择原文件，从服务端分片清单恢复。
- 签名 URL 仅在本地瞬时使用，不记录日志、不写 sessionStorage；S3 PUT 使用签名响应头及 `credentials:'omit'`，不经平台认证客户端。平台 JSON 读写仍复用现有 apiFetch / CSRF 请求链。
- 创建上传/运行先按账号、项目保存持久 Idempotency-Key；存储身份失败时不发送 POST。网络/5xx/无效成功回执保持未知，只允许原 key GET 查回，404 不清除身份；确定 4xx 才允许修正草稿后再提交。
- 上传会话 ID 与待查请求身份按账号/项目隔离存入 sessionStorage。刷新后读取服务器上传列表并重新选择本地文件续传；切换会话、停用或卸载取消本地请求。后台云 run 不因关闭页面而取消。
- 使用 setTimeout 与 AbortController 顺序轮询活跃 run；未激活不轮询。取消只代表取消意图，预算不承诺供应商账单实时硬封顶，真实失败不自动创建新的付费运行。
- 按后端补充合同，对 submission_unknown 提供云控制台核对提示及 provider run ID 的 `/runs/{id}/reconcile` 表单；此操作只核对原提交，不新建 run。
- `taskTypes.ts` 新增 cloud input/source/artifact 校验以及 cancelled 状态/事件，确保通用任务列表与详情可读取云任务。`BioTaskLinks.tsx` 复用现有导航返回生信工作区；用户再打开 FASTQ 云工作区查看完整运行。

## 限制与未执行

- 所有网络均由测试 mock；签名 URL 使用 `.invalid` 测试域名，没有真实上传、AWS API、真实付费运行、账号/地域/CORS/配额或真实 FASTQ 验证。没有安装云应用、启停服务、变更业务数据、提交或推送。
- 未执行浏览器视觉验收、真实下载、真实云到矩阵导入到下游完整端到端验收；测试只证明代码与本批合同的工程行为。
- UI 首期仅单文库、一对 L001 R1/R2，不支持完整多 lane/多 chunk 编排。后台合同预留不等于界面已支持。
- 真实云成功不等于矩阵通过审核，也不等于下游本地资源满足；本批没有改变既有下游计算资源限制。
- 通用任务详情返回现有生信工作区，不新增独立云任务路由；浏览器刷新不会保存完整填写中的分析表单，只保存上传会话及未知提交身份。页面停用时仍保留内存中的表单并沿用草稿保护。
