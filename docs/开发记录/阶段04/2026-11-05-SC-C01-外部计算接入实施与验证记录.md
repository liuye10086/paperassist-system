## 当前交付

- 云接口位于 `backend/app/api/bio_cloud.py`；统一传输接口位于 `domain/bio_cloud/provider.py`，AWS SDK 位于 `adapters/bio_cloud/aws.py`。新增受限配置及可选固定 SDK 依赖，API 密钥不进入前端或业务快照。
- S3 16 MiB 分片签名上传、SHA256 分片身份、服务端分片列表续传、同一会话完成恢复。原始 FASTQ 不经本机整包上传或分析。multipart 组合校验与文件 SHA256 分别记录。
- 上传和运行记录进入 PostgreSQL；迁移 `0071_bio_cloud_runs` 承接 `0070_delivery_snapshots`。云运行复用现有 tasks、outbox、dispatcher、Worker 租约及 defer。没有创建第二套任务调度服务。
- 后台记录固定 requestId 与输入；StartRun 关闭 SDK 自动重试。未知回执不自动创建另一个付费运行；有云 ID 后只查询同一运行。支持取消、查询恢复及异常查回，Worker 中断及取消/完成竞争保留真实远端状态。
- 运行结束后按约定目录获取 matrix/features/barcodes/QC/log，冻结 key/size/ETag，流式下载、核对长度及 SHA256，登记受管原件和来源说明。缺文件、混合版本或超出现有容量时阻塞回接，保留远端完成事实与已获取文件。
- 结果可选入现有 MTX 导入表单，复用原候选审核和下游入口；已有矩阵上传保留。云运行完成不自动发布数据集，不把传输成功说成生物学验证通过。
- 页面具备上传、排队、分析、结果获取、完成、失败和取消状态，正常流程不显示内部 revision，也不要求用户创建版本。

## 按用户意见简化

用户要求减少防御性建设、重复确认和版本操作后，移除了外部处理与预算的两个独立勾选。样本、流程、配对文件和预算填好后，页面给出处理与计费说明，一次点击“提交云分析”即可提交；没有正常路径的第二次弹窗。接口沿用明确提交动作产生的授权字段。

后续不按每个计算节点建设独立版本/审批页；每次分析共用一份输入、参数和任务记录。仅保留防止重复计算收费、断点恢复、必需输入校验及实际草稿覆盖提示。未继续增加额外云管理、账单系统或清理系统。
