## 1. 当前基线与阶段边界

现有代码已支持 SCI/毕业论文项目创建、Excel 文件历史、固定分析配置、描述统计、云端箱线图、AI 解释和 Word 报告。上述九张业务表、事务和两类云端请求恢复已接入 PostgreSQL；资产继续保存在原磁盘路径，API与前端合约保持不变。SQLite schema 6仅作为离线导入来源，不再用于应用运行或测试。

用户要求统一 PostgreSQL。两库在本机 `localhost:5432` 的 PostgreSQL 18.1，分别由 `paperassist_app` / `paperassist_test` 拥有，使用项目专用连接配置；测试每例建立独立schema。迁移角色 `paperassist_app` / `paperassist_test` 保留各自库的显式迁移权限；运行角色分别为 `paperassist_runtime` / `paperassist_test_runtime`，均非superuser、无CREATEDB/CREATEROLE、无数据库CREATE/TEMP且不能交叉CONNECT，开发最小权限check通过。

本轮数据库底座统一已实现，并从一致时点备份只读导入开发库；原SQLite已归档到备份目录，原文件资产路径保持不变，不实现双写。九表全行及哈希、重复导入、真实应用重连后的读取与下载已验证。全套回归的最终结果见[PostgreSQL统一与迁移记录](../开发记录/阶段01/PostgreSQL统一与迁移记录.md)，历史SQLite验收不替代本轮证据。
