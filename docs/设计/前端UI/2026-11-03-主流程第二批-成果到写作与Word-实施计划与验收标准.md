## 3. 目标使用流程

1. **查看已有成果**：保留当前分类，显示名称、类型、固定版本和真实状态。可下载不等于已经核对、可用于写作。
2. **带着成果进入写作材料**：选择 SCI/毕业论文交付，明确添加固定来源。未整理的原始分析结果先进入既有研究发现核对；图只能补充，不能单独冒充结果与方法。
3. **预览与核对**：复用固定材料预览，用户明确提交结果与方法候选，再核对并发布。已有候选或正式稿可沿原记录继续，不要求重做。
4. **继续完整写作**：已发布的 Results/Methods 事实稿明确标注范围；需要完整论文时进入既有完整写作页。已有完整稿直接打开所选版本，不自动扩写。
5. **找到 Word**：按所选稿件版本展示已有 DOCX；需要新导出时保留原配置和手动提交。研究报告 Word、事实稿 Word、完整稿 Word 不混称为同一种成品。

研究型项目沿 `ResearchWritingHandoff`→候选→`ResearchPublished`；旧 SCI/毕业论文项目继续沿 `ProjectManuscripts` 与现有 `AnalysisWritingTransfer`，不强行迁移。

## 4. A：成果出口与固定来源承接

**修改重点**

- 保留全局“继续写作”和“已有稿件”入口；在当前固定研究发现、研究图、研究报告处提供针对该对象的“用于写作”操作，避免泛化成每类附件都可直接写论文。
- 发现/研究报告直接作为待添加材料；研究图作为补充材料。普通分析运行、处理数据或外部证据沿现有研究发现核对入口继续，保留 `Source` 的类型、固定 ID 和 locator；不能解析到受支持固定来源时提供原详情/核对入口，不猜测来源。

## 5. B：写作材料、候选与正式稿件衔接

**修改重点**

- 写作材料页显示当前交付、已有选择和入口带来的待添加材料；用户点击添加后合并去重。返回旧链接不重复添加，既有草稿、人工备注、语言和章节选择保持。
- 继续使用按交付保存的 sessionStorage 草稿；承诺同一浏览器会话内刷新/往返恢复，不扩展为跨设备云草稿。登出或切换账号仍按现有策略清除旧会话内容。
- 编辑已有稿件时显式选择目标稿件，并固定选择时的当前版本：`manuscript_id`、`base_version_id`、`expected_revision`。刷新出现新版时提示比较，用户决定是否采用；旧材料和预览不能静默重绑最新版。沿用服务端“期望修订号必须等于当前修订号”的规则，不新增以任意历史版本直接覆盖当前稿的能力。
- 当前材料缺少必要发现/报告、学校章节配置未完成时，给出针对该动作的补齐入口，不阻断无关历史稿件和下载。

## 6. C：固定稿件版本到 Word

**修改重点**

- 结果页“查看已有稿件与 Word”先展示可读的稿件名称/类型/版本；多份稿件明确选择，不猜“最新的就是本次所需”。有固定稿件上下文的操作直接到该版本导出页。
