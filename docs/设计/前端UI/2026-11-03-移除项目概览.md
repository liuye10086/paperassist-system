# 移除项目概览，沿步骤推进

目标：移除侧边栏“项目概览”和任务卡片中转页，保留“项目资料 → 上传文件 → 选择需求 → 执行分析 → 查看结果”的主流程。

实现方式：复用现有 React / TypeScript 页面及路由。新建成功仍直接上传；首次打开既有项目显示第 1 步项目资料，原概览根链接和 tasks 子视图兼容为项目资料。保留已打开页面的恢复、历史链接和草稿，不改后端接口。

- [x] 同步既有导航测试，核对草稿保留、旧链接、创建后上传、记录入口和浏览器历史。

## 顺序推进补充

用户进一步确认：按所选服务顺序推进，允许返回已完成步骤；只写论文时不强制运行分析。

- 读取已保存的需求、文件数及既有任务／成果作为导航依据。空项目不能从顶部、侧边栏或跨模块入口跳到后续阶段；保存需求后才能进入处理阶段，再查看结果和继续写作。
- 只选写作时，第 4 步显示“稿件写作”，侧边栏改为“成果与下载”。需求问卷继续仅显示所选服务的小步骤。
- 上传页显示“1. 选择材料类型、2. 选择文件并上传、3. 核对已上传文件”；分析流程、稿件资料编排增加顺序编号。
- 保存需求后立即更新导航依据，包含提交结果不确定后重新核实成功的路径；不会自动运行分析或生成稿件。
- 保留旧深链接及页面历史。已到达页面可返回，不把访问页面标记成任务完成；这是界面顺序引导，执行模块原有的材料、版本、费用和授权检查继续生效。
- 在“项目记录与用量”中保留刷新流程状态入口。
