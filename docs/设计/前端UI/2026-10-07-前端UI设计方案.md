# 前端 UI 设计方案

日期：2026-10-07。状态：三步UI改版、后续微调、两项审查修复及6项体验修复与切页动效优化均已通过用户验收，验收服务已停止。用户已授权纳入阶段01收尾统一提交推送，实际结果以Git记录为准。阶段01适用范围收尾完成；阶段02具备启动条件，尚未开始开发。

## 已确认的方向

采用“简洁科研工作台”：白灰底、深紫主色、少量卡片。用户明确要求前端不展示编号、哈希值等技术信息。

目标是让用户通过项目名称、文件名和任务状态找到正在进行的研究，把目前纵向堆叠的功能整理为明确的工作区。现有登录、项目、Excel、统计、图表、解释和Word能力作为设计内容。

可点击稿位于 [preview/index.html](preview/index.html)，只使用合成示例数据，演示页面切换、项目选择和分析布局；不连接实际账户、数据库或模型服务。正式前端已应用三步改版，最新结果见[第三步交付记录](../../开发记录/项目维护/前端UI第三步交付记录.md)，此前范围见[第一步](../../开发记录/项目维护/前端UI第一步交付记录.md)与[第二步交付记录](../../开发记录/项目维护/前端UI第二步交付记录.md)。

## 参考依据与取舍

2026-10-07实际查看了 [SciSpace](https://scispace.com/) 首页及侧栏、[沁言学术](https://www.qinyanai.com/) 官网，以及从官网进入的[网页版](https://app.qinyanai.com/)公开界面。

| 参考 | 可借鉴的内容 | PaperAssist 的用法 |
| --- | --- | --- |
| SciSpace | 大留白、清晰主入口、侧栏导航、入口下的快捷动作 | 保持主操作突出，把“继续项目 / 新建项目”放在首页，而不是堆满所有表单 |
| 沁言学术 | 分组侧栏、白灰工作台、深紫操作按钮、功能入口分区 | 用项目上下文组织“概览 / 文件 / 分析 / 成果”，降低长页面寻找成本 |

曾考虑纯对话首页、工具门户和项目工作台三种方式。纯对话首页需要尚未实现的自然语言任务能力；工具门户适合更多独立功能。当前采用项目工作台，最贴合已有的数据分析闭环。页面布局和配色是参考后的设计建议，不是对参考网站私有页面的推断。

## 页面与信息组织

### 工作台

- 左侧保留品牌、工作台入口及当前项目内的导航，底部放账号与设置。
- 顶部是当前位置、界面语言和账号入口，不在页面顶部堆叠大标题与诊断信息。
- 主区域突出“继续你的研究”和“新建项目”，下方展示项目列表。
- 项目列表显示名称、类型、更新时间和可理解的状态，保留搜索和类型筛选的设计位置。
- 新建项目采用聚焦表单，仍填写名称、研究主题并明确选择SCI/毕业论文类型。

### 项目概览与文件

- 进入项目后，标题使用项目名称，研究主题作为次级信息。
- 项目内导航为“项目概览 / 项目文件 / 数据分析 / 图表与报告”。
- 概览展示文件、近期分析和成果，入口指向相关内容，减少重复按钮。
- 文件页以文件名、上传时间、大小、解析状态为主；上传、预览和下载位置固定。
- 预览保留工作表切换和可滚动数据表，不把整个页面变成横向滚动区域。

### 数据分析

- 用“数据 / 字段配置 / 描述统计 / 图表 / 分析解释 / Word报告”表示流程，不展示步骤编号。
- 当前步骤有明确的标题和主操作；历史成果仍可查看和下载。
- 配置区与数据预览在桌面并排，较窄窗口上下排列。
- 统计结果保留样本量、缺失数、分组、单位、统计量和计算口径；结果展示以表格为主。
- 图表占据主要内容区域，图注、解释与下载动作有清楚的层级。
- 历史结果提示使用“历史结果”“设置已变更，请重新分析”等自然语言，避免内部版本数字。

### 登录与账号

- 登录页采用安静的品牌区与表单区，保留邮箱、密码和恢复入口。
- 新设计继续使用已有认证方式，不新增公开注册、微信扫码等能力。
- 登录后的语言、改密和退出进入统一账号区域，避免横排按钮挤占正文。

## 不展示技术元数据

| 当前可能出现的内容 | 新界面处理 |
| --- | --- |
| 项目、文件、任务、统计、图表、解释和报告的内部 ID | 不渲染；条目由名称、类型和时间区分 |
| SHA256、输入/图片/报告哈希 | 不渲染，也不放入可展开详情 |
| 配置 revision、当前版本/历史版本数字 | 改为“当前结果 / 历史结果 / 需要重新生成”等状态文案 |
| 请求/容器编号、工具标识、Python/openpyxl/python-docx版本 | 不展示于用户工作区 |
| 文件选择项末尾的截短 ID | 去掉，以文件名和上传时间区分 |
| 技术化来源记录 | 改为文件名、工作表、字段、生成时间、科研方法等可读信息 |

内部ID和哈希仍用于接口、关联、下载和一致性判断；这次改变显示方式，不删除后端记录或前端内部状态。研究数据中用户原本填写的样本编号、Excel行列位置属于内容或定位信息，保持原文，不当成系统元数据清理。

落地时需覆盖 `ProjectSummary`、`AnalysisSetup`、`StatisticsResults`、`BoxplotFigure`、`AnalysisExplanation`、`WordReport` 及中英文词典。不要只隐藏主界面后仍在来源详情、提示或文件选择框中露出技术字段。

## 视觉规范

- 页面底色采用浅灰，内容表面为白色；深紫用于主要按钮、选中导航与必要强调。
- 侧栏约230px，主内容采用弹性布局；卡片按内容需要使用，不用多个无意义统计卡填满首页。
- 正文14–16px，标题24–32px；以字号、间距和字重体现层次。
- 卡片圆角约12px，输入和按钮约8px；阴影轻，边线细，避免满屏渐变。
- 图标使用一致的细线风格，按钮优先保留可读文字。
- 状态用文本和颜色共同表达，焦点可见，弹窗可用Escape关闭。
- 桌面为主，较窄窗口压缩侧栏并将双栏内容堆叠；数据表允许自身横向滚动。

## 落地顺序

用户已确认具体页面布局，按以下顺序改现有前端：

1. 应用壳、设计变量、登录与项目列表；延续现有双语和账号操作。
2. 项目概览、文件与分析内容区；保留项目选择、草稿、请求取消和忙碌状态。
3. 统一清理技术字段的可见输出，调整相关文案与针对性的界面测试。
4. 运行前端测试、构建和lint，再通过现有脚本启动，交用户手工验收。

第4项验证随每次交付执行，各步及后续体验修复现均已验收；提交推送按用户本次阶段01收尾授权统一执行。本轮界面改版未重跑后端全量回归，未新增与UI无关的机制。
