原请求的最小本地记录及状态约束：

```ts
type PendingManuscriptRequest = {
  key: string; url: string; body: string;
  phase: 'sending' | 'unknown';
}
// scope 包含 manuscriptId、version.id 和业务操作域；用户/项目由 useResearchDraft 隔离。
// body 保存首次提交的确切 JSON 字符串，重试不从当前表单重新拼接。
```

对 `useWritingOperation` 增加可选持久化 scope，旧调用保持兼容；只给本批完整写作入口接入。同步请求锁继续放在 ref 中，避免同一事件循环双击；持久化不是按钮锁的替代。

| 情况 | 明确行为 |
| --- | --- |
| 正在发送 / 排队 / 运行 | 禁止同一请求再次提交，允许查看原任务；刷新页面只读取 |
| 连接中断、超时、5xx、响应无法核实 | 保留原键、URL、固定请求体，显示“提交结果待核对”；冻结该未确认操作的输入，其他草稿保留 |
| 原请求可直接查证 | 复用研究请求查询、候选回读、写作预览/请求历史及任务详情；能证明属于同一请求才解除未知状态 |
| Word 列表无法精确识别原请求 | 展示已有导出但保留未知标记；提供明确的“用原请求重试”，沿既有 POST 和原键/原输入返回原记录，不创建新键猜测结果 |
| 正式任务失败且允许 retry | 先回读任务工作区，继续使用原任务、固定输入、`expected_task_revision`、`allowed_actions`；不重新创建分析或稿件任务 |
| 409 / 固定输入冲突 | 保留草稿及旧成果，显示需刷新比较；不得换一个新键绕过冲突 |
| 服务端明确拒绝或请求已确认成功 | 解除该请求的未知状态；成功优先展示已有对象；用户修改配置或明确再做一次才形成新意图 |
| 登录身份变化 | 禁止继续发送并清除本用户范围内的待处理操作，沿原认证恢复规则处理；不跨账号恢复 |

完整写作的未知请求恢复仍受原授权有效性、费用确认和 `logical_task_id` 约束。恢复审核/执行勾选不属于本批能力；不把“同键重试”包装成纯查询，也不把读不到结果直接当成首次提交未发生。遇到无法安全查证且原接口不能恢复的真实模型状态，保持待核对并给原任务入口，不自动重发模型调用。
