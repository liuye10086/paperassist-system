# 项目功能清单与清理候选

当前项目的主体能力已覆盖“建项目、交材料、定需求、分析、核对成果、可选写作、Word 交付”。建议先精简重复和兼容入口，再决定是否停用具体业务能力。**本清单只供选择，没有删除、停用或重生成任何功能、数据和成果，也不表示全项目流程已验证完成。**

清单日期：2026-11-02。固定编号 `F01`—`F50` 用于后续讨论；同一功能内部的不同算法或数据类型已在描述中列明，不因合并成一行而认为可以整体删除。

## 如何作决定

- **建议保留**：支撑客户主流程，或保护原件、固定版本、权限、任务及可复现性。
- **可折叠**：保留业务与历史能力，只简化默认界面或改为按需显示。
- **可停用待确认**：可以考虑停止新建请求；必须先明确替代入口、历史读取和正在执行的任务如何保留。这不是删除授权。
- **已退役**：当前源码已取消的新生成能力；相关历史读取与共用能力另列，不能连带删除。

表内“**源码在**”表示本轮只读检查找到了当前入口、合同或后端路由；“**既有验收**”表示引用已有范围内的记录，没有在本轮重新运行。“**待补**”包括真实质量、具体环境或端到端验证缺口。各行引用的 `S1`—`S13` 在文末给出；源码存在不等于当前服务已加载，更不等于适用于任意研究材料。

## 与客户完整流程有关的已知边界

1. **需求勾选与执行配置不是自动同一件事。** 当前九类勾选保存需求范围；客户还要进入对应数据/分析模块核对材料和设置。不能把“勾选 GO / KEGG / GSEA”写成已经运行，也不能保证缺资源时可直接完成。
2. **默认研究项目与传统写作入口并不完全等价。** 当前 `research` 的独立 `reviews/journals` 有后端门禁和前端提示，侧栏隐藏独立意见入口；受控写作按已发布稿件及有效交付上下文进入。清理旧类型前须先解决替代路径问题。
3. **旧写作表单可能与客户“真实写作”的预期不一致。** `ManuscriptWriting` 同时保留旧无真实调用合同与 `WritingLive` 入口；这是值得优先检查的呈现与入口问题，不能直接推断旧任务可以删除。
4. **A19 仍是独立缺口。** 文章写作、Word-only 和 B06 整批验收都没有把候选→新稿 root→DOCX 的实际完整链自动计为通过；保留原请求和产物，避免以清理或复测为名重复生成。
5. **报告性能与输入适用性不是删除 PDF 后自然解决。** 既有长包核验性能、真实学校/期刊、专业双语、字体、独立供体/队列及生物学验证仍按原记录保留。
6. **分析成果与稿件 Word 仍按各自固定来源保存；入口已补齐。** `ArtifactLibrary` 展示分析图、分析/集合报告及独立排版记录；`ManuscriptExports` 列对应稿件的 DOCX。本次 Edge 复现仅有稿件 Word 时成果页空提示过宽的问题，已新增“查看已有稿件与 Word 下载”入口，并将空提示限定为分析成果。下载原件已实际核对，没有新建输出 [S13]。
