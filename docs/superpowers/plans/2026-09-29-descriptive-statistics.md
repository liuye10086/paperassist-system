# 最小分析闭环第二步：真实描述统计

用户已要求开始下一步。本步在已验收的字段配置上执行描述统计，保存可追溯结果；统计图、模型解释及 Word 报告继续按后续步骤开发。开发完成后等待用户验收，不自动提交推送。

## 设计

- 复用 openpyxl 整表安全扫描、原文件 SHA256 检查和第一步的完整记录规则。仅计算已保存的配置，执行入口接收 `expected_revision`，不接受客户端提供的数值或任意代码。
- 增加 `backend/app/descriptive.py`：固定统计工具 `descriptive_statistics_v1`，使用 Python 标准库 statistics 计算均值和样本标准差（分母 n−1）。四分位数按排序后位置 `(n−1)p` 线性插值，p 为 0.25、0.5、0.75；用 Fraction 保留插值及 IQR 中间精度，最后转换为 JSON 浮点数，避免直接相加溢出或先舍入再相减失真。
- 输出总体及可选分组的 n、mean、std、min、q1、median、q3、max、iqr。总体也遵守所选数值/分组完整记录规则。分组按原数据首次出现的有效组排序；n=1 时 std=null 并提示，其余位置统计量等于该值。数值溢出时受影响指标为 null 并提示，不输出 NaN/Infinity，不填 0。
- 数值列中原生整数超出 `±(2**53−1)` 时执行拒绝并提示，避免被转成相同浮点数；有限浮点输入及最终输出保持双精度边界。第一步仍允许预览/保存配置，精度限制在执行时说明。
- 本次使用标准库即可覆盖固定描述统计。相比 pandas/SciPy，不新增安装依赖；后续统计检验再按实际方法引入相应库。仍沿用 FastAPI 同步线程池和当前解析上限，独立进程/硬超时为已知后续限制。
- SQLite schema 2→3 只增加 `analysis_runs` 表；每个文件、配置修订和工具版本唯一。保存不可变结果快照，含 UUID、源文件摘要、字段名称/位置、配置、检查摘要、计算方法、Python/openpyxl 版本、开始/完成时间。重复执行同一配置返回已有结果；并发请求只保存一份。计算期间配置变化则返回 409，不将旧配置结果当作新结果。
- `POST .../analysis-runs` 执行或返回已有结果；`GET .../analysis-result` 读取最新保存结果及当前配置版本、是否匹配。旧结果保留，页面只展示最新一份；完整历史管理不在本步范围。
- 新建 `frontend/src/StatisticsResults.tsx`，复用页面样式展示“执行描述统计”、计算状态、总体/分组表、方法和来源。字段尚未保存或与保存配置不一致时不能执行；输入变更时明确区分旧结果。请求超时给出重新读取结果入口，切文件/工作表后忽略旧响应。
