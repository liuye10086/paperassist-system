## 3. 更新进度的规则

- 先核对代码、自动验证或用户明确反馈，再将对应任务标为 `- [x]`；只完成一部分时保持 `- [ ]` 并说明缺口。
- 自动测试、只读数据库查询、用户人工验收分开记。管理员密码已设置及项目归属正确，不等于用户已手动查看全部历史成果。
- 交付证据写入所属阶段的开发记录，再同步阶段清单、路线和相关决策；目录移动时修复所有文档内相对链接。
- 历史测试次数和迁移快照保留原日期，不能拿旧结果证明新功能；本轮只改文档时明确未重跑功能回归。
- 暂缓或条件尚未成立的需求保持未完成并写明原因。阶段结束前核对适用条目和剩余边界，不把局部交付当作整体结项。
- 完成工作后报告修改、验证及限制。提交或推送必须先获得用户明确确认。

历史Git授权与提交状态按各独立记录和Git基线理解；阶段09唯一后续提交/推送授权注记保留在[仓库README](../README.md#历史授权注记)。
