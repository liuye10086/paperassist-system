## 1. 目录职责

```text
docs/
├─ README.md                         文档入口与归档规则
├─ 科研论文辅助Agent项目需求文档_V0.13.md
├─ 技术实现方案_V0.1.md
├─ 项目参考文档.md
├─ 开发阶段/                         路线及阶段00—10任务清单
└─ 开发记录/                         根据阶段开发产生的文档
   ├─ 项目管理/                      跨阶段决策、需求覆盖、参考复用
   ├─ 阶段01/                        本阶段实施计划、迁移、验收记录
   └─ 历史小闭环/                    早期Excel→Word计划及验收记录
```

后续阶段开始时按需建立 `开发记录/阶段02/` 等同级目录。当前的 `开发阶段/` 只保留路线与阶段任务清单；原 `docs/superpowers/plans/` 中的计划已经按所属阶段或历史小闭环归档，不再另起一套计划目录。

| 内容 | 放在哪里 | 命名和维护方式 |
| --- | --- | --- |
| 产品范围、总技术方案、参考候选 | `docs/` 根目录现有三份文档 | 保留文档版本及被后续决定替代的说明 |
| 路线、功能点、完成状态、剩余步骤 | `docs/开发阶段/` | 保持阶段编号与条目ID；只写简要状态和证据链接 |
| 需求覆盖、跨阶段决定、源码接收与复用登记 | `docs/开发记录/项目管理/` | 在现有台账持续更新，避免多份互相矛盾的决定 |
| 单项实施计划 | `docs/开发记录/阶段NN/` | 新文档用 `YYYY-MM-DD-模块名-实施计划.md`；已有文件保留名称 |
| 迁移、验收、交付及复用适配记录 | 对应 `docs/开发记录/阶段NN/` | 用具体模块命名，写明日期、范围、结果与限制 |
| 早期闭环计划与验收 | `docs/开发记录/历史小闭环/` | 保留原日期和当时结论；后续变更用说明与链接补充 |

后端代码、前端代码及测试仍分别放在现有 `backend/`、`frontend/` 内。参考源码继续放在已忽略的 `reference-projects/`；实际业务资产、数据库备份及本地核验文件分别留在已忽略的 `backend/data/`、`backend/backups/`。文档只记录必要的路径和验证摘要，不复制密码、连接串、会话凭据或研究原件。

## 3. 更新进度的规则

- 先核对代码、自动验证或用户明确反馈，再将对应任务标为 `- [x]`；只完成一部分时保持 `- [ ]` 并说明缺口。
- 自动测试、只读数据库查询、用户人工验收分开记。管理员密码已设置及项目归属正确，不等于用户已手动查看全部历史成果。
- 交付证据写入所属阶段的开发记录，再同步阶段清单、路线和相关决策；目录移动时修复所有文档内相对链接。
- 历史测试次数和迁移快照保留原日期，不能拿旧结果证明新功能；本轮只改文档时明确未重跑功能回归。
- 暂缓或条件尚未成立的需求保持未完成并写明原因。阶段结束前核对适用条目和剩余边界，不把局部交付当作整体结项。
- 完成工作后报告修改、验证及限制。提交或推送必须先获得用户明确确认。

此前登录交付与文档整理已按用户授权提交推送；项目编辑的新改动仍未提交、未推送，具体提交及验证状态见项目编辑交付记录。
